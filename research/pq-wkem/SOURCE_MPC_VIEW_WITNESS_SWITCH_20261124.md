## 1. Serialized candidate with a single binding transcript

Let R_x(w) be the canonical polynomial-size Boolean verifier for the full three-ground ORIGINAL relation with all relevance and admission conditions. Pad canonical input representations to fixed polynomial lengths, including the complete ORIGINAL witness, and distinguish the trapdoor input by domain. Let S be the fixed native cancellation signature, with precommitted message/VK; use a uniform lambda-bit KEM seed K to mask S by an independent domain-separated XOF. Build chooses uniform lambda-bit s and h=H_trap(s). Define a Boolean circuit Q_x,h(w,t) = R_x(w) OR [H_trap(t)=h]. Build can execute Q on (w0,s), where w0 is a syntactic dummy, without an ORIGINAL witness. The trapdoor branch is only an internal device for the attempted compiler, not an admissible challenge branch.

Use the following explicit three-party Boolean MPC-in-head execution to avoid an ideal source evaluator. Each input bit is XOR shared among three parties, with the first two shares independently uniform and the third determined by the input. Public constants use a canonical sharing. XOR gates are local. For each AND gate with input shares a_i,b_i, choose independent random tape bits r_i, with indices modulo 3, and define

    c_i = a_i*b_i XOR a_i*b_(i+1) XOR a_(i+1)*b_i XOR r_i XOR r_(i+1).

Indeed XOR_i c_i = (XOR_i a_i)*(XOR_i b_i), since all nine pair products occur exactly once and each r occurs twice. Include in V_i the input shares, wire shares and random tape for party i, using exact circuit and wire indices. Given V_i,V_(i+1), party i's gate equations are checkable, as are the corresponding public input shares and committed output shares. The union of all three checked adjacent pairs of the SAME views gives a real accepting input for Q; one pair alone does not. This is a local consistency fact, not a claim of ZK or QPT proof of knowledge for a full protocol.

Build samples independent lambda-bit salts rho_i and commits A_i=H_view(context,i,rho_i,enc(V_i)). Publish the three A_i, the output shares, and (V_0,rho_0),(V_1,rho_1), with a checked adjacent-pair opening. Let K=H_key(context,rho_2) and B=S XOR XOF(context,K). Capsule C contains all these public bytes, h and the public statement/circuit/context. Its size and all honest setup operations are polynomial. The proposed Open is: use qualifying ORIGINAL w to complete the hidden view under A_2 with input (w,0), check all pair equations and acceptance, and recover K from the missing opening. Thus the intended cryptographic gate is a single fixed globally bound view triple, not release followed by an optional honest-code source check.

**Exact correctness failure (before any fixture).** For the two fixed revealed views, the hidden input share vector is uniquely determined by whichever complete input u is being represented:

    in_2(u) = u XOR in_0 XOR in_1.

The committed hidden view has in_2(w0,s). The requested ORIGINAL completion instead needs in_2(w,0). Unless (w,0)=(w0,s), the two input vectors differ. For s uniform, s=0 occurs with probability 2^-lambda; even then all w distinct from w0 fail. Canonical view encodings therefore differ, regardless of changes to the AND tapes, wire traces, or other fields. An opening of A_2 to the new view requires a collision of the actual commitment hash against the original view/salt. A witness-independent global commitment has fixed the *setup* input, not just the accepting output. It does not admit arbitrary ORIGINAL inputs. A successful switch is not a consequence of both inputs satisfying Q.

Even abandoning the requirement to switch the reconstructed input, knowing w does not expose the independent hidden salt rho_2. In the isolated classical ROM implementation, rho_2 was sampled independently of the input sharing, all MPC tapes, the original evidence and all other salts. Before guessing it, the hidden commitment output is a fresh uniform oracle value; so is H_key(context,rho_2). For the KEM-seed experiment, let B be an independent uniform masked payload (or omit B when testing recovery of K). Give the opener even the entire V_2 for free, but not rho_2, as well as all other public data. Provided no other setup data are derived from rho_2, a classical q-query opener finds rho_2 with probability at most q/2^lambda in the standard coupling with an oracle not programmed at the hidden seed. Otherwise its probability of guessing K is at most 2^-lambda. The bound only concerns this actual independent-salt implementation and the isolated KEM experiment; it does not assert native signature entropy or QROM security. Salting the views makes the missing opening harder, not accessible to an ORIGINAL witness.

Giving rho_2 in C to repair this immediately makes K public, including when R_x is FALSE. Deriving rho_2 from the complete hidden view instead eliminates independent salt entropy, but that view still binds (w0,s); a different original witness has a different share vector. Changing the hidden view commitment to exclude input shares would need a new proof that the remaining committed data force the same input shares across openings. Dropping that binding premise and still applying the three-pair extraction argument is invalid. No implementation of this known invalid repair.

## 2. Repair attempt: late-bound transcript and OR-branch switch

To avoid fixing one witness at Build, let Open generate ALL three views and commitments freshly from its ORIGINAL certificate. This gives correct source verification, and the MPC AND identity above remains valid. Build would like to keep the same K for every such late-bound transcript without learning the certificate.

A direct hash-only version is the following actual public descriptor: Build samples s, publishes h=H_trap(s), masks S using K=H_key(context,s), and includes Q plus any proof-checking data generated from (x,h,context) and independent coins. No setup views generated using s are released. Open builds a valid transcript T_w for the ORIGINAL branch and tries to derive K from T_w and the descriptor. The mathematical change is full global proof generation at Open, not obtaining an individual row's reusable secret seed. It restores verifier completeness, but not release correctness.

For this particular repair, an exact joint-distribution obstacle is available without any assumption about the hardness of R_x. Fix a true x and give Open an actual w (even as nonuniform advice independent of s). In the classical ROM, sample s,h,K independently and program H_trap(s)=h, H_key(context,s)=K. Sample the remaining descriptor using (x,h,context), independent coins and the oracle, and use an independent uniform B for the isolated KEM experiment. Couple to an unprogrammed experiment in which s remains uniform independent of the entire execution. Include both descriptor-generation and opener queries in q. The probability of querying an oracle coordinate containing the chosen seed in the relevant domains is at most q/2^lambda; prior to that event the distributions coincide. A generated accepting T_w changes neither the distribution of s nor K. Conditioned on no such query, K is uniform, so recovery probability is at most (q+1)/2^lambda. This holds for the genuine source witness, not merely an invalid trace. If the public descriptor is allowed other s-dependent correlated information the coupling need not hold; constructing exactly that information is the missing operation. This is a scoped classical completeness failure of the specified repair, not a general ROM or concrete-SHA impossibility, and not a full-public security theorem.

A proof for Q also cannot simply be substituted into an ORIGINAL-extraction theorem. Full-view extraction from three consistent pair openings yields an input satisfying Q, which can be (w0,s); it is not intrinsically a qualifying ORIGINAL certificate. A future independent proof using w is an authentication tool but not a key-agreement transcript with the earlier setup. Revealing the trapdoor or publishing a direct derivation of K from h makes a FALSE capsule openable. Requiring both branches instead of OR would make Build require a certificate and Open require the setup trapdoor, destroying the intended completeness.

## 3. Precise handoff

A genuine repair would require an actual serialized hash-only translation between committed accepting executions with DIFFERENT inputs, in which an original-witness-generated transcript yields the earlier hidden K while an arbitrary trapdoor/simulated/locally valid transcript cannot. It must not be modeled as a secret-key evaluator or a commitment with the desired witness-dependent equivocation as an assumption. Ordinary binding commitments cannot support the specific same-commitment switch in section 1; removing that binding is not a security argument. Independent simulation of MPC views or Fiat-Shamir transcripts does not supply the cross-execution key correlation. Do not repeat fixed salted views, dummy-branch OR proofs, or the late-bound independent-hash descriptor as WKEM candidates.
