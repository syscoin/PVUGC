# MINK-LAMPORT-FALSE-20261101: real hash-key release and compact FALSE signed-XOR setup proof

**Scope and result:** A finite, classically computable restricted **signed-XOR source** composition with actual SHA-256 Lamport one-time native-style signing key was tested locally. A compact, publicly verifiable FALSE-source setup branch requires only E refutation bits rather than publishing all zero-mode opening coins. This is not generic-NP witness encryption, an authenticated Bitcoin source proof, a native deployed SLH signature, a solved hard-TRUE extractor, or a QPT security assessment.

## Source and common capability

For signed-XOR graph edges (u,v,b), make A over F2 with each row (b,e_u+e_v). A valid ORIGINAL witness z satisfies A(1,z)=0. Independently sample Lamport signing secrets K[i,b] as 512 uniform 256-bit strings, with native-style checking key vk[i,b]=SHA256(K[i,b]). For a canonical path/context digest d, the one-time signature gives K[i,d_i], and the verifier hashes each supplied preimage. The key is 16,384 bytes, vk 16,384 bytes, and signature 8,192 bytes. SHA-256 preimage hardness is an **explicit unproved QPT assumption**. This signature format is not claimed to be deployed on Bitcoin.

For each of the 131,072 bits of K, choose independent uniform m0,m1 and m2=Kbit+m0+m1. Publish three vectors C_j=A^T s_j+m_j e0 for fresh uniform s_j in F2^E. A valid ORIGINAL witness z computes sum_j (1,z)^T C_j=Kbit. All valid witnesses recover the same complete precommitted Lamport K; no canonical witness or common intermediate trace is required. A typed length-prefixed manifest should bind A, the native vk, claim/UTXO, branch, anchors/window, path and SHA-256 capsule digest. The local Python checker implements a SHA-256 manifest binding its literal source rows, vk, provided context, and capsule bytes, and rejects modification; it does NOT check real SYS/BTC AuxPoW or tags.

## Compact FALSE setup branch

If the signed-XOR relation is FALSE, a public polynomial-time Gaussian elimination yields delta with A^T delta=e0. A valid ORIGINAL witness would imply 0=(1,z)^T A^T delta=(1,z)^T e0=1, so no witness exists. For every capsule vector require C_j in Image(A^T), tested by polynomial-time Gaussian elimination. Thus a public setup verifier can accept an alternative FALSE branch from just delta (E bits) plus the ordinary manifest: it does not need all zero-mode coins. On the actual two-edge fixture the former per-capsule 393,216-byte zero-mode-coin certificate becomes a 2-bit delta; the capsule itself still occupies 393,216 test-encoded bytes. No extra verifier runtime assumptions are introduced.

For any actual unknown Lamport key bit, choose arbitrary two m shares, derive the third, and for any C=A^T s0 set s_real=s0+m delta. Then A^T s_real+m e0=C. Therefore every accepted FALSE branch capsule is consistent with **every valid underlying KeyGen secret for the genuinely bound vk**. A malicious arbitrary vk outside KeyGen range is NOT certified by this branch; no valid ORIGINAL witness exists on that source, but genuine TRUE-source setup consistency still needs the unsolved QPT-sound/QPT-ZK proof. The FALSE branch cannot be used on a TRUE signed-XOR source.

## Complete restricted joint FALSE-view theorem

Fix an honestly generated Lamport key K, genuine vk, all public manifest fields, a polynomial number of independently generated FALSE signed-XOR capsules (with independently verified delta for each), and allowed independently simulatable auxiliary outputs. For one coordinate, real C=A^T s+m e0 with s uniform and fixed secret share m. The simulator without K or SourceOpen samples s0 uniform and publishes C=A^T s0. The substitution s0=s+m delta is a bijection. Thus the **joint** distribution of all capsules and actual FALSE-branch proof certificates is exactly identical conditional on *any* K, genuine correlated vk and any separately generated native signing transcript. A QPT adversary coherently processing the resulting classical public bytes inherits exact equality.

For classical adaptive disclosure of at most two of three lane shares per key bit per capsule, the simulator samples each opened share independently uniform, uniformly samples a preimage s0 from the affine fiber A^T s0=C, and returns actual coins s_real=s0+m delta, memoizing repeated requests. Pairwise lane-share distributions are uniform and independent of K, including across separately randomized related FALSE capsules. Opening a third lane reveals Kbit. This does NOT cover a related TRUE capsule for the same key, secret-correlated external advice, more than one authorized message signature per Lamport key, malicious correlated setup, or quantum-superposition source-opening queries.

## Arbitrary-QPT native-forgery reduction (scoped)

For fresh path signature forgery after at most one prior classical authorized one-time signature on a different 256-bit digest, embed a random SHA256 one-way challenge Y=SHA256(U) at one of the 512 random Lamport vk entries. All remaining secret entries are generated normally. FALSE capsules, their public setup certificates, and allowed two-of-three openings are simulated exactly without the unknown U. A forgery on a distinct digest contains a preimage at an entry not opened by the signing query. The uniformly selected embedding hits that position with probability at least 1/512, yielding a **straight-line QPT** one-way inverter. A different canonical path message with the same digest instead gives a collision. Hence fresh false-path forgery probability is at most 512*Adv_QPT_OW(SHA256)+Adv_QPT_collision(SHA256), plus separately justified context/authentication failures. No quantum rewinding or volunteered internal representation is needed.

For an authenticated N-of-N path, stripping an accepted honest signer's Lamport component gives the same single-key forgery experiment. The existing one-honest erasure/no-bypass graph remains an indispensable conditional prerequisite. This is a FALSE-source signature security result, NOT the required hard-TRUE arbitrary key-recovery-to-ORIGINAL-witness proof. TRUE signed-XOR sources are easy to solve. General Boolean AND/CSP/PoW source release remains unsolved.
