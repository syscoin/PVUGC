## Serialized candidate and actual evaluation equations

Let m be a fixed polynomial bound on the injectively encoded canonical original witness, including length/domain where needed. Compile the unchanged complete source verifier to a deterministic bounded Boolean circuit with a designated acceptance gate, fan-in <=2. Claim context is fixed and included in all domain separators; no independent verifier chosen by the capsule. The compilation is symbolic, not an implementation of live consensus rules. Use a lambda-bit hash-based GGM expander G and independently domain-separated lambda-bit gate hashes J_g and final mask family P. Consider independent random-function domains only for the analytic test below, not a concrete SHA or QROM claim.

Build samples K uniformly in {0,1}^lambda, two lambda-bit seeds a_(i,b) for each input i and bit b, and lambda-bit seeds c_(g,r) for every gate g and each of its constant number of possible input rows r. The capsule serializes these seeds, the circuit and canonical context, an optional final correction seed d, and E = sigma_cancel XOR KDF(ctx,K,len(sigma_cancel)). All seeds used by Open are public; no ideal private evaluator.

For a full original candidate w in {0,1}^m, define the input label

    L_i(w) = GGM(a_(i,w_i), delete_i(w)).

The tree root is selected by bit i first, then the remaining bits in canonical order. Both seeds are public. Using a_(i,1-w_i) on delete_i(w) gives the label assigned to the DIFFERENT complete string w^i, not an alternative legitimate label for the original namespace. This removes the need for an exponential prefix cover of late-bit subsets in a single fixed tree. It does not restrict arbitrary callers from evaluating both seeds.

In topological order compute the actual Boolean values of the source circuit, and for a gate g with predecessors u,v and row r=(value_u,value_v), define

    L_g(w) = J_g(ctx,w,r,L_u(w),L_v(w)) XOR GGM(c_(g,r),w).

Use an explicitly distinct gate domain and include wire order, row and full witness. Unary gates/constants can use fixed-width dummy inputs with distinct domains. No separate secret output-label table is needed. Compute

    V(w) = J_final(ctx,w,L_accept(w)),
    K'(w) = V(w) XOR GGM(d,w).

Open returns E XOR KDF(ctx,K'(w),len(sigma_cancel)). This is classical PPT, with polynomial seed count and serialized length, and it does not recover a key by trusting an honest-code validity check. The required equality is K'(w)=K for EVERY original accepted w. The candidate has not established that equality. The bit-first forest and recursive rows compute a reproducible leaf value for every complete candidate, but the leaf is not in general a common key. ## Attempted seed compiler and repair

Try to choose d so that the independently generated label namespace leaves collapse to the common precommitted K only on accepted original inputs. The intended mathematical change from reusable garbling is not to expose a common output root or reusable true label; normalization should occur only at the last leaf of the complete certificate. This is the first explicit compiler equation:

    GGM(d,w) = K XOR J_final(ctx,w,L_accept(w))    for every accepted w.

The right side can be evaluated with actual w (not just the last Boolean acceptance bit), but Build lacks future w. Even giving Build the list of q distinct fixed accepted certificates does not in general make a lambda-bit correction seed exist in the independent ideal-function model.

For fixed upstream seeds, fixed K and any fixed d, condition on the expander domains and all gate domains. The q final J_final inputs are distinct because they include injectively encoded w, regardless of aliasing among internal labels. They are independent uniform lambda-bit strings in the separate final domain. Therefore the probability over J_final that ALL q equations hold for that d is exactly 2^(-lambda*q). Taking a union bound over the 2^lambda possible d gives probability at most 2^(-lambda*(q-1)) that ANY such seed exists. This permits arbitrary selection of d after seeing that oracle. If K is also selected after seeing the oracle, union over K too gives 2^(-lambda*(q-2)). The bound is meaningful for q>=3 in that second case. It is not a bound on a general public program representing the correction, only on the specified seed-only expander compiler.

A more aggressive repair lets Build adaptively choose all seed strings, not just d. Let S count all lambda-bit seeds in the serialized candidate (including d), with the circuit and encoding held fixed. For each fixed tuple of seeds and K the final-domain distinct-input argument still applies. A union bound gives min(1,2^(-lambda*(q-S-1))) over the existence of ANY tuple satisfying the q equations, even allowing unbounded adaptive selection of that tuple. The source relation and the fixed q original witnesses must be independent of the ideal *label* hash domains for this statement. No claim is made that a given real withdrawal has q>S+1 known qualified witnesses, or that actual SHA obeys this ideal-domain model; q is a conditional test of the construction on instances with sufficiently many qualifying certificates. Attempt to move normalization earlier, before gate outputs are consumed: choose one secret root s_(g,b) for the desired leaf label GGM(s_(g,b),w) at each gate Boolean output. Then for every input row r yielding b one needs the *same* public row evaluator to satisfy

    Corr_(g,r)(w) =
       GGM(s_(g,b),w) XOR J_g(ctx,w,r,L_u(w),L_v(w))

for all w realizing that row. A seed-only Corr repeats the overdetermined equality at the internal gate; if the target output-root seeds and input-root descriptions are simply serialized to compute Corr as ordinary code, arbitrary callers can compute the target leaves for either output value, not just the row justified by the full source input. If the accepting root is made common to the native KDF, the key is directly exposed; if the final normalization is still needed, the candidate has not solved the terminal equation above. An honest local row check after revealing a root cannot restore confidentiality. Keeping the roots private leaves Corr unimplemented. Thus no actual seed compiler of this form can be credited as the needed gate repair.
