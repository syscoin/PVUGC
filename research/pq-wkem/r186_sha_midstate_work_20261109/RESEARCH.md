## Candidate A: pre-work midstate shared by all nonces
Propose C_shared=K XOR H_pad(midstate_before_nonce(P)). If P is known and fixed, this chaining state is computable by anyone before mining, so the attacker simply computes the same H_pad and obtains K with no original witness. The checker substitutes an explicit domain-separated SHA256(P) for the midstate to demonstrate the public-info issue; it does not claim to serialize actual compression state. ## Candidate B: completed parent work SHA digest

## Candidate C: delayed coinbase secret opening
Try setup-secret s, coinbase body CB(s)=prefix||s, parent-merkle commitment m=SHA256d(CB(s)), and sealed E_s=K XOR H_pad(s). A miner can mine a header committing to m while seeing only m, but a complete authenticated source proof requires the ACTUAL committed coinbase body and Merkle proof, not just the header/commitment. If CB(s) is given to anyone before work, s is readable and opens E_s early. If everybody with s erases and miners see only m, a header may meet PoW but nobody can produce the committed coinbase body for a full source witness. If an actor releases CB(s) after work, that actor is an ONLINE release authority, forbidden here. N-of-N key erasure does not fix this timing split for the proposed carrier: an honest erased share blocks useful complete data publication; prepublishing it defeats conditioned secrecy. This is NOT a theorem against all hash-based WKEMs or other source circuits.
