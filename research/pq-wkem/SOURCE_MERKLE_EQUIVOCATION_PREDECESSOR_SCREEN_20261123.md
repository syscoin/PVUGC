Thus honest adversarially *incompatible histories* are not required to provide such an opening; requiring it upgrades ORIGINAL evidence into a collision attack. This statement does NOT confuse ordinary different-index membership proofs under one tree (which are perfectly valid and reveal no collision) with contradictory openings at one index.

**Genuine incompatible histories:** Qualified Bitcoin and Syscoin forks usually commit to DIFFERENT descendant block/transaction roots while sharing an ordinary ancestor. Their authentic ancestry paths have separately authenticated branch roots. There is no same-root contradictory opening at the same leaf index. If the proposed pad uses only a common ancestor, that value is already public with the baseline and cannot gate cancellation. If it uses `H(rho_0||rho_1)` or any unknown conflicting descendant as a pad, Build cannot precompute a frozen `D` for every possible later witness.
