## Previously missing property and its precise scope

The preceding hidden-master SOURCE encrypts the **entire 256-bit native master** separately in each of J related same-scope capsules. Revelation of the encryption coins `(r_j, eta_c,j, eta_d,j)` for even one capsule makes the master **public** with no SOURCE opening or ORIGINAL witness. Keeping the ciphertext size and SOURCE matrices of three related capsules unchanged, the following scheme makes **one arbitrary complete coin disclosure reveal an information-theoretically independent Shamir share**, while any two obtainable packets allow the SAME master to be recovered. It tolerates loss of any one packet (2-of-3), whereas the older 3-duplicate scheme tolerated loss of two (1-of-3); pre-funding DA and the changed liveness requirement must be explicit. This is an improvement in targeted leakage robustness, not a free improvement in every dimension.

## Classical-PPT Build and public release, exact sampling

Fix signer `h`, an exogenous canonical relation/context preamble, and an independently selected **pre-funding random seed label** `prelabel` that is fixed before native key generation and contains **neither pk nor any funding txid/output hash depending on pk**. This corrects a potential *circularity in the predecessor*: it described `G_s(K)` while `s` contains the **very pk derived from G_s(K)**. That formula cannot be used as an ordinary classical-PPT KeyGen unless the two contexts are separated. Draw a fresh, independent `K <- {0,1}^256` per claim. Set `NativeSeeds=G_prelabel(K)` using the predecessor's domain-separated SHAKE256 expansion, with the fixed `prelabel` in place of the final scope; derive genuine native `pk=Native.PK(Native.KeyGenFromSeeds(NativeSeeds))`. Now finalize the *canonical signed scope* `s=Encode(version,R_original,x,actual-claim/UTXO,branch,anchors,window,context,prelabel,pk,exact-challenge-path)` and the pre-funding manifest, and verify actual UTXO/path identity before funding. This separates **acyclic seed derivation** from **full public claim/UTXO/native-pk binding**, even if the final txid depends on pk. Precommitments and pre-funding graph construction must resolve their own output-id timing explicitly; the symbolic scope expression does not certify that graph. Per signer share only honestly uniform `A_h <- F_q^(n*m)` across independent scopes; per scope sample independent `U_s <- F_q^(n*L)` (not hash-derived from pk or a self-referential scope). This is conditional on a real native PQ scheme; the checker uses a mock root and cannot certify native signatures.

Take field `F=GF(2^8)` defined by `t^8+t^4+t^3+t+1`. View `K` as 32 independent bytes in F. Independently draw a uniform 32-byte slope `V <- F^32`; for `alpha_1=1, alpha_2=2, alpha_3=3` in F, define the 32-byte shares `S_i = K + alpha_i V` (bytewise field sum, XOR, and field multiplication). This is ordinary 2-of-3 Shamir secret sharing of exactly the *same* native master. It does not require a common witness, a canonical witness, or identical SOURCE intermediate states.

For each `i` independently draw `r_i <- F_q^n` and `eta_c,i <- chi^m`, `eta_d,i <- chi^L` where the centered bounded error law `chi` is the SAME as in the predecessor. Express `S_i` as 52 canonical little-endian base-32 digits `a_{i,l}` (the unused upper four bits are zero). Publish a **complete packet** for each i:

```
c_i = A_h^T r_i + eta_c,i                              mod q
d_i,l = U_s,l^T r_i + eta_d,i,l + g*a_i,l               mod q
```

The full public view is `Vpub=(R_original,x,s,A_h,U_s,all three (c_i,d_i),g,chi,pk,signed-manifest,setup/DA records,auxiliary,permitted native signatures,all other related/independent-scope public outputs)`. The three packet indices are authenticated and distinct. Never use an old packet under a different scope or U. Other scopes may share A but **must** have independent U, K, V, packet coins.

The SOURCE interface (not yet supplied by ORIGINAL witnesses) accepts any legal vector family `Z=(z_l)`, `z_l in {-1,0,1}^m`, `wt(z_l)=w`, `A_h z_l=U_s,l`. `DecryptShare(i,Z)` computes `t_i,l=d_i,l-z_l^T c_i (mod q)`, uniquely rounds to one of 32 evenly spaced `g*a` values with the cyclic-gap bound, checks 52-digit canonicality, and reconstructs `S_i` (32 bytes). For ANY two distinct authenticated packet indices i,j, `Release({i,j},Z_i,Z_j)` may use *different valid SOURCE states* for each packet, derives

```
V = (S_i - S_j)/(alpha_i - alpha_j)  over GF(256), bytewise
K = S_i - alpha_i * V               over GF(256), bytewise
```

then regenerates genuine native seeds and checks actual `Native.PK(sk) == pk`, manifest/scope/UTXO/path bindings, canonical release message, and (only off chain) signs the exact challenge path with the genuine native signing algorithm. Reject missing, duplicate, malformed, inconsistent, wrong-scope or noncanonical shares. Any valid SOURCE openings yield the SAME `K`, because `t_i,l = g*a_i,l + eta_d,i,l - z_l^T eta_c,i`. For `|eta| <= B`, all errors are <= `B(w+1)`; require `g>2B(w+1)` and `q-31*g>2B(w+1)`. The predecessor's illustrative `q=16777213, n=256, m=4469, w=2000, B=128, g=524287, L=52` meets these correctness inequalities; no claim of concrete 128-bit QPT hardness.

The Shamir one-disclosure property is **exact and unconditional** before considering native pk: for any fixed `K` and any i, `S_i=K+alpha_i V` is uniform on `F^32` since multiplication by nonzero alpha_i is bijective. Thus the pair `(K,S_i)` is exactly uniform on `F^32 x F^32`, and one complete packet-coin disclosure reveals `S_i` and no other information about K except information already available through `pk` and other public objects. Any two shares determine K; **two coin disclosures fully defeat protection** by design.

## Full-public restricted QPT reduction, including adaptive leakage

**Security game and restrictions.** Honest target signer/source setup is classical PPT and samples `A,U` uniformly as above; the relation identity, x, claim, branch, anchors, path, pk and final scope are bound in the signed public manifest; the `prelabel` for seed expansion is chosen independently **before** generating K and pk, so a scope or funding outpoint depending on pk is not an input to the PRG. The adversary is arbitrary *nonuniform QPT*, may process all capsules jointly/coherently and have arbitrary quantum advice independent of target `(K,V,coins)` except through the generated public view and explicitly permitted correlated native checking key/signatures. Only classical leakage requests are supported: *after* seeing the entire public view and doing arbitrary quantum computation, the adversary adaptively chooses up to ONE target packet index and receives its genuine full `(r_i,eta_c,i,eta_d,i)`. Other independent scopes' coins/masters and published SOURCE openings may be revealed according to the previously defined separate-target sampler; these are independently sampled and efficiently simulatable. The target SOURCE opening, target K, secret-dependent hash commitments, target maliciously generated source correlations, and coherent superposition leakage-oracle queries are **not** allowed in this restricted game. They cannot be silently added by the proof. Auxiliary must be efficiently simulatable from the public view and permitted independent data, not hide target master or encryption coins outside the stated interfaces. Nonchallenge signatures may be requested through a **classical** native signing oracle; target challenge-path signing remains fresh. If a quantum oracle for leakage or signing is required, this reduction needs a separately justified model.

Use the **same assumptions as the previous restricted construction**, not a new WE/source-opening assumption: (a) full-vector decisional QPT-LWE on *honestly uniform* `M=[A|U]` with bounded `chi` and the above dimensions (including polynomial samples under the same public M); (b) the predecessor's separately stated QPT secret-input PRG assumption for actual `G_prelabel(K)` versus uniform 384-bit native seed material (not automatically implied by SHAKE); (c) genuine native QPT EUF-CMA with independent uniform 384-bit native signing seeds and permitted classical signing oracle; and (d) QPT authentication/signature security of the scope/manifest and public pre-funding setup. All reductions are straight-line, do not rewind or request any internal SOURCE representation from the attacker. No classical-to-QPT lifting is assumed.

Let `Win` mean unauthorized recovery of a usable final native secret or production of a fresh accepted native signature for the exact protected challenge scope. Let `Leak` be the adaptively disclosed target packet set, with `|Leak|<=1`. For each unordered pair `P={i,j}` from `{1,2,3}`, define `E_P = Win AND (i not in Leak) AND (j not in Leak)`. **Every legal leakage transcript leaves at least one pair unopened**, so pointwise `1_Win <= sum_P 1_E_P` and `Pr[Win] <= sum_P Pr[E_P]` even for quantum-derived adaptive index choices.

Fix P. In hybrid H1 replace *the entire* packet i vector `(c_i,d_i-g*a_i)` by uniform `F_q^(m+L)` and then publicly shift d by the known share digits; in H2 do the same independently for packet j. For each hop a straight-line reduction embeds the complete full-vector ordinary QPT-LWE challenge at the *actual* uniform `[A|U]`. It samples the Shamir K,V, authentic native `pk=Native.PK(KeyGen(G_prelabel(K)))`, all other packet randomness, permitted native signing material, all independent scopes/other signer outputs and their leakage responses itself. It cannot answer packet i/j coin requests when a challenged vector is uniform, but **aborts with fixed outcome 0 at the first such request**. Because `E_P` is false on those transcripts in BOTH compared worlds, the reduction's output probability is *exactly* `Pr[E_P]`. Quantum adaptive computations before each classical leakage request are unrestricted. Therefore

```
| Pr_real[E_P] - Pr_H2[E_P] | <= 2*Adv_QPT-LWE .
```

In H2 neither hidden share's plaintext occurs in any packet. The **remaining single Shamir share** is uniform independent of K, *even if its full coins and plaintext are disclosed*. Consequently the complete remaining public SOURCE/packet/leak view, outside pk/permitted signatures, is independent of K. Only now replace `G_prelabel(K)` with the QPT PRG challenger Y, sampling the remaining single share independently; the simulator does **not** need K. Simulate native keygen/signatures with Y and then use the native QPT EUF-CMA challenger genuine pk and its classical allowed-signing oracle. Recovery of a *usable* private key gives a fresh signature by signing a never-queried protected message; a fresh accepted signature is already a forgery. The signature/hash-domain and the **prelabel** are fixed before the target master. The final transaction/scope may depend on pk but is deterministically constructed and publicly bound after pk exists; it must not feed back into the seed PRG. For each P,

```
Pr_real[E_P] <= 2*Adv_QPT-LWE + Adv_QPT-PRG(G_prelabel)
                + Adv_QPT-Native-EUF-CMA + Adv_QPT-setup-auth.
```

Sum over THREE possible pairs. This gives a 3-fold union bound, not an independence heuristic and not a classical-only speedup:

```
Pr_real[Win] <= 3 * (2*Adv_QPT-LWE + Adv_QPT-PRG(G_prelabel)
                      + Adv_QPT-Native-EUF-CMA + Adv_QPT-setup-auth)
```

for ONE fixed honestly generated protected signer/scope and at most one adaptive *classical* target coin disclosure. If an adversary selects any of N*C protected signer/scopes, use an additional N*C guess/union factor with explicit scope independence and exclude target scopes already opened by other means. The bound counts *all* correlations in the defined full view, including the **real** checking key, two uniformized packets, the remaining real packet and its complete leakage, allowed native signing oracle responses, separate-target multi-scope SOURCE openings, and QPT auxiliary (subject to the independence restriction). A proof that exposes the **actual protected SOURCE opening** cannot use this bound: that opening decrypts all three shares. Setup where a malicious participant controls A,U,K,Shamir shares or native pk is also OUTSIDE the proof.

## Efficiency, completeness regression and test provenance

For 3 related packets, public bytes are **identical** to 3 duplicate-master packets; the master/share length is unchanged at L=52. Using shared-A per signer, N=4 signers, C=100 claims, `n=256,m=4469,L=52`, three bytes/field element and J=3: `N*n*m*3 + N*C*(n*L*3+3*(m+L)*3) = 45,978,768 B` of public SOURCE+packets. Genuine signatures, pk, scopes, manifests, proofs, evidence and Bitcoin witness data are additional. This is **5,425,200 B more** than the previous **two-packet** configuration (40,553,568 B); it is not a storage saving over two packets. The improvement is tolerance of one complete packet-coin leak while retaining recovery if any one packet becomes unavailable. The tradeoff is that two shares must be available, instead of one in a duplicated-master construction. DA and authenticated share correctness must be verified before irreversible funding; native pk checking *after* recovering a candidate does not by itself prove a malicious builder made three consistent ciphertexts.

The exact supplied `check.py` uses deterministic, deliberately weak **TOY** matrices with duplicate columns to exhibit two different legal SOURCE openings, q=65537,n=3,m=8,w=2,B=2,g=2000,52 digits and 32 trials. It checks GF(256) inverses, single-share perfect hiding enumerations, 2-of-3 reconstruction from each pair and both distinct openings, exact complete-coin leakage of each packet, surviving-pair release and wrong-share rejection via a mock SHA256 checking key. The root is **MOCK**, SHAKE256 seed expansion is real, no genuine SLH signing or quantum hardness was tested. Toy duplicate-column A violates uniform-M QPT-LWE sampling and is only for algebraic correctness. Two identical offline runs passed exactly **91,785 assertions**, with captured JSON output and SHA-256 provenance. The QPT reduction is a pen-and-paper conditional proof under explicit independent assumptions, not a computation proving them.
