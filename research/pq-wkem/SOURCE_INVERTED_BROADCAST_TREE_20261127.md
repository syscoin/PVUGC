## 1. Public sibling reconstruction is not credential gating

Consider a binary tree whose keys K_v are defined bottom-up, with internal key K_v=H_node(ctx,v,K_left,K_right), in a separate hash domain. Let the entire canonical witness w index one leaf l (for the diagnostic grant an injective bounded padded representation). Try to let Open derive the root from the complete leaf credential and all sibling values along its path, like a Merkle opening. Build publishes sibling values for every permitted leaf path. This is NOT a new source Merkle proof; it is a proposed capsule tree.

For any two distinct permitted leaves l,l', let v be their least common ancestor. The sibling list for l gives K_right at v if l goes left, and the list for l' gives K_left. Thus their public union supplies both child keys of v. The ordinary hash reconstruction computes K_v, then computes all the keys up to the root from the public sibling path above v. No leaf credential was used. If only a single leaf is covered, this exact two-path attack is not asserted. For any tree covering at least two distinct leaves with public plaintext sibling lists, the attack is straight-line and independent of hash inversion, native malleability, or source validity. A root mask E=sigma_cancel XOR KDF(ctx,K_root,length) is then public-decryptable. This is a global path-union failure, not a claim about the soundness of actual Merkle inclusion proofs. Ordinary public source Merkle proofs intentionally expose a public root, not a hidden release key.

## 2. Concrete directional repair before considering original enrollment

Avoid public sibling reconstruction entirely. Choose independent random lambda-bit K_v for each node in an explicitly given finite enrolled tree, root included. For each directed edge e=(child u,parent v), serialize

    D_e = K_v XOR H_wrap(ctx,e,K_u).

Choose E=sigma_cancel XOR KDF(ctx,K_root,length), with separate wrap and KDF domains and injective edge encodings. Context binds all original claim/native/capsule parameters. Open given an enrolled leaf key and its index computes K_v=D_e XOR H_wrap(ctx,e,K_u) along its entire path and unmasks E. This is an exact, polynomial-in-explicit-tree-size Build and Open using hashes and XOR. Independent node keys and upward wrapping avoid the reciprocal sibling-key encryption cycle that would otherwise need a circular/KDM argument. There is no XOR of independently selectable wire labels to form a terminal key; any one complete enrolled leaf key suffices. This is a repair of the public-sibling algebra, NOT an independently secure original witness KEM. In particular, no QROM hybrid for the enrolled scheme is claimed, and tree enrollment has not been implemented for original evidence.

The direct public sibling attack from section 1 no longer gives any plaintext node keys: two outgoing-from-child wraps of one parent are merely two masked copies. The public XOR of the two copies is the XOR of their hash pads, not the parent key. This is an exact algebraic distinction, not a theorem that arbitrary QPT attackers cannot recover the key. Multiple known enrolled keys are intended to release the capsule; their correlations with sibling capsules would still need analysis. The following enrollment problem occurs even granting an ideal secure implementation of this explicit tree and ignoring its size.

## 3. Offline ORIGINAL enrollment, attempted repairs

Let V_x(w) be the complete original verifier, with all three independently sufficient grounds, actual authentication, relevance, maturity, and exact claim/native bindings. Canonical leaf identity i=encode(w) retains the entire certificate. No final check of V_x may be the only protection on the path. The exact missing operation is an offline classical-PPT generation of public wrapping data and leaf access such that every qualifying future w yields the correct initial key K_i, but arbitrary unauthorized access to any root path implies actual original evidence or an independent justified QPT break.

A prospective compact enrollment uses a secret master seed s and a distinct label for each node v:

    K_v = H_key(ctx,v,s).
    D_(u,v) = H_key(ctx,v,s) XOR H_wrap(ctx,(u,v),H_key(ctx,u,s)).

Build can compute a specific edge using s, independent of knowing the original witness. Open must compute the edge wrap and its initial key for future identities. Publishing s, or a public continuation descriptor that gives all K_v, exposes K_root directly. Publishing s only at a fixed root prefix of a seed-tree with public forward expansion exposes all its descendant keys; a public list of allowed prefix seeds is not source authentication, because an arbitrary suffix under such a seed is enough to derive a key. If an explicit prefix represents only syntactic identities, then some of those may be nonqualifying; if it represents only qualifying canonical certificates, anyone can complete such a published prefix and verify a qualifying certificate. The latter observation is only about an explicit nonempty prefix cover, not arbitrary succinct constrained keys. The prior constrained-FSS note already identifies this prefix-cover limitation; do not implement it again.

A different repair uses a witness-derived leaf key K_i=H_leaf(ctx,encode(w)), rather than the master seed's output. When i is the complete encoding, Build can evaluate that leaf key for a particular named w without extra secret information, but then has named/enrolled that particular witness. If it explicitly lists all leaf wraps indexed by those complete encodings it has made the witnesses public. If it instead uses a public identity digest i=H_id(ctx,encode(w)) and defines the leaf key as H_leaf(ctx,i), anyone can compute the leaf key directly from a published directory entry. Public leaf membership by identity alone is not a secret credential; testing a full original preimage of i only in honest Open does not restrict the actual hash-pad access. If the key depends on the full preimage rather than i, Build needs that preimage for a named enrolled leaf. This is a concrete distinction between a public receiver identity and the private credential needed by the directional wrapping construction. No inference about inversion of actual source hashes is necessary.

The repaired explicit hierarchy can instead use arbitrary independent random leaf keys. Then the actual original certificate must deliver a matching key or matching edge pad; this is the unresolved cryptographic enrollment step, not simply verifying identity membership. Granting a hidden master-derived private-key issuing function restricted to V_x would assume the very missing operation. An ordinary certificate authority, hash-based signature on a receiver identity, or source verification key does not compute that secret. A public encrypted edge directory for all future certificates would additionally have to implement the above correlated edge equations compactly without revealing root or forbidden leaf keys. Neither a Merkle commitment to the directory nor ordinary PRG expansion provides the needed restricted evaluation. Reversing hash-chain direction also cannot turn a public parent into a private child preimage chosen by an unknown future original witness.

If considering the actual source Merkle or ancestry path as a key hierarchy, its root is a public authenticated commitment, not a private root selected by Build. Applying a public KDF to it gives a public pad; making a hidden root key out of it requires a new secret-dependent correlation that the original source proof can evaluate. There is no change of the source relation or claim that all original witnesses contain a common unknown preimage.
