## Serialized trial

Let R_x be the unchanged original source relation, including all three sufficient grounds, relevance, maturity, full authentication and burn typing. Let S be the fixed native cancellation signature; V_x is its public verification predicate for the frozen context/message/key. Use the auxiliary relation F_x(w,s)=R_x(w) OR V_x(s), as in the preceding note. Its native-signature branch is a setup witness, not a qualifying original certificate. In particular F_x is true even on FALSE original instances.

Consider a classical polynomial-time public-coin proof of F_x with first message a, t-bit challenge e, response z, verification Check(a,e,z), and a chosen-challenge honest-verifier simulator Sim(x,e). Grant correctness. The trial needs fresh randomized first messages (including an independent salt covered by verification), and uses a separate hash domain H_FS(ctx,a) truncated to t bits. For the quantitative screening only, this domain is an ideal random function independent of the interactive proof coins and other hash domains. This is not a theorem about concrete SHA. Define g as a public deterministic polynomial-time key function, of output length |S|.

Build(x,S):
1. Use (dummy_w,S) as witness, generate first message a0; compute e=H_FS(ctx,a0), generate valid response z0.
2. Compute K0=g(x,ctx,e,a0,z0). Publish C=(x,ctx,e,E=S XOR K0) and erase private data. In this trial the first message is not committed into C, and is not itself a native claim identifier. The full native and original context remains fixed.
3. No public per-wire labels or private evaluator are assumed.

Open(C,w):
1. Use (w,dummy_s) with R_x(w)=1, generate independently randomized coherent first messages a; compute H_FS(ctx,a). Retain the first one in bucket e and form its valid response z with w. Reject if the bounded number q of trials is exhausted.
2. Compute K1=g(x,ctx,e,a,z), return E XOR K1. Native verification may detect failure but is not a release control.

The required equation is K1=K0 for every qualifying w and honest Build sample, up to a specified negligible error. Note that g has no access to the hidden setup transcript. Adding independent fresh proof repetitions does not by itself establish the equation. A KDF of complete proof bytes has no reason to give equal keys on different accepting transcripts; in a separate ideal KDF domain, independently sampled distinct transcript inputs give independent pads, so equality occurs with probability 2^(-|S|). Deriving g from the bucket alone gives equality but publishes the pad. The attempted repair is to exploit proof-specific private entropy retained in every transcript within the same challenge bucket, while allowing arbitrary first messages and responses.

## Resource/security fork for that repair

**Long bucket:** Under the specified fresh-transcript sampler, each previously unqueried a has probability p=2^(-t) of being in bucket e. Condition on the Build sample and its challenge; accidental reuse of a0 or earlier oracle inputs is excluded by fresh high-entropy salts, with the corresponding negligible collision term added if the salts are finite. Thus after q distinct fresh queries the success probability is 1-(1-p)^q <= q*p. For superlogarithmic t and polynomial q this is negligible. The original source witness only supplies the response to a challenge here; it supplies no shortcut to the independent hash target. Classical Open fails completeness even on TRUE. This is a statement about this algorithm and independent-domain idealization, not a general lower bound for every possible source-dependent construction. Actual qualifying witnesses need not have been chosen to optimize any auxiliary proof hash, so their existence cannot substitute for the missing shortcut.

**Short bucket:** Suppose p is inverse polynomial and choose q large enough to make the exhaustion probability negligible. A public adversary can instead sample candidate transcripts from the chosen-challenge simulator Sim(x,e), checking Check(a,e,z) and H_FS(ctx,a)=e, retaining the first passing sample. For this attack require that the interactive simulator works with the actual other hash domains, not by programming H_FS, and that its fixed-challenge transcript distribution is indistinguishable from an honest fixed-challenge transcript using the source witness, jointly with the realized capsule C as auxiliary input. Assume either exact simulation or computational indistinguishability stable under polynomial repetition and access to the independent H_FS. These are explicit conditions of the trial, not security properties inferred for arbitrary proof systems.

For exact simulation, the real fixed-e transcript and simulated one have identical distributions. Sampling a real first message followed by a response to fixed e and filtering on H_FS(ctx,a)=e is distributionally the same as honest Open, since the first message is generated before the challenge. The simulator's fixed-challenge samples can therefore be filtered in precisely the same way. This uses ordinary hash evaluations rather than Fiat-Shamir oracle programming or equivocation of a binding commitment. For computational simulation, use a polynomial hybrid over the q samples with the real C retained as auxiliary data; filtering, selecting, computing g, XOR and public native verification are efficient transformations of this experiment. Equivalently the negligible distinguishing error is multiplied by at most a polynomial if using conditional rather than bounded-loop distributions. The attack neither extracts private adversarial state nor needs a qualifying source witness.

In a hard-TRUE experiment, honest correctness says that the resulting decoded value is S except for negligible failure when the transcript comes from a qualifying source witness. The simulated transcript yields an accepted native signature with essentially the same probability (verification is an efficient distinguisher). With exact simulation it also yields the same exact signature recovery probability; computational simulation of exact recovery can be assessed if the joint experiment permits S as auxiliary checking data. Accepted native forgery is already sufficient for the requested security obligation. Crucially the auxiliary relation is always true because Build has the native signature, so public simulation is not blocked simply by absence of a source witness. No claim is made that correctness alone forces a matching pad on FALSE original instances; it need not, and hard-TRUE suffices to reject this repair.

Thus bucket matching either requires non-PPT honest work in the stated fresh sampler or admits a public simulator that bypasses the source in the stated simulatable short-bucket model. The two failures are separate: one cannot use the inefficient long-bucket mode to claim security of an efficient Open. No quantum attack is required to reject an otherwise claimed QPT-secure mode in the latter case.

## Attempted escape and handoff

A possible escape would be a **source-dependent targeted first-message sampler**: given every original witness w, produce an accepting transcript in the specific precommitted high-entropy bucket in classical PPT, with a pad correlated with the setup's hidden transcript, while an actual-oracle public simulator cannot sample that conditional distribution. Merely moving source bytes into the hash input still gives fresh independent hash outputs; allowing challenge selection by the source changes the capsule's bucket and no longer forces the same pad. An ordinary programmed Fiat-Shamir simulator is not an algorithm available to the opener using fixed real SHA. A witness-derived targeted sampler would require a new explicit algebraic/hash-only operation linked to real source authentication; none is constructed here. Further varying t, salts, number of repetitions, proof backend, or proof hash placement is not a productive continuation.

The full public view includes x, native VK/message, C, ctx, source commitments, auxiliary and sibling capsules. A real construction must jointly simulate those with malicious source-coin retention and prove both FALSE security and arbitrary hard-TRUE recovery/forgery reduction to an actual original certificate or independent justified break. The restricted rejection argument here does not supply such a construction or a general impossibility theorem. It does not alter the original source relation, endpoint graph, R225 activation binding or the coverage-only interpretation of R316.
