## Candidate and direct simulation screen

Let R_x be the full unchanged original three-ground verifier. Fix its bounded Boolean or RAM execution, including input parsing, every authentication/relevance/LC maturity/work/burn check and output acceptance. Use Z_j for the full logical execution state after step j; in the candidate it includes the current entire hidden state from the predecessor (all local factors and exact amplitude) and the original verifier's state, not just a single gate's bits. Let T_(j,a) be a local allowed-row transition acting on that entire state, with a including the selected source bits. The predecessor's dense matrices give a concrete T for its transport component. Assume temporarily that consistent accepting execution reaches a fixed canonical target V, and that the terminal pad is H_expand(ctx,V) with independent domain separation. This grants only correctness of the transport along valid streams, not security.

Try public split-state or other randomized non-malleable codes Enc_j,Dec_j with different stage parameters pp_j. Build publishes pp_j, c_0=Enc_0(Z_0;r_0), D=enc(S) xor H_expand(ctx,V), and public refresh programs
    U_(j,a)(c;r) = Enc_(j+1)(T_(j,a)(Dec_j(c));r).
Reject if decoding fails or the row is invalid for the decoded state. Open selects the chronological allowed rows from the actual complete original witness, runs U with fresh coins, decodes the final state, and applies the terminal KDF. This is a concrete polynomial-size wrapper if the underlying states, row maps and codes are polynomial size. Its mathematical change is a global nonlinear encoding on each refresh rather than additional matrix noise or another factor basis.

Attempted security hybrid: after each honest refresh, replace the global encoded state by a freshly randomized codeword and use non-malleability to treat any adversarially changed codeword as either the same state or an independent state. This is invalid for the actual public view. For ordinary public Enc,Dec, a single joint PPT tampering map can implement
    F(c) = Enc_j(f(Dec_j(c));r*)
for any efficiently computable f, e.g. complement one chosen bit of a multi-bit state. Dec(F(c))=f(Dec(c)) by correctness. Such a state-dependent transformation is not a same-or-independent distribution in general. A split-state non-malleability experiment may exclude precisely this map; the real capsule is fully public and cannot exclude it. This argument does not assert a failure of a split-state code under its own definition. It identifies a wrong security-model transfer for this wrapper.

More specifically, the original public state closure attack lifts through this exact wrapper unchanged. The public decoder permits recovery of every underlying state at the stage boundary. The adversary can run the predecessor's local matrices directly, or evaluate the public refresh on chosen states and decode outputs to obtain the accessible row ratios and normalized factors. Since Enc is public, adding independent encoding coins does not restrict the states on which these programs can be run. The wrapper does not change the predecessor's transport equations. In the earlier hard-TRUE argument, integer flow balance recovers the target including amplitude without an original witness. The earlier FALSE cycle fixture also remains a fixture for that transport. It is not a new test or proof about real BTC/SYS. Therefore do not implement a larger code, a different encoding basis, or another fixture for this public-decoder variant.

## Repair attempt: hide intermediate decoders, authenticate refresh of full state

The meaningful repair changes actual disclosure. Keep Enc/Dec keys secret at intermediate stages, expose only an authenticated refresh token for each transition, and expose a terminal decoding mechanism. Try the explicit hash-only private encoding
    c_j=(n_j, Z_j xor H_expand("state",ctx,j,k_j,n_j),
              H_tag("auth",ctx,j,k_j,n_j,Z_j))
with independent uniform stage secrets k_j and fresh nonces. The keys are not given to Open. A receiver must execute the entire refresh at a hidden decoded state, not recover k_j or Z_j to software. Build knows stage keys and V, but it does not know the later source. For a transition between two concrete states (Z,Z') at concrete salts, Build could publish an encrypted correction to the masked state and the next tag. For an arbitrary original source it must handle all reachable states and fresh nonces. An explicit table of corrections over all states/nonces is exponential in the general bounded verifier and is not classical PPT. Restricting to a fixed polynomial list of actual states would silently remove original witnesses.

The hash-only refresh algebra can be written exactly. Let P_j(n)=H_expand("state",ctx,j,k_j,n), and let m be the public masked part. To return the correct next masked part, the public token must compute
    B_(j,a)(n,m,n') =
      T_(j,a)(m xor P_j(n)) xor P_(j+1)(n').
It must authenticate that m was issued for the hidden input, and compute
    A_(j,a)(n,m,n') =
      H_tag("auth",ctx,j+1,k_(j+1),n',
            T_(j,a)(m xor P_j(n))).
Neither equation follows from ordinary hash/PRG evaluation on public inputs. Revealing the stage seeds to implement the equations removes the proposed private encoding. Providing a program that contains the seeds as ordinary constants does the same in the full public view. A software assertion over decoded states is not a cryptographic restriction on an arbitrary caller. A hidden evaluator for these equations would be the missing construction, not a hash-only implementation.

Try replacing the hidden MAC with a publicly verifiable forward refresh tag: from a public prior tag t, let t'=H_tag(ctx,j,a,t,n',m'). This is computable for any chosen m', regardless of whether the hidden-state transition produced it. A verifier of just that recurrence supplies no authentication of the hidden relation. Requiring the full original certificate in a verifier of the recurrence restores a check of evidence but still does not implement B or a secret pad recovery. Moreover independent accepting histories may produce distinct tags. Encrypting S under one public-history tag cannot ensure every-witness agreement; encrypting under an input-independent terminal tag publishes the pad if the tag is public. Thus this proposed tag repair is rejected without expanding state tables or repeating source-pad trials.

A terminal-only private decoder also has to be treated as a disclosed capability in the actual capsule. If its key is published as ordinary data, the security experiment already includes it; the preceding stage must cryptographically prevent generation of the relevant terminal encoding on unauthorized inputs. A terminal software check cannot repair a stage updater that allows unauthorized states. This does not rule out a secret stage encoding with genuinely publicly evaluable restricted transformations. It explains exactly why this non-malleability proposal has not constructed them. The independent split-state simulation and independent per-stage code randomness provide no joint simulator for the keyed refresh token, terminal key, native VK/message, related capsules or maliciously retained source coins.
