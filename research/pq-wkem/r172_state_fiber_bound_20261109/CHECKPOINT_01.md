Candidate repair to R171: replace its native single preimage fiber with a hash-sealed **complete verifier state** whose release label is path independent for every legitimate ORIGINAL witness. The graph's state must include authenticated claim/UTXO, child outcome vs complete parent-work certificate, anchor/window and any assignments which are reread. Treat the source as an arbitrary polynomial-time verifier, not a hash puzzle. Let graph states s have random k-bit potentials L_s, public transition record keyed under H(L_s, step, branch) encrypt L_{s'}, and each accepting state share a final frozen capability key K. A witness specifies edges; honest traversals of all accept paths yield one K. The new unfinished task is to make this graph compact and maintain cryptographic soundness when all edges and hashes are public.

Investigate exact read-twice verifier language L_n={a||b: a,b in {0,1}^n, a=b}. Each first-half assignment requires remembering n live bits until its matching reread in the second half. Distinct first-pass strings a and b are distinguished by suffix a. Consequently, any **deterministic path-state graph** reading this input left to right without secret external state has >=2^n distinct states just after the first pass (Myhill–Nerode style argument). Compact binary state representation uses only n bits but does not give the setup a polynomial number of independent secret random labels to publish. This lower bound is for that public explicit graph architecture, NOT an impossibility theorem for arbitrary witness encryption or hash circuits.

A proposed repair is an on-path arithmetic fingerprint state (e.g., sum 2^i(a_i-b_i)). This checks equality with n+1 bits and has polynomial-time transition functions, but still has 2^n reachable midpath values. If L_state is a publicly computable hash of the fingerprint, everybody (including an invalid-source adversary) can evaluate its accept label. If L_state is a secret keyed hash, Open cannot evaluate it without the secret key or a whole exponential table. A verifier's public accepting predicate is not a secret releaser. Test these claims with executed toy code, and continue to look for a source-authenticated preimage that prevents the public key/label bypass.

Native-signature caution: a partial Lamport key with target SHA256d output y can make any preimage u complete one fixed signature slot; an *interval* PoW predicate SHA256d(u)<T does not constitute a native Lamport verification equation SHA256d(u)=y. Emulating a target interval with a native verification key generally demands a new verifier or representations of many accepted output digests. Even if this were solved, it would not provide the frozen ordinary native sigma across every ORIGINAL witness. These are candidate-specific constraints; not universal impossibility claims.

Planned executed tests: exact reachable prefix equivalence classes n=1..12; contradictory rereread path accepted if state merged; direct label traversal of explicit graph finds acceptance without a witness supplied externally; fingerprint field checks and adversarial public label read. No calibrated QPT security proof is claimed.
