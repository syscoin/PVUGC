## Raw source-input prefix compression
Let A_x be the set of original qualifying certificate bitstrings for the fixed x, with the existing three independent OR challenge branches and full relevance, contextual AuxPoW, source history, maturity, claim, deadline/reset and native cancel-message binding. Ordinary GGM gives public descendant keys from a published prefix seed. If this publicly exposed key is already sufficient to release K, any reader obtains it without a certificate. If the key is only conditionally useful, the missing cryptographic source-dependent release remains unimplemented. In the favorable idealized prefix-only model where every covered raw input is qualified, exact completeness/soundness require a dyadic prefix cover consisting of *all-valid* subtrees. A raw input outside the original relation may not decrypt merely because a plaintext verifier is placed after an otherwise public pad.

For an independent random hash-target predicate on n input bits with acceptance p=2^(-d), each dyadic prefix block of size 2^j is entirely valid with probability p^(2^j); there are 2^(n-j) such blocks. Thus E[X_j]=2^(n-j-d*2^j), and
Pr[an all-valid subtree of size >= 2^j0] <= sum_(j=j0)^n 2^(n-j-d*2^j).
Also Pr[|A| < p*2^n/2] <= exp(-p*2^n/8). Outside these exceptional events a cover with maximum subtree B needs >=p*2^n/(2B) entries. When n-d is superlogarithmic and B polynomial, this is superpolynomial. This is a random-function **toy acceptance-language bound**, not a concrete SHA or original-Bitcoin/Syscoin theorem.

Publishing subtree seeds also makes leaf secrets immediately computable; even a compact cover does not cryptographically authenticate source evidence or yield one common key. Hiding seeds behind SHA commitments does not help an ordinary original witness recover them: future headers do not contain the independent setup seed preimages. Requiring a public predicate-constrained secret evaluator to bridge this gap merely renames the missing construction.

## Digest-domain pivot and repair
A SHA256d work digest with target-prefix zero bits has an easily described prefix domain. But a digest-domain GGM key does NOT bind a claimed digest to its SHA256d *preimage*, contextual target, canonical AuxPoW parent coinbase/SYS tag, Bitcoin-history anchor, relevant Syscoin ancestry and LC depth. Anyone can submit digest zero to a public digest-only evaluator. A public `VerifyOriginal` after recovering K is not cryptographic gating. Even perfect prefix compression therefore fails ORIGINAL source qualification.

Ordinary GGM independently derives different leaf values for different future valid certificates; with one frozen D=sigma_cancel XOR H(K), these cannot all be used as the SAME K without a per-leaf correction. Publishing those corrections for all future digest values is exponential; publishing an unconstrained correction exposes K on invented digest values. The repair requires a **new serialized, source-authenticated, common-value, hash-only public evaluator**; none was instantiated here.
