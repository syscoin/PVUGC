## Candidate R2-CAP: canonical sparse-Merkle absence path

Hypothesize a **consensus-authenticated, complete, deterministic** source-state burn registry committing exact BurnID -> (amount, recipient, reserve, authorization, replay status) at one fixed height. We are **not** claiming this registry exists in the deployed Syscoin source or that an arbitrary private root is sufficient.

For a fixed root `rho`, exact burn ID `k`, fixed tree depth `d` and canonical encoding, use domain-separated node functions:

```
L_empty     = H("EMPTY")
L_occupied  = H("OCCUPIED", canonical(k), canonical(record))
N(l,r)      = H("INTERNAL", l, r)
```

A complete absence witness `p=(s_0,...,s_{d-1})` is the ordered sibling path from the empty leaf to `rho`, with directions determined by the bits of the **authenticated** index k. Exact length, index, node-byte sizes, root and encodings are mandatory. The intended semantic token was `T=H_tok(context,rho,k,s_0||...||s_{d-1})`; this is NOT claimed to be a secret token or sufficient key-release gate.

### Exact lemma, including QPT attackers

For fixed `rho,k,d`, two **different** accepted empty-leaf paths imply a collision in the domain-separated internal-node hash. The extractor computes both traces bottom-up: their starting leaf is identical, some sibling differs, and their final roots agree; at the first reconvergence after divergence, two different ordered node inputs have exactly the same hash. This produces a concrete classical collision, using only the accepting outputs, in polynomial time. It is straight-line and works even when those outputs were generated by an arbitrary QPT adversary. It relies on **QPT collision resistance** of the exact hash; it is not a reduction from preimage resistance alone or a standard-model proof of SHA256 hardness.

Likewise, a valid *empty* leaf proof and a valid *occupied* leaf proof for the same `rho,k` imply either a collision of domain-separated leaf hashes or a reconvergence collision in their internal traces.

Thus all accepted **canonical absent paths for one exact authenticated source root** coincide except under a QPT hash-collision break. If different outer BTC/AuxPoW witnesses authenticate that *same* root, their inner R2 path can be normalized to the same semantic token. This reduces the common-output ambiguity for this **one fixed-root subrelation**, not for different source roots, R1 or R3.

### Why this does not give Build/Open

Try `E = sigma_cancel XOR H_pad(T)`, with raw `Open=E XOR H_pad(T(w))`. If classical Build knows the unique accepting path before construction, every accepted fixed-root witness will recover the same `sigma_cancel`. But the required builder runs before the future activated source/witness is known. Uniqueness of a hash preimage **does not** give the builder its value or the correct hash pad from a public root. This is the exact still-missing algorithm, not proof polish.

Attempted repairs, each rejected for its exact failure:

1. **Public root as pad:** substituting `H_pad(rho,k,context)` makes Build easy but lets anyone recover the secret without the original challenge.
2. **Setup-chosen fake Merkle path:** the builder can select an artificial root/path pair, but cannot make that arbitrary root an actually authenticated Syscoin source-state commitment. Malicious root/path retention also bypasses source admission.
3. **Builder with full state at setup:** it can determine a *static already-decided* fixed-root absence and compute its path, but this does not support a future dynamic withdrawal chosen by one notary or the other R1/R3 challenge grounds. No use of an already known witness is disguised as deferred release.
4. **Including an outer WorkID / source-certificate digest:** a raw token derived from the outer evidence can reject unauthenticated wrappers, but different valid work certificates to the SAME root now have unrelated pads, breaking the frozen common-key identity. Prepublishing a correction row per possible future work witness is a source-indexed, pre-source-enumeration table, not a polynomial compiler. Omitting source-authentication identity entirely lets an unqualified root/path open the raw pad even if honest Open performs a post-hoc original-source check.
5. **Different future authenticated state roots:** even when k stays absent, an unrelated legitimate state update usually changes sibling paths and their candidate tokens. A proof of uniqueness per root does not correlate different roots to the same frozen key.

A supposed sealed evaluator or correlation-intractable NP PRF providing both accepted original-source authentication and hidden-key release is precisely the missing primitive. This pass does not rename or assume it. The canonical path lemma also does not turn arbitrary source negative claims into finite Merkle nonmembership without a real consensus-authenticated complete map.
