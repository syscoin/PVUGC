## Conditional theorem and exact attack

Consider public classical PPT keyless `Build(q,s;r)` for a FALSE ORIGINAL claim template q and native branch PK `vk=(s,B_{q,s}(r))`. The builder accepts adversarially selected coins r, with many independently searchable roots while **keeping public seed s fixed**. A native SLH-DSA-like key generator computes a root `G_s(z)=XMSS_top_root(SK.seed=z,PK.seed=s)`. NIST FIPS 205 Algorithm 18 specifies `SK=(SK.seed,SK.prf,PK.seed,PK.root)`, `PK=(PK.seed,PK.root)`, and top root depends on SK.seed and PK.seed but **not SK.prf**. Its key-equation is from the standard, not a claimed new native-signature attack.

Malicious setup finds a **claw** `B_{q,s}(r)=G_s(z)`, publishes the apparently valid keyless capsule using coins r and PK (s,root), and retains z and any chosen SK.prf. It can then issue a fresh native signature for the intended claim branch without an ORIGINAL witness. This is a **pre-funding chosen-output attack**; neither source-stream extraction (Run 483) nor Run 259's COMPLETE-representation extraction is triggered. Honest already-funded fixed public keys cannot be swapped after the fact.

Under an explicitly **independent, flat h-bit two-root-family ideal model**, with domains large enough for search, store t builder outputs. Classical birthday/claw costs O(2^(h/2)) samples. Quantumly, store t=2^(h/3) builder roots and Grover-search the native SK.seed domain for a matching output: marked fraction approximately t/2^h, coherent evaluations sqrt(2^h/t)=2^(h/3). This is a genuine quantum claw search and assumes reversible access to native root computation and efficient coherent table membership (potentially enormous QRAM). Standard Brassard–Høyer–Tapp technique; no physical resource estimate or actual SLH-specific QROM proof.

**Important security-width accounting:** because the adversary supplies the **same PK.seed** to both generators, only h=bits(PK.root) is searched, **not the 2h-bit serialized PK**. For h=128/192/256, the ideal classical exponents are 64/96/128 and coherent quantum-query exponents are 42.67/64/85.33. FIPS 205 has n=16/24/32-byte roots for its 128/192/256 parameter sets. A hypothetical h=384 gives 128 quantum queries in this very particular model. These figures DO NOT downgrade ordinary NIST SLH-DSA EUF-CMA security; a maliciously programmable independent keyless root family is an additional assumption not present in SLH-DSA KeyGen.

## Escape and falsification conditions

The attack REQUIRES public acceptance of multiple maliciously selected r **at a common seed**, substantial overlap of Build roots with actual native signing roots, and no honest setup contribution fixing/validating the key before adversarial search. A source-conditioned Build that produces nonsignable outputs on false claims (and proves this), or entangles PK.seed with r so it cannot remain fixed, escapes the exact h-bit claw. For independent flat FULL (seed,root) 2h-bit mappings with adequate domains, generic query exponents change to h classical and 2h/3 quantum, **but that is not a proof for any real joint distribution**. With a single already funded output, quantum single-target inversion is a different (ideal 2^(h/2)) task. The source statement may include the final UTXO and key; q is only a pre-funding claim template and final signing context must commit to the actual key.

Taxonomy: chosen-input public evaluation (5), malicious retained coins and signing secrets (6), public checking-key correlation (8), and genuine coherent claw search (9) are decisive. Context and branch binding prevent old signature replay but not a newly generated valid signature under a retained matching SK (7). A single false capsule suffices (4). Seam, gauge, and fingerprint results (1–3) do not apply to this map-only candidate; the flat distribution is a conditional assumption and must be audited, not asserted.

QPT ledger: honest Build and native root algorithms classical PPT, arbitrary QPT adversary allowed coherent evaluation of their public classical algorithms; the displayed attack is **exponential in h**, hence it is NOT an asymptotic polynomial-time QPT insecurity theorem, nor does a no-attack test prove QPT hiding. No auxiliary-advice, multi-capsule, malicious N-of-N, all-witness SAME-key, or accepted-forgery-to-ORIGINAL extraction result is established. No WE/iO/RIO assumption was introduced as a shortcut.
