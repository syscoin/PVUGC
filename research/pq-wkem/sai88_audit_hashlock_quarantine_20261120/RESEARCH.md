## Candidate with precise order

Let i range over N independent participants and j over 2t candidate *whole* bundles. At least one participant h is honest. Each bundle has distinct native signing keys (sk_(i,j),pk_(i,j)). No signing key may be reused between bundles. Independently sample r_(i,j) uniformly in {0,1}^256, independent of native keys and FE coins. Put the commitment H(r_(i,j)) for every participant inside its own j-th native script-path leaf. That leaf checks all N hash preimages AND all N native signatures. Other escape/refund paths must be separately authorized and checked for a bypass.

1. Construct and freeze the native output graph containing **ALL 2t script leaves**, each leaf binding the session/claim policy. Commit the whole graph to the immutable nonwitness output and completely fix the funding/activation txid and cancellation prevout BEFORE constructing signatures or FE. A native script path can in principle be a Taproot-style Merkle leaf; its internal key path must be demonstrably unspendable under the chosen first-release classical assumption, not be a malicious trapdoor.
2. For EACH candidate j, compute its actual script-path native sighash m_j, including the frozen prevout and leaf commitment. Participant i signs m_j and builds a protected capsule C_(i,j) carrying its signature. Commit exact capsule/native key/script/policy bytes and all candidates before sampling audit entropy. A complete builder must cryptographically bind the ORIGINAL three-way challenge predicate inside release.
3. Choose a uniform t-subset of WHOLE bundles after all pre-audit commitments, with honest unpredictability. Audit these bundles, revealing all native signing keys, FE master secrets/random tapes and compilation evidence. **Do NOT open the independent r_(h,j) of audited leaves**; auditing the FE compilation does not require that independent script hashlock nonce. Keep those honest hash preimages unrevealed/erased. Revealed audit signing keys cannot spend those leaves without the honest hashlock preimage.
4. Reveal AND hash-verify ALL N hashlock preimages for all UNAUDITED retained leaves, before irreversible funding. An absent or bad preimage aborts unfunded. Do not modify the native graph, so each previously frozen m_j remains valid. Publishing retained r is harmless ONLY IF the honest native signature remains cryptographically locked in a sound FE capsule.
5. After funding, any ONE watcher possessing any original qualifying witness w tries every retained whole bundle. If at least one retained whole bundle is sound, the SAME w makes all N capsules of that bundle return the required fixed native signatures; the required retained hashlock preimages are already public. No N-party challenge response. Qualifying original witnesses need not share source states or be canonical.

This closes the specific **output-root-change-after-audit** dependency when the claim, activation outpoint and all candidate script paths can be frozen before audit. It does NOT close R225 for unknown FUTURE claims that change the activation outpoint after one-time N-of-N setup. Those still require independently secure dynamic constrained signing or an explicit fully specified slot-global veto. The graph and capsule manifest must not depend on their own final hash. Precommit its session ID and graph first, compile capsules second, and publish a post-compilation manifest independently.

## Security and useful-completeness qualifications

Given independent unknown honest r_(h,j) and no bypass, an audited leaf is inaccessible even though its N signing keys are disclosed. A retained leaf has public r_(i,j), so unauthorized cancellation is still prevented ONLY by the honest participant's *sound* source-conditioned capsule and native signature unforgeability. Leaked audited keys cannot sign a retained leaf because all j keys and TapLeaf hashes are distinct. Bitcoin script, transaction, key-path, hashlock and timing checks remain mandatory; this is not a Bitcoin VM proof.

If the bad bundle set B was fixed by pre-audit commitments and the t-subset A is uniformly selected, the event that audit passes while every retained bundle is bad has probability at most 1/C(2t,t). This is the SAI87 counting argument, not new FE correctness. For t=68, -log2 C(136,68) = -132.1278685. Selective reruns/aborts, malicious coin generation, broken FE correctness, script bypass and native consensus restrictions are NOT included in this count. A malformed retained bundle can be safely ignored if at least one other fully correct retained whole bundle exists and the attacker cannot steal through another branch.

One-honest participant must erase/protect independent hashlock secrets for audited leaves and FE/native keys for retained leaves. A proof of an NP compilation relation cannot prove erasure or security of the underlying compiler. Independent setup coins and exact byte-bound manifest checks precede funding. The requirement to bind actual future claim-specific assertions is not weakened.
