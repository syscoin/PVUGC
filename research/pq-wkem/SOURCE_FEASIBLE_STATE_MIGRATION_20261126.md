## 1. Actual implicit configuration relation

Use a synthetic uniformly random n-bit S and y=H("migration-native-check",ctx,S) to isolate the release operation. This is NOT a real native signing-key or signature distribution. Context includes the exact claim, capsule and native message/VK bindings (not asserted implemented here).

A state is (m,w,z) with m one bit, w a fixed-length padded original witness, and z an n-bit native candidate. Feasibility:

    F_x,y(m,w,z) = (m=0 AND R_x(w))
                    OR (m=1 AND H("migration-native-check",ctx,z)=y).

Adjacency permits changing exactly one of the native candidate bits or changing m, holding w fixed, provided both endpoints are feasible. The initial state for every valid w is (0,w,0^n). The target set is the mode-1 states. A public predicate checks the entire configuration including R_x, not a collection of independently checkable wire labels.

For EVERY w with R_x(w)=1 there exists a path of at most n+1 edges: set z=S bit by bit, then flip m. This does not rely on source proof equality, a shared preimage across witnesses, an explicit graph with efficiently enumerable vertices, or a source witness supplied to Build. The graph has exponentially many implicit vertices despite its succinct uniform description. It avoids the direct graph traversal argument for the earlier explicit resolution graph, but not the need for an actual migration algorithm.

At a mode-changing edge the z value is unchanged, and already satisfies the native hash check. Thus the honest opener needs a concrete method of reaching such a z in source mode, not an existential shortest-path argument. Source-mode feasibility does not distinguish ANY native candidate z: it is independent of all z bits. ## 2. Attempt a constructive navigation repair with hidden coordinate order

The specific missing operation above is selecting the next native bit to move toward the planted target. Instead of requiring the opener to explain a setup commitment or produce a second proof response, let Build precompute a series of checkpoints of its native assignment. The plain public order is an immediate optional-check bypass. Try hiding BOTH the native bit values and their order, without using a witness-dependent salt that Build cannot know.

Build chooses a uniform permutation pi of [n], A_k={pi(1),...,pi(k)}, and publishes the ordered checkpoint digests

    D_k = H("migration-checkpoint",ctx,k,enc(A_k,S|A_k)),  k=1,...,n.

Here enc is a canonical injective representation of the sorted set and corresponding bits. The order pi itself is NOT published, nor are the sets A_k or the partial assignments. The level k is domain-separated; Build publishes only n hashes, not a table of all subsets. The original public context and y remain as in section 1. The checkpoint hash domain is distinct from native check.

A candidate actual Open first verifies the complete original w, then maintains the global state (0,w,A,v) where A is the set of discovered coordinates and v their recovered bits. Start with A empty. For k from 1 to n, enumerate all possible one-coordinate extensions (j,b), j not in A and b in {0,1}; accept the extension if its checkpoint hash equals D_k. If there is no unique matching extension, fail closed. At the end, set z=v in canonical order, verify y, and change m. The genuine extension is in the enumerated set at each step; absent a hash collision among distinct tested checkpoint inputs it is unique. Thus the honest algorithm is well-defined classical PPT with at most n(n+1) checkpoint hash evaluations and the original verifier, and recovers the SAME S for every qualifying original w on the collision-free executions. This conditional correctness is a synthetic capability trial, not a real native endpoint theorem.

The new hidden-order idea does NOT stop arbitrary public recovery. At the first level the search universe has only 2n possible (coordinate,bit) choices. At level k, once the previous partial assignment is recovered, there are exactly 2(n-k+1) one-coordinate extensions. The attacker runs precisely that greedy enumeration with NO w and NO original verifier call. By induction on k it obtains every partial assignment and ultimately S, under the exact same uniqueness condition as the honest algorithm. A collision or non-unique extension causes the same completeness problem for both, not a security advantage. Even if the checkpoints are published as an unordered bag, the attacker can test against every element of the bag at each level; with domain separation and no relevant collisions this is still polynomial. Hiding a global permutation does not hide a planted assignment when each next checkpoint certifies one of polynomially many extensions from a publicly known initial state.

This is a classical straight-line full-public break of the actual repaired capsule, on FALSE as well as hard-TRUE instances. In the synthetic chosen-payload game the attacker compares the recovered S with the candidate payloads. It never provides a source certificate, does not need a quantum query or a hash break, and does not rely on splicing two source traces or probing an additive secret evaluator. A full-view simulator cannot hide the selected synthetic capability for this construction. Native checking-key and sibling-capsule exposure cannot remove the attack. A proof that each configuration is feasible, or a hash commitment to the complete source witness alongside it, does not change the published checkpoint arithmetic.

## 3. Repair boundary, not a proposed primitive

One can make the initial migration state depend on actual w (e.g. retain the complete w as above); but the public checkpoint test in section 2 depends only on the native partial assignment, so the attack remains unchanged. Do not retry hidden index names, additional checkpoint levels, transcript commitments, or fixed source labels.

To defeat the explicit attack one would need an actual source-dependent checkpoint test or native-state transition that can be evaluated from every original w, but not from publicly enumerated partial assignments alone. A possible structural direction is an implicit state graph where reaching a native target is tractable ONLY from a complete source-mode state, with no locally exposed native partial-state verifier. This requires specifying the complete serialized neighbor/transition computation and joint simulator, not simply declaring that infeasible configurations have no edges. For instance, defining a transition to output the next planted bit only if R_x(w)=1 does not construct the transition: the bit still must be recovered by public arithmetic, and an ordinary honest-code branch can be skipped. The test must not require a witness-independent hidden checkpoint opening, since that returns to the known independent-opening obstruction. No such source-dependent transition is supplied here.

The distinction from dual-copy resolution routing is that mere public enumeration of all implicit graph vertices is not polynomial; the actual attack on the checkpoint repair is a constructive, local greedy search that recovers S without enumerating the implicit graph. The distinction from paired proof search is that the choices are adaptive extensions of one global native assignment, not independent solvable-puzzle indices. Neither fact is a proof of impossibility for arbitrary implicit graph constructions. The missing equation remains a genuine source-to-native transport, with a joint full-public arbitrary-QPT reduction. No isolated prefix/graph optimization should be pursued until it is constructed.
