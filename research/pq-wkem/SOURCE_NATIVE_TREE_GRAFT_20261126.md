## 2. Favorable native missing-component algorithm

Grant an idealized Lamport-style fixed-message verifier with independently checked hash preimages. This is a test of the proposed graft, NOT an assertion that Bitcoin supports this verifier or that SLH permits choosing its internal commitments arbitrarily. Assume temporarily that a source Merkle node uses the same injectively encoded hash domain as one selected native signature component. This favorable compatibility is essential; ordinary source and native hash domains need not agree.

For a fixed safe message M, arrange the required digest at one selected index to be a public authenticated source commitment r. Generate ordinary independent preimages for all other selected indices and publish the corresponding partial signature P. For the missing selected index the verifier accepts any canonical q such that

    H(node-domain || q) = r.

A Lamport-style key can be formed in polynomial time without knowing q: simply fill the selected public digest with r, generate the other required key material, and publish P. Public Open(w) parses an original witness for the immediate preimage q of r and returns P with q in the vacant position. If setup knows q, it also knows the exact full signature S = P || q; if it does not know q, this is a keyless attempt and it has NOT implemented the required Build(x,S) for a supplied frozen S. Grant knowledge of q at setup for the next security test. Setup erasure is assumed, and the verifier is fixed to M; no alternate payment or unrestricted spending key is being considered.

For any two witnesses exposing immediate preimages q and q' of the SAME r in the SAME canonical domain, if q != q' then the two strings exhibit a hash collision. Thus the construction actually has a plausible common-value mechanism for the restricted case where every witness opens r: it uses the unique immediate preimage rather than the entire variable witness. It is not necessary that all paths or all leaves agree. The key question is whether any accepted missing-component recovery implies the original challenge. That implication is false for the proposed source graft.

## 3. Exact native-forgery bypass: opening a node is not authenticating a claim

Consider a four-leaf authenticated binary tree with leaf digests l0,l1,l2,l3, internal digests a=H(node-domain || l0 || l1) and b=H(node-domain || l2 || l3), and root r=H(node-domain || a || b). All fields are fixed-width, with left/right order checked. Suppose a hypothetical qualifying certificate contains a proof at leaf 0 and additional authenticated semantic facts, while a benign proof at leaf 2 is publicly available and does not satisfy the ORIGINAL challenge. The leaf-0 proof supplies l1 and b; computing l0 from the leaf gives a, hence q=a||b. The leaf-2 proof supplies l3 and a; computing l2 gives b, hence exactly the same q=a||b.

An arbitrary classical adversary with that benign proof outputs the completed native signature P||a||b on M. It does not need to construct any source witness for a burn fault, heavier BTC branch or incompatible SYS histories. It needs neither a hash collision nor an oracle inversion. It may ignore Open's explicit R check. The two paths give the identical required preimage, not a same-message signature variant; even exact-S secrecy fails when this graft is used. If the tree is public, simply computing its top children is enough and no membership proof is needed.

This counterexample is a symbolic authenticated-tree experiment, not an assertion that a particular on-chain burn registry or source commitment is deployed. It illustrates the missing semantic implication for any graft that uses the immediate preimage of a shared root, whenever a nonqualifying source view also exposes it. Context-bound partial signatures do not change what the root-preimage test checks. The attack completes the native verification obligation directly, so encrypting or verifying additional off-chain metadata after the native signature is assembled is ineffective.

Even the restricted correctness claim requires care: for a root of a canonical source Merkle tree, the top node's immediate preimage is determined by its two children; a proof that verifies the root but presents only an already-known subtree digest may not expose that preimage. Different semantic source witnesses may not open this particular root at all. No assumption of a shared original preimage across all three grounds is justified.

## 4. Attempt to graft at a more specific node rather than the root

Let r_i be a public digest at depth i, and expose all native components except the required preimage of r_i. This changes the set of admitted openings to witnesses that actually expose that specific node's children. For any two original paths whose lowest common ancestor is above i, at least one of the paths does not traverse the chosen node. It may contain its digest as a sibling, but a digest is not its immediate preimage. For example, in the four-leaf tree with r_i=a, the leaf-2 proof provides a and computes b but does not disclose l0||l1. Thus descending from r to a can avoid the particular benign leaf-2 opening but destroys every-path correctness. If the actual policy restricts admissible evidence to one leaf, that is a different relation; no such restriction is authorized here.

At the selected leaf itself, the opening may authenticate one exact record under an existing commitment. This still supplies no predicate for finite missing/invalid historical authorization, authenticated relevance and maturity, or the comparison of two histories. In particular a fixed anchor shared by competing histories does not authenticate the distinct future suffixes simply because one opens the anchor. Conversely, the unknown future suffix's commitment cannot be used as an independently fixed native checking digest at setup unless the scheme provides the missing late binding mechanism. A fixed commitment to a verifier is not a commitment to the result of evaluating it on future original evidence.

One could add an AND of required preimages for selected nodes. The native verifier then accepts only when each opening is supplied, but those nodes are still fixed in advance; if a genuine witness does not expose one required node, completeness is lost. Giving an OR of grafted commitments could cover different evidence paths but makes any one benign opening sufficient. Adding a separate fixed native component whose opening is conditioned on the complete source predicate is exactly the missing construction, not an implemented repair. A stock native verifier with its actual domain-separated internal hashes is less flexible than the favorable test; no native-key graft or deployment assumption follows.

## 5. Handoff

The direct graft differs from earlier label-based transport: it can make the common preimage *literally part of the native capability*, so no representation-extraction assumption is needed to test the candidate. It fails because hash-tree membership and root opening authenticate a commitment, not the complete ORIGINAL challenge relation, and the attempted depth repair removes coverage. The remaining operation is a serialized original-source-controlled native missing component (or an independent full-public encapsulation of it) for which ANY successful native completion entails the required semantic original certificate or an independent justified QPT break, while EVERY qualifying original witness suffices. Do not assume a native root selected from source data supplies that implication. Do not retry this direct graft by changing tree fanout, increasing proof length, wrapping the root opening in a hash pad, or adding ordinary native signatures whose missing components are independently sampled and unrelated to the original evidence.
