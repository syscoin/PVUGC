## Result

NIST FIPS 205 Algorithm 18 computes `PK.root = xmss_node(SK.seed, ..., PK.seed, ...)`, **independently of `SK.prf`**. Algorithm 19 uses `SK.prf` solely to calculate the signature randomizer `R` (line 3). Given *any* candidate `z` satisfying the public equation `xmss_node(z,...,PK.seed,...)=PK.root`, an attacker can choose any appropriately sized `R` and execute Algorithm 19 lines 5–17 with `z` to produce FORS/HT signatures. Algorithm 20 accepts: it extracts `R` from the signature and does not test that `R` was generated by `SK.prf`. Even a different root-preimage seed works. The resulting accepted native signature need not contain an ORIGINAL Syscoin witness or the original serialized signing secret.

The public predicate `G(z)=[F_PK.seed(z)==PK.root]` has at least one marked point among `2^(8n)` possibilities. Coherently evaluating its **public** XMSS-root circuit permits Grover/amplitude amplification in `O(sqrt(2^(8n)/N_PK)) <= O(2^(4n))` root-oracle calls, where `N_PK>=1` is the number of matching seeds. This is an exponential generic **quantum-query** upper bound, NOT an asymptotic QPT break or practical hardware estimate. Each coherent root query is a substantial reversible computation.

For the Run 688 example `b=288, M=2^32`, frontier search takes about `2^128` oracle queries, but this **separate native-root search** gives exponents 64 for FIPS 205 SLH-DSA-128s (`n=16`, signature 7,856 B), 96 for 192s (`n=24`, signature 16,224 B), and 128 for 256s (`n=32`, signature 29,792 B). Therefore `n>=32` is necessary for a *literal* `2^128` coherent-root-query target against this attack, not sufficient for full 128-bit quantum security. **Do not conflate this toy query count with NIST's Category 1/3/5 resource-based security claims.** FIPS 205 explicitly warns that its categories are not a single 'bits of security' metric.

The root oracle uses native `PK` only and bypasses the entire mixer; neither per-slot mask independence nor the Run 259 SOURCE-extractor can repair this route. Run 687's false-instance forgery reduction remains conditional on the actual native EUF-CMA level. The attack family is (5) public chosen-input evaluation, (8) auxiliary checking-key correlation, and (9) genuinely coherent Grover search; it makes no claim against concrete RIO/CLZ mixers, no seam/gauge break, no reused credential/UTXO issue. It is present even with honest classical N-of-N setup and erased signing seeds. A complete proof may legitimately charge this attack to an independent native-signature break, but must quantify the claimed strength.
