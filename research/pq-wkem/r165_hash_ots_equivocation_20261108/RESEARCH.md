## Full explicit RESTRICTED hash-only release

Let ctx contain relation identity, claim/UTXO, authorized challenge branch, source slot, anchor/window and exact intended native signing VK/message. Setup freezes a native PQ-path signature sigma and independent random lambda-bit K, and publishes CK = Hcheck(ctx,K), Dsig = sigma XOR Hmask(ctx,K). Let m be a CANONICAL SEMANTIC SOURCE OUTCOME digest, e.g. Hout(ctx,slot,pure_child_header_hash), not the parent AuxPoW certificate hash.

For each i=1..L choose independent uniform a_i in {0,1}^lambda and define b_i = a_i XOR K. Publish two domain-separated hash commitments C[i,0]=Hlab(ctx,slot,i,0,a_i) and C[i,1]=Hlab(ctx,slot,i,1,b_i). **The signer retains both a_i and b_i**. The signer attests to m by revealing s_i=a_i when m_i=0 and s_i=b_i when m_i=1. Public Verify checks each revealed label against the appropriate commitment. A pair of complete attestations on m and m' with at least one differing bit permits:
    K_i = s_i(m) XOR s_i(m')
for any i where m_i != m'_i. Every such i gives the SAME setup K. Check CK, unmask Dsig, verify the intended challenge-path native signature. The two source witnesses can have different full underlying PoW and ancestor evidence. Two different Bitcoin parent work certificates for the **same** pure Syscoin child are the SAME semantic outcome, and expose the same label choices: they must not unlock.

The exact N-of-N algebraic extension assigns K=K_1 XOR ... XOR K_N; party j publishes its own correlated label commitments using K_j, and two complete aggregate attestations reveal each K_j. This is a mathematical extension ONLY and must not conflate the preauthorization ceremony with existing source-signing quorums. The actual first and second signatures are online source actions, not a public computation from raw PoW evidence.

## Quantum and full-public limits

The published commitments on missing labels share the same hidden K. One attestation gives the adversary s_i for one branch; each missing label equals s_i XOR K. CK and all commitments thus create many correlated checks of a guessed K. In a *quantum random-oracle idealization*, coherent key guessing may take order 2^(lambda/2) queries; the independent-commitment count cannot be multiplied as if it provided independent secrets. A full QPT multi-target hash-bound, auxiliary/sibling-capsule reduction and security proof have NOT been carried out. The toy JS mixes 32-bit words and has no claimed cryptographic one-wayness. The independently executed local CPython checker uses genuine SHA-256 commitments, but still does not measure QPT hardness.

If an adversary directly owns the attester's retained pair secrets, it knows K before either signature. It can reveal a second branch labeled as a fabricated source outcome and immediately recover sigma, bypassing the actual ORIGINAL requirement, even though all two-attestation hash checks pass. The source label verifier checks that the *same signer issued labels*, not that the two underlying histories meet the ORIGINAL Syscoin/BTC anchored-fork/violation relation. Simply running an off-chain source verifier after the release cannot undo the leak. Additional parent-work target, coinbase root tags or public source IDs do not hide the held pair secrets.

For N-of-N: if one honest party erases all future labels at funding, normal attestation cannot be produced; if it only signs one canonical branch, no two conflicting complete attestations can arise (even if two genuine PoW forks exist), violating every-ORIGINAL-witness completeness; if it signs every admissible fork on demand, a continuously available honest online source participant enforces the release predicate, violating the permitted no-online-release-authority model. A malicious source signer retaining both label branches compromises security, which the user expressly treats as a threat. Existing ChainLocks/BLS does not automatically implement our specially correlated hash-label attestation, and ChainLocks must remain optional.

This is a POSITIVE restricted *algebraic common-key design* for a changed source model, but it is NOT a positive generic ORIGINAL-witness construction advance under the task's strict reporting standard.
