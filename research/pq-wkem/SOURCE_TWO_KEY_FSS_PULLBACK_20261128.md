## 1. Desired public pair and distribution

Let R(x,w) be the unchanged original relation, with a bounded canonical witness encoding W in {0,1}^N, including canonical length/padding and the complete verifier for the three independently sufficient grounds. Do not assume a fixed future witness digest or replace complete histories with a vector of local outcomes. Let v be an ell-bit uniform mask and E = sigma_cancel XOR H_mask(ctx,v), expanded with domain separation. Seek classical-PPT generation of (K0,K1) from x,v and public evaluation F such that

    F(K0,W) XOR F(K1,W) = v     if R(x,W)=1
    F(K0,W) XOR F(K1,W) = 0     otherwise.

Zero is a convenient chosen reject behavior, not a required property of a successful WKEM. The zero-mask corner can be excluded by sampling a nonzero v. Correctness would be immediate, but full-public privacy of (K0,K1,E) with native checking data and auxiliary state must be proved; individual key privacy is irrelevant. In particular, do not simulate the pair by two independent keys just because each individual seed is pseudorandom. The XOR is a public interface, not an oracle available only to honest Open.

Use hash-expanded binary trees with domain separation and independent setup seeds as the concrete starting form: expand each seed into two seed children and control bits. A correction word at a tree level can synchronize the two traversals on a nonselected child and preserve an independent pair on a selected child. For a known point p, such a word can be calculated by expanding the actual two current seeds and XORing the nonselected child seeds. At the selected child continue with the corrected seeds, and at the known terminal point a final word can correct the output difference to v. This describes why known-point correction computation is possible; it does not assert a new FSS construction or privacy theorem. We need to generate the corrections WITHOUT a known accepted point, for the full accepted language.

## 2. Attempt: pull back terminal corrections through the source hash verifier

First test the idea of a compact accepted set on the verifier's terminal output (e.g. a PoW digest below a contextual target, or a verifier acceptance bit). A tree over that *output* can use a small range or known-point representation; the actual Open would calculate the output from W and evaluate the pair on it. The proposed mathematical repair is to run the two seed trees directly on the entire W, using correction words at prefix nodes, not expose a terminal-output tree. ## 3. Direct witness-prefix correction

For the direct synchronization variant, a prefix u is called live if some canonical completion W satisfies R(x,W). It may contain both accepting and rejecting leaves. Once the two corrected seeds and control bits are identical on a prefix, applying identical public deterministic expansion and correction rules below it cannot make the states differ again. Therefore no live prefix may be synchronized to equality in this variant, because its accepting leaf must have nonzero output difference v. A known-point tree computes the appropriate decisions along the known point. For the original source language, knowing a prefix is live is itself a decision about an existential suffix, not a public source check on a completed W. A general algorithm able to decide live(u) on arbitrary prefixes in PPT using only x can find a complete original witness in at most N+1 such decisions: test live(empty), then try u||0 at each position, otherwise choose u||1. Verify R(x,W) at the end. This uses the *unchanged* original predicate; it is not an extraction from arbitrary key recovery.

A potential repair is to synchronize only using a readily computable syntactic superset of live prefixes, without deciding true liveness. This can safely leave extra prefixes unsynchronized, but then the final corrections must distinguish all genuine accepted full W from false ones and produce the same v. Consider the concrete direct terminal rule

    D(W) = H_out(ctx,s0(W)) XOR H_out(ctx,s1(W))
    output(W) = D(W) XOR c                for a surviving terminal pair,

with one public common terminal correction c. In the independent-output ideal experiment, condition on m accepted leaves whose 2m terminal hash inputs are distinct and on all setup choices independent of the corresponding fresh H_out outputs. Their D_i are independent uniform ell-bit strings. Even allowing c to be selected after seeing ALL D_i and v, simultaneous correctness requires D_1=...=D_m, probability 2^(-ell*(m-1)). If c is not allowed to depend on any D_i, the stronger probability for the specified common v is 2^(-ell*m). The first bound follows by conditioning on D_1; each of the other independent differences must equal it. This exact calculation is only for the indicated fresh-input distribution; it is NOT a bound for correlated corrections or arbitrary concrete hash circuits. A setup that forces repeated/correlated terminal inputs must separately demonstrate how that correlation is generated.

Per-leaf corrections c(W)=D(W) XOR v avoid the correctness issue if generated separately, but a table over unknown future accepted complete witnesses is not a practical Build. A public algorithm computing c(W) from v-independent data and the two public seeds, conditioned on R, still has to embed the secret v in the correction without revealing it elsewhere. A common correction for all terminal pairs can work if the pairs have a shared secret-dependent difference; the independent-output experiment no longer applies, but no hash-only public generator for that correlation has been constructed. Setting seed differences by linear correction arithmetic is not a remedy without an explicit nonlinear full-view proof; the R327 attack on its own additive evaluator remains a regression, not a general statement about every seed construction.

## 4. Prefix-cover alternative and scope

Try eliminating the common terminal word by generating point/prefix-function pairs for a polynomial list of cylinders u_i {0,1}^{N-|u_i|} whose union is exactly the accepted W. For disjoint cylinders, XOR of their functions yields v on the union and 0 outside; overlapping cylinders require a separate disjointification or parity-aware construction. Even granting efficient pair generation on known prefixes, this is not a solution for hard-TRUE original x. If Build explicitly outputs a nonempty list of wholly accepted cylinders, any one gives a valid ORIGINAL witness by filling remaining positions with zeros (canonical encoding and validity are already required throughout each cylinder). An algorithm producing such a list from x therefore already computes an actual certificate on true x. This diagnoses the positive-cylinder method, without assuming a particular number of accepted leaves. A signed or parity-canceling collection of cylinders not individually accepted is not covered by this argument; however, in a *public explicit polynomial prefix list* one can find a leaf where the parity is one by traversing its finite prefix trie, maintaining ancestor parity and testing unrepresented child subtrees with constant parity. Any nonzero leaf can be completed in O(N) once located. Thus even a parity representation of this explicit kind supplies a certificate, rather than solving the no-witness generation requirement. This does not rule out computationally hidden or non-prefix representations.

The only candidate repair not already rejected here would need an actual compact two-key correlation generator whose output on complete original W has a common difference at acceptance, and whose *joint* public distribution (including full key bytes) can be simulated and reduced. It cannot be justified by ordinary single-key function secret sharing, by terminal-output evaluation on a public bit/digest, by independent fresh seeds, or by a supplied list of known accepted cylinders. This is the unresolved source-verifier pullback, not a new assumed primitive.
