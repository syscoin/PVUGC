# R194 checkpoint 02 — pivot to source-atomic qualified-observation mixing

The initial R194 digest-prefix hypothesis repeats R192's already documented direct source-hash failure. After reading R192's exact research note, do NOT promote or rerun that as progress. The already committed CHECKPOINT_01 is historical provenance only.

New exact subproblem: can a hash-only first-differing-bit carrier avoid R193's global label-mixing attack by assigning labels to COMPLETE authenticated source observations rather than to unconstrained witness-bit occurrences? Focus only on qualified Syscoin AuxPoW fork challenge R3 with a fixed claim-prefix reference height. This is a new source semantic lemma, not a cryptographic label-grant construction.

Let h_rel be the last relevant source height, r=10*ceil(h_rel/10) the common rounded reference height. For qualified candidate history P, define U(P)=its UNIQUE pure Syscoin child ancestor hash at height r, derived from a fully authenticated chain, not from arbitrary coinbase script search or parent WorkID. Require each P's source window, anchor, tag cadence, complete ancestry and fork depth to satisfy Q_x(P). For tagged children of height n, n>=max(r+6,h_rel+kLC-1) is a sufficient high-water mark for both visibility and branch depth when divergence d<=h_rel (subject to all remaining source qualification conditions). kLC is an exact statement parameter, not assumed numeric.

Define an attribute transcript A(P,i)=(i, bit_i(U(P)), P, Q-proof) and only admit attributes with a COMPLETE Q_x(P) witness. The proposed property is: whenever a collection of such transcripts comes from two DIFFERENT U values, those two qualified records are themselves a valid same-reference-height R3 inconsistency witness. If all U are identical, all admitted bit openings are globally consistent with this canonical hash. Thus mixed locally valid attributes from genuinely authenticated source histories cannot create a FALSE-instance mismatch without also proving a real qualified fork.

Scope: only provenance-carrying classical attributes. Does NOT prevent attackers from fabricating labels, from extracting both labels directly out of a public capsule, or from coherent quantum key recovery without supplying any transcripts. Need an independently instantiated cryptographic source-to-label gate that enforces actual Q_x(P) before revealing each label. The existing SHA/AuxPoW tag bytes are not setup-chosen hidden label preimages. Source labels from a public bit function are forgeable without P; labels generated by setup are unavailable in future P unless new release mechanism is built. That missing gate is still a real original-dependent algorithm, NOT proof polish.

If successful, the result would repair the *logic* of global consistency at the qualified-source level without asking which Syscoin branch wins; it would not yet repair source-to-hidden-label derivation, N-of-N composition, BTC-work/burn branches or QPT extraction.

Verify that any pair of authenticated differing labels yields a qualified fork certificate, and reject parent-work-only diversity, malformed root/height and out-of-window records.
