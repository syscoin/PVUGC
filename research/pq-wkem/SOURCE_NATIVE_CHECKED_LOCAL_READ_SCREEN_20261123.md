## Exact proposed interfaces and public-read attack

Consider the candidate architecture in its general read-only form:

    Build(x_W,sigma_cancel;r) -> C=(D,meta,E)
    Schedule(C,w;rho) -> adaptive indices in [M], at most q reads
    Decode(C,rho,((i_1,D[i_1]),...,(i_t,D[i_t]))) -> sigma or reject

D is a polynomial-size serialized table of M blocks (blocks may be long enough for cryptographic data); meta may include source checks, code parameters, commitments and all native context; E may be a payload masked by the decoded KEM key. Decode includes public payload unmasking. The candidate correctness target is Pr_rho[Open(C,w;rho)=sigma_cancel] >= 1-epsilon for each honest capsule and qualifying w (or average over Build's coins if correctness is average). All randomness supplied to Decode is sampled publicly or uniformly independently of w, with witness-dependent choices confined to the read schedule. No claim that this encoder has been realized for the original relation. The purpose is to determine whether a locally decodable code or PCP-style random-access architecture could realize it without a private evaluator.

The architecture permits a completely nonlinear Decode, arbitrary adaptivity of Schedule, and binding Merkle proofs on reads. No requirement that read values are linear or that the attacker supply a valid trace. Because D is public, any D[i] and any honest Merkle opening of D[i] are computable from C. A commitment to public table data does not create read authorization.

Fix C, a qualifying w and public coins rho. For every candidate length t<=q, enumerate the M^t possible ordered index sequences (including repeats), retrieve their actual table blocks and run the public raw Decode, including payload unmasking. If a public stage needs a transcript-derived hash, recompute it from those same bytes. The actual adaptive sequence generated by Schedule on w and rho is one sequence on the list. Enumeration need not predict adaptive choices, check whether a sequence was generated by a legitimate w, or know any source certificate. It simply invokes the raw decoder on the exact public bytes. If the raw decoder itself takes the full original witness as a computational input beyond this transcript, it is outside the proposed interface; a check in Schedule or an external final if-check is not such a dependency.

Let L=sum_{t=0}^q M^t (or pad with an explicit stop symbol and use (M+1)^q). Each candidate costs polynomial time. On honest coins for which Open succeeds, at least one candidate output is the exact sigma_cancel. Two distinct attacks:

* Accepted native forgery/cancellation: test each candidate output against the exact native checking key, message, outpoint and bound context. Return the first accepted candidate. On the honest-success event there is at least one. A different accepted signature for that same fixed message is still sufficient to trigger the endpoint; no claim of ordinary EUF security implying strong same-message security is made.
* Exact-byte recovery without a public digest or unique signature: sample uniformly one of the L sequences, evaluate its decoder, and return its output. Conditional on the honest-success event, the chance of recovering the exact sigma_cancel is at least 1/L. Thus average probability is at least (1-epsilon)/L, even if many other valid native signatures exist. With a publicly committed exact-signature digest one can instead test the list, subject to the appropriate independent second-preimage assumption; the list argument needs no such extra assumption.

These are classical algorithms, hence within the arbitrary QPT threat model. No quantum oracle programming, rewinding, adversary transcript or internal-state extraction, source coin secrecy, or concrete hash weakness is needed. The native checking key's actual correlation with C is preserved because it is used directly, not resampled. Additional related capsules and auxiliary information may simply be ignored. If L is polynomial in the security parameter, the accepted-cancellation attack is PPT with honest completeness probability, and the exact-recovery attack has nonnegligible probability. For M polynomial and q bounded, this includes constant-read secret-block schemes; more generally the condition is polynomial L, not a claim for arbitrary polynomial q.

Qualification: if successful transcript decoding independently and efficiently yields an ORIGINAL qualifying witness, the attack may also be a source-witness solver, not an unauthorized break of a valid construction. But that removes the nonvacuous hard-TRUE regime for which this candidate is sought. On any independently hard TRUE distribution (actual original evidence computationally inaccessible to PPT/QPT under the stated source assumptions), a polynomial list enumerator recovering the capability with the above success cannot satisfy a reduction to original evidence or an independently hard hash/native break. This does not claim a particular actual bridge instance is hard, R is NP-hard, or the architecture fails FALSE hiding; on FALSE the list need not contain an accepted output. The candidate fails the requested hard-TRUE security before a FALSE simulator could make it acceptable.

## Attempted escape via source-dependent joint decoding

The immediate mathematical repair is not another code or longer block. The decoder must either have a superpolynomial public transcript space, or use actual original evidence in a cryptographic operation beyond the read addresses. Merely domain-separating Schedule with H(canon(w)) does not change the attack: the addresses are still among the enumerated sequences. Merely requiring a Merkle opening or proof of table membership does not help when the entire table is public. Moving the original verifier to the start of Decode as a gate over the raw final output does not protect the raw operation.

One attempt at the second escape uses witness-dependent decryption of a read row. Write k for the fixed lambda-bit payload key; let a schedule identifier i choose one of M rows; attempt

    row[i] = k XOR pad[i]
    pad[i] = H_row(ctx,i,canon(w))
    Open_raw(C,w) = row[i(w)] XOR H_row(ctx,i(w),canon(w)).

This changes the decoder interface: raw release now depends on the full source witness, not just the index. But it leaves Build with the exact unknown-source correction problem. If two different qualifying original certificates use the same row and the domain-separated row hash is independent of the verifier, their distinct unqueried hash inputs have independent uniform outputs in a classical ideal-hash calculation. The single row cannot decode to the same k under both except with probability 2^-lambda for a fixed pair. For a qualifying w unknown to Build with its row-hash inputs all unqueried, the chance that any one of M fixed row pads matches a corresponding fresh hash output is at most M/2^lambda, even allowing Open to choose the row after evaluating those hashes. This is conditional on that fresh-input model, not a QROM or concrete SHA theorem. It is the already known source-pad/matching attack, so do not implement this escape or sweep M, q, padding, hash placement or code parameters. If the row hashes are not independent because a genuinely source-specific non-black-box construction correlates them, that correlation needs its own actual public compiler and joint security proof; it is not obtained by assuming a programmable hash.

The first escape, superpolynomial transcript space with polynomial per-witness access, is not excluded by the list attack. It is also not a construction. A witness-preserving public verifier compiler must supply one secret-bearing serialized object and a nonlinear whole-transcript decoding rule whose correctness holds for EVERY original certificate. It must be generated without enumerating those certificates, and arbitrary recovery from the full public bytes (not just well-formed schedules) must reduce to original evidence or an independent justified break. A locally checkable codeword or a PCP verifier alone checks a purported proof, not this payload correlation. Replacing secret-bearing read blocks with a hidden row generator reinstates the missing public evaluator. The preceding separator-key screen already explains why explicit polynomially enumerable consistent assignments can solve the original instance, and why an implicit hidden-seed table generator is missing. Do not redo that screen using a longer read path.

## Disposition and precise handoff

The attempted global transcript decoding architecture avoids relying on inconsistent combinations of occurrence-local labels, but a short public transcript permits a direct native-checked list attack even for nonlinear/adaptive decoding. The full-witness row decryption repair falls to the previously recorded independent source-pad matching problem. No new public correlation compiler, actual original-source release, native signature, executable source verifier, empirical test run, simulator or QPT security theorem was obtained. This is an analytic construction preflight, not a general impossibility result. No fixture was implemented after the preflight failed. Do not continue with larger local-read fixtures, alternative codes, or lookup authentication alone.

The next candidate must change the actual secret-bearing raw decoder so its source-dependent computational information cannot be replaced by a small public transcript, and construct that dependence from x_W and sigma_cancel without predicting future witnesses. It must jointly simulate the full public view, not assume the read transcript or source-dependent decoder is private. Preserve all three original OR grounds, exact evidence maturity/typing, slot-global versus activation-bound endpoint choice, malicious setup and native same-message considerations. No ordinary PR comment or user notification is warranted.
