## Candidate A: normal form of an accepting proof

Proposed public algorithms (the normalizer is the part to construct, not an assumed primitive):

    Build(x,S):
        pp <- public proof parameters and shared public normalization coins
        T1 = Normalize(pp,x,Encode(1,S))
        E = enc(S) xor KDF("cancel",ctx,pp,T1)
        return (pp,E)

    Open((pp,E),w):
        T0 = Normalize(pp,x,Encode(0,w))
        return dec(E xor KDF("cancel",ctx,pp,T0))

Here pp is sampled from x without either branch witness. Encodings are canonical and length-delimited, native verification public, and the KDF independent of proof-generation domains. If Normalize gives T0=T1 for every qualifying w at this pp, correctness is exact. Unlike the previous proof-response reconciliation attempt, no public approximation to a response is required. A proposed security strategy is to use extractability of the canonical proof token: recovery of its KDF input would furnish either an original certificate or a native accepted signature. This strategy must not assume the attacker exposes its internal state or query log, and a QROM transition to input extraction would separately need proof.

Try an explicit normalizer over accepting proof certificates. Use the typed disjunction representation of the entire bounded verifier, not an easier source predicate: a selector b, source witness array u, native witness array v, with each active encoding beginning in a one-bit marker 1. All-zero inactive arrays are allowed as padding but are not active witnesses. Accept a certificate (b,u,v) iff b=0 and u decodes to a valid source certificate, or b=1 and v decodes to a valid native signature. Initialize source proof as (0,1||enc(w),0...) and native proof as (1,0...,1||enc(S)). Normalization attempts to minimize lexicographically by greedily changing a 1 to 0 when F_x remains true; repeat until no allowed decrease. This is classical PPT because there are only polynomially many 1-to-0 changes. It is not required to find any new source witness to begin.

The two normal forms cannot coincide: source initialization never increases any native-array bit or selector; native initialization cannot set the source marker to 1 and therefore cannot change the selector to 0 while maintaining acceptance. In fact even arbitrary public nonmonotone local rewrites preserving acceptance cannot merge the two starts without generating a valid witness of at least one branch from the other. To test the nonmonotone repair rather than merely another variable order, below analyze the intended extractor independently of the particular descent. This is an exact failure of the proposed normalizer for the full typed disjunction, without assuming anything about the internal source verifier or its history rules.

## Candidate B: opaque canonical proof, independently generated extraction trapdoor

Replace the openly decodable normal form by a compact opaque proof token T. Permit a secret extraction trapdoor tau in the proof parameter distribution: (pp,tau) <- Param(x), with both sampled independently of branch witnesses given x. Honest Normalize sees pp, not tau. Require exact token agreement (or failure at most epsilon over the honest joint distribution). The contemplated simulator supplies pp and tau without S or w, and from the proof token alone the extractor X(pp,tau,x,T) returns an accepted typed OR witness with probability at least 1-delta. This allows arbitrary extraction computation on the token, including quantum computation and independent random coins; it does not rely on a submitted representation of an attacker. This is a mathematical repair target, not a claimed hash proof system.

Test under the following explicit conditional ensemble. Source instance and qualifying witness are jointly sampled; the source marginal is hard for classical PPT (or QPT if the relevant reduction and source assumption are QPT). There is an efficient sampler of the joint ensemble for the native reduction, independent of the native signing secret. The native VK is generated independently conditional on source context, and M(x) is the exact cancellation message computed from public data. R_x and the sampler must allow this key binding without requiring its signing secret. The source reduction can sample a native key and one honest signature on M(x); the native reduction receives a challenge VK and never asks its signing oracle for M(x). No claim is made here that the exact real Bitcoin/Syscoin future-history distribution has such a PPT joint sampler; this is the case in which the proposed independent-hardness argument could apply. Any alternative correlated ensemble must be analyzed explicitly.

Couple both experiments with the same x, w, S, pp,tau. Put T0=Normalize(pp,x,Encode(0,w)) and T1=Normalize(pp,x,Encode(1,S)). Include the shared public coins in pp; if Normalize has further randomness, require a joint agreement guarantee for the actual honest Build and Open coins. Run X on each token with the same independent extraction randomness (or, for quantum X, use the same input-state density operator when tokens agree). Write p_i=Pr[X on T_i outputs a valid branch-0 witness] and q_i=Pr[X on T_i outputs a valid branch-1 witness]. Verify outputs and give malformed ones neither type. Then

    p_0 + q_0 >= 1-delta
    |p_1 - p_0| <= Pr[T1 != T0] <= epsilon
    p_1 + q_0 >= 1-delta-epsilon.

The second line holds because conditioned on identical classical inputs the extraction output distribution is identical, regardless of extraction time or randomization. The last line is exact. No query recording or rewinding is used.

But p_1 is the success of a source-finding reduction: given the hard source marginal, sample native keys and S, run Param, normalize the native witness and invoke X. The reduction has no w. The probability q_0 is success of a native forgery reduction: given a fresh native VK, sample the original source instance and w without its signing secret, run Param, normalize w, and invoke X. An extracted branch-1 signature verifies for the fresh cancellation message, which the reduction did not request signed. This uses ordinary fresh-message EUF only in the screening experiment; it says nothing about changing signatures on an already-signed message in the actual endpoint.

Consequently in this candidate ensemble

    1-delta-epsilon <= Adv_source_find + Adv_native_fresh_forge.

If both independent assumptions hold, correctness and independent token-only extraction cannot both have negligible failure. This is a stronger check of the attempted canonical proof repair than observing that its two ordinary proof transcripts differ. Even a hidden, nonlinear, opaque normalization does not rescue the specified independent extraction interface. This is a restricted two-witness argument, not an impossibility of source-specific hash-only WE. It applies before the KDF security step, before signing-role composition, and does not require any adversarial access to the secret extraction trapdoor in the real protocol.

## Repair screen: capsule-dependent parameters and extraction via changed oracle

A possible escape changes the premise materially: make pp depend on S and simulate it only in the security reduction, rather than independently sample it. The native reduction above cannot generate that real pp. If its simulator can produce (pp,tau) without S with the correct joint law for the source normalizer and extractor, q_0 transfers by indistinguishability (efficient test: run the normalizer on known w, extract, verify a branch-1 result). For p_1 the source reduction must be able to sample the extraction trapdoor jointly with a real setup or a compatible simulated setup and normalize its known S. Only a simulator that supplies those respective joint laws restores the inequality, up to the two distinguishing errors. Simulating the marginal pp while losing the token/trapdoor correlation is insufficient. If the simulation is only for the complete ciphertext including E and known S, it need not give either of those laws. Such a capsule-dependent nonextractable normalization is NOT ruled out by this derivation; no actual generation algorithm for it was found.

Another proposed escape is FS-style extraction by changing a challenge oracle instead of applying X to one fixed proof token. In a classical black-box experiment, suppose X can query a normalized-proof prover repeatedly with adaptively chosen modified public parameters or modified oracle descriptions, and each branch gives an exactly equal token for each of those requests (using shared prover coins where appropriate). Couple X's randomness, requests, and replies in the two experiments. The transcripts remain identical by induction and the same inequality follows for final extraction. More generally couple until the first differing reply; replace epsilon by the probability of that divergence event. Thus an extractor relying on challenge modifications must exploit a branch-dependent reply with nonnegligible probability under its chosen challenges, while preserving agreement for actual honest public setup. Honest-oracle agreement does not imply agreement after adversarial programming. This restricted classical transcript argument is not a QROM extraction lemma, does not assume that measuring arbitrary coherent queries is harmless, and does not rule out QROM-specific extraction. It identifies a concrete design obligation for the alternative.

Attempt the obvious programmed-challenge repair: choose independent domain-separated hash challenge e=H(ctx,pp); on an exceptional challenge (e=0) output a branch-opening witness, otherwise output a common opaque proof. This gives a formal way to make extraction replies differ at programmed challenges, but does not generate the common opaque proof on ordinary challenges. Choosing it as a public hash of pp exposes the mask; choosing it as an independent hash of each branch proof destroys the required equality. The transparent Hamiltonian first-message construction already read above supplies two different valid openings to one public first message; neither public first message nor revealing the two different proof openings implements the opaque common token. Therefore do not implement a challenge-bucket sweep, larger graph, code normalization or new hash-placement test in this family. The escape remains an unconstructed operation, not an advance.

## Handoff

The next genuine mechanism must make public capsule parameters correlate with a hidden proof normal form or other target in a way evaluable by every ORIGINAL witness, without the independently extractable common-token trap above. In particular a security proof that simply extracts either witness from a canonical token using independently generated trapdoor cannot serve as its joint simulator in the independent-hardness ensemble. An oracle-programming approach would need both an actual classical construction achieving hidden common-token correctness for ordinary oracles and a separate coherent-access extraction proof; programmed exceptional responses alone accomplish neither. Do not assume canonical proof generation as a primitive or count this preimplementation screen as progress on the requested release.
