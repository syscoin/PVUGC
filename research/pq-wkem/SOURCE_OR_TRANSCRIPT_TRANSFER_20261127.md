## 1. A source branch that CAN be completed publicly

Let R_S(x,w) be the full finite bounded original predicate (all three OR grounds and claim relevance, admission, depth and binding). For a deliberately inefficient but polynomial thought experiment, compile it into a Hamiltonian-cycle graph G_x with forward reduction mapping every genuine original witness to a cycle and a reverse reduction mapping an actual valid cycle to an original certificate. This is only a semantic reduction, not a practical source encoder. Use the usual two-challenge graph protocol with bit commitments: first message A_S commits to every adjacency bit of a permuted graph; challenge 0 opens all commitments and permutation to establish isomorphism to G_x; challenge 1 opens only cycle edges to establish a Hamiltonian cycle in the committed graph. For the static candidate use hash commitments H_s(ctx, position, bit, salt), domain-separated and uniquely encoded. No commitment hiding is needed for the source branch once the challenge-0 response is public.

Build can produce a real A_S and full challenge-0 opening Z_S0 without knowing ANY source witness, even if G_x has no cycle. Put (A_S,Z_S0) in the capsule. A genuine original witness gives a Hamiltonian cycle by the forward reduction, which can be permuted using Z_S0; all the required edge-opening coins are already there. Thus public source response completion Z_S1 = Complete_S(A_S,Z_S0,w) is a concrete polynomial operation, not the missing black-box SourceOpen. Any accepted Z_S1 paired with the authentic challenge-0 opening gives an actual cycle (or incompatible bit commitment openings) in G_x, then a genuine original certificate. This is a deterministic two-transcript semantic implication, not a QPT extractor from arbitrary capsule recovery. It also does not magically hide any native secret.

This addresses a possible objection to the previous fiber preflight: a shared first message can indeed be generated without a source witness and then completed using that witness, if the first message commits to the public instance rather than to an unrelated hidden key. The remaining issue is whether that completion can be coupled to a secret-bearing transcript.

## 2. Attempted OR coupling to the frozen native capability

Let K be an independent uniformly sampled mask key, and Y=H_k(ctx,K) its public hash image. Build knows K and stores E=sigma_cancel XOR H_mask(ctx,K) with distinct domains. Let R_K be the preimage relation for Y. The same graph protocol (with an appropriate circuit-to-graph reduction) supplies a hash-only two-challenge proof for R_K. Its first message A_K commits to a permuted graph; Build can create openings for both challenges because it knows a witness. From two accepting responses to the SAME A_K and DIFFERENT challenges, one can recover K' with H_k(ctx,K')=Y, via the graph reduction, absent a commitment collision. K'=K is needed for exact unmasking; a distinct preimage would require a collision for this binding of the originally sampled key. Neither the native verification key nor knowing the cancellation message supplies the second response.

Use the OR-proof challenge equation c=c_S XOR c_K. Set c=0, initial c_S0=0 and c_K0=0. Publish A_S,A_K,Z_S0,Z_K0, c and E,Y. These can be generated before any source witness exists. Source completion provides Z_S1 for c_S1=1 and unchanged A_S. To preserve global challenge 0, the native branch must now respond to c_K1=1 with unchanged A_K:

    Verify_K(Y,A_K,1,Z_K1)=1.
    K' = Ext_K(Y,A_K,(0,Z_K0),(1,Z_K1)).

The intended repair was to derive Z_K1 from Z_S1 via a joint public transcript helper, making source completion cryptographically authorize the alternate native response. Direct OR composition has no such equation. With independent native commitments, source openings and native witness-dependent edge openings belong to different graph instances. Relabeling vertices, sharing challenge bits or hashing the source response into the native challenge does not compute a Hamiltonian cycle of G_Y. The source proof is not the second native response.

Worse, the ordinary OR transcript chosen in this direction publishes the full native challenge-0 opening. It makes the native graph completely visible, just as the source branch is; nonetheless no cycle is given. Publicly supplying the native cycle/edge selector to repair completion immediately extracts K without source evidence. If instead Build publishes native challenge 1 initially, publishing enough to later answer native challenge 0 also immediately extracts K; challenge-1 opening alone provides no map to the original graph. This rules out the straightforward independent OR coupling in both orientations; not all possible correlated transcript designs.

## 3. Attempted repairs, and the precise dependency

(a) Allow changing the global challenge instead of forcing the native challenge to change. Then a receiver can keep (c_K,Z_K) fixed and set c'=c_S1 XOR c_K. The pair only extracts a source witness, not K. Fiat-Shamir binding of c to the common first messages and context prevents treating two arbitrarily selected challenge bits as two accepted noninteractive proofs; it cannot manufacture an alternate native response. This preflight uses interactive transcript equations internally, not a claim of Fiat-Shamir QPT soundness.

(b) Build a joint AND graph for R_S AND R_K. This would cause extraction of both witnesses from two complementary full openings. Build can publish the real challenge-0 opening of that graph before seeing a source witness. However, to construct the alternate cycle using only a source witness requires a forward map from w_S to a cycle of the AND graph with the unknown K. A normal reduction supplies that map only from (w_S,K). Publishing native cycle data sufficient to reconstruct it independent of w_S exposes K; withholding that data is exactly the missing source-conditioned transfer. Merely calling the AND graph a joint commitment does not implement it.

(c) Share commitment openings between the source and native graph branches, rather than just the challenge. In the actual source construction the complete challenge-0 response already exposes ALL source bit/salt pairs, before w exists. Any native opening which is just a public deterministic translation of an individual such pair is obtainable without w. One still needs a global map from an actual source cycle into a native cycle, such that no public extraction bypass exists. Giving a map that is merely a verifier for a proposed pair does not compute the second response. Publishing the native cycles for every possible source cycle is not classical PPT in general. A hidden keyed translation would require the same secret evaluator forbidden by the handoff. This is a rejection of these explicit simple repairs, not a theorem against arbitrary source-specific correlated proof systems.

The exact candidate to pursue, only if it can be instantiated rather than postulated, would be a joint Build_KS(x,K) producing one shared first message and public helper T, together with a classical PPT translation:

    Z_K1 = Transfer(T,A_S,Z_S0,Z_S1,A_K,Z_K0)

for every original w and its source completion. Full-public security must show arbitrary QPT key recovery or accepted native forgery implies an original certificate or independent justified break; it is insufficient to prove that a party which VOLUNTEERS two source transcripts yields a certificate. A reduction must cover native public keys/messages, correlated auxiliary input, sibling capsules, malicious source-coin retention and setup. The special-soundness statement above is about actual transcripts only and neither requires nor licenses rewinding a quantum attacker. Even public original proof generation and extractability alone do not implement Transfer. Do not count this interface as a primitive assumption or a solution.

## 4. Disposition and handoff

The new source-completion operation is explicit but delivers a publicly checkable certificate, not the native capability. It leaves the cross-instance response transfer entirely missing. The direct OR construction, free global challenge repair, AND construction and per-commitment sharing repair were rejected statically; no larger fixture, coefficient/basis variant, packing, or generic verifier benchmark is warranted. No implementation or tests executed. No external literature, web, subagents or new source facts. No notification or ordinary PR comment.

Original source and endpoint requirements remain: all three grounds, actual claim relevance and maturity, R316 coverage correction, R225 slot-global versus activation-bound native message, one-honest N-of-N setup and pre-funding correctness/availability, no release authority and no changed network assumptions. Same-message native forgery requires its own argument. No deployment claim or generic NP WE claim.

Next candidate must avoid merely renaming Transfer as a publicly extractable proof: construct correlated native response completion AND its full-view simulator together. The source proof witness can change a challenge response to a fixed source commitment; it cannot by that fact alone change an independent native commitment response.
