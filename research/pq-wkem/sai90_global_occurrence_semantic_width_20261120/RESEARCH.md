## One candidate: witness-chosen Merkle root for global occurrence consistency

A fixed claimed `r` makes inconsistent repeated reads impossible except for a collision/second-preimage against the domain-separated Merkle commitment. The small checker verifies this positive property for its exact messages; it does not claim a computational security proof. This is a distinct repair of *unbound variable-occurrence substitution* at the public syntax layer, not a secret-release construction: **the attacker can choose an arbitrary r and witness**, so all full ORIGINAL source checks still must be cryptographically enforced inside release.

## Exact width/occurrence distinction (structural, not an ORIGINAL WKEM theorem)
Let a deterministic layered *read-once* BP have n freely chosen input bits, public transition functions delta_i(q,b) and at most W states per layer. If some accepting path exists, ordinary dynamic programming over reachable states constructs an actual accepted word in O(n W) time and O(W+nW) reconstruction space. If its acceptance condition were exactly the approved original-source relation, including full authenticated headers/contextual work/claim binding, this would construct a qualifying original certificate. Thus a polynomial-width explicit read-once BP is incompatible with a claimed *hard-to-find* TRUE witness distribution unless that source hardness claim is false or some premise (public transitions, exact acceptance, independently choosable bits) fails. This is not an unconditional lower bound for all compact cryptographic evaluators.

The escape route “use a width-small read-MANY BP” introduces a different error if input occurrences are unconstrained: one original variable x tested as x=0 and later x=1 has NO satisfying single assignment, but the syntactic per-occurrence path (0,1) accepts. More generally, deterministic read-once checking of `L_k={uv:|u|=|v|=k and u=v}` in that fixed order requires at least 2^k states after reading u: for u≠u', the common suffix v=u distinguishes their continuation. This is a counting argument for the stated plain automaton model, not a lower bound on hash-based FE or arbitrary succinct proof systems.

Merklizing one globally chosen bitstring repairs exactly this read-many occurrence-consistency issue at the data-verification level, with polynomial-sized per-occurrence hash proofs. It does NOT prevent algebraic mixing of independently obtainable secret labels from the complete public capsule (R289/R327), nor grant cryptographic access to the hidden state of SAI86; a public wrapper around a freely computable secret output is bypassable. The SAI89 core source-dependent update equation remains unconstructed.
