## One concrete restricted hash-only release algorithm
Take independent uniform a,b in {0,1}^kappa, set K=a XOR b and freeze native signature sigma on intended message M. With independent domain-separated hashes H_0,H_1,H_C,H_mask and context fixing claim, path, relation identity, native VK/message, Build emits
    v0=H_0(ctx,a), v1=H_1(ctx,b), CK=H_C(ctx,K), D=sigma XOR H_mask(ctx,K).
The *restricted* relation R_pair(C,(a',b')) requires H_0(ctx,a')=v0 and H_1(ctx,b')=v1, i.e., two complementary secret attestations. Public Open verifies both, sets K'=a' XOR b', checks CK, unseals D and validates native sigma. Build/Open are explicit classical PPT. Every valid pair recovers the SAME precommitted sigma, except hash collisions. No post-hoc source-verifier oracle.

**One-disclosure straight-line output identity:** if a is already publicly disclosed and a QPT adversary returns the exact correct K by any algorithm, then b=K XOR a is a classical preimage of v1. No quantum rewinding or query-trace request. This is a structural identity, NOT a complete reduction from QPT recovery to independent quantum one-wayness: an inverter needs to simulate all correlated v0,v1,CK,D, native VK, auxiliary data and siblings without knowing unknown b. Native accepted *different signature* also needs an EUF-CMA analysis. Brute-force CK inversion is independently possible with enough quantum queries.

## Failure against actual ORIGINAL source
ORIGINAL w includes real Syscoin child, actual claim/UTXO, parent Bitcoin AuxPoW, coinbase/Merkle direction, tags, height, anchored ancestors, windows and chain membership. None requires setup-chosen a,b. If future source bytes contain at most q independent uniform kappa-bit candidate fields, chance of both setup-chosen values appearing is at most q(q-1)*2^(-2kappa), under the stated independence model. Thus actual every-ORIGINAL-witness completeness is MISSING.

If a signer/miner deliberately inserts a,b, it already holds both pre-event and can extract K early. Candidate blocks or mempool messages reveal inserted preimages before authenticated inclusion; raw Open releases even for unanchored invalid source evidence. An honest API post-check R_ORIGINAL cannot prevent direct XOR and unmasking. Hashing pads with future WorkID prevents Build freezing SAME K for every distinct future unknown WorkID without new correlation.

**N-of-N obstruction scoped to this candidate:** If K is XOR of participant K_j and each K_j=a_j XOR b_j, any coalition possessing all complementary tokens required by Open can privately compute K before actual source publication. If an honest participant deletes or withholds a complementary token, ordinary public AuxPoW does not automatically manufacture it for every genuine future ORIGINAL witness. Requiring honest signers to attest both opposed branches is an online source signer/release authority not entailed by independent work. Two conflicting quorum signatures need not share every designated signer. This does not prove general hash-only WE impossible.
