## 1. Root selection and public input interface

Let V_x be the complete unchanged finite ORIGINAL predicate, with its witness length bound N, and let sigma be the fixed safe cancellation contribution. Use a canonical, indexed, domain-separated Merkle commitment root t = Commit(context,w) with unambiguous padding and bit positions. Open receives w, computes t and membership paths P_i for the bits. Define the relation CheckPath(t,i,b,P_i) in the usual way. Two opposite openings at a fixed t and i imply a hash collision by tracing the first divergent node with equal parent digest. This observation only concerns explicitly available paths; it is not a quantum extraction result.

The intended construction is a separate virtual garbling G_t of F_x(w) = sigma if V_x(w)=1, else bottom. For each input wire i, only L(t,i,b) corresponding to a membership opening should be obtainable; intermediate and output labels must also be t-specific. The builder must be independent of t. An adversary can choose arbitrarily many t, know all commitment coins for chosen witnesses and retain all Open randomness. Thus one-time privacy for a single honestly sampled root is insufficient; t must not be a trusted or hidden session identifier.

If such a root-bound transfer were implemented, a fixed-root opposite-bit mix would require inconsistent membership, and labels from different roots would not be interchangeable. That is the intended new consistency mechanism, not a proven property of a construction. In particular the root by itself is just a public commitment, and membership checks in honest code cannot enforce secret release.

## 2. Explicit row-translation candidate and preflight

For the finite deterministic checker, first consider standard independent input/output wire labels K_{i,b} in {0,1}^lambda and hash-pad garbled rows (a two-input gate g with output wire k and truth function f):

    E[g,a,b] = K[k,f(a,b)] XOR H(row,g,K[i,a],K[j,b]).

Use canonical context in all hash domains. Ignore row selection bits, which are irrelevant to the following obstruction. The target virtual row for root t uses derived labels

    L(t,i,b) = H(label,t,i,K[i,b])
    E_t[g,a,b] = L(t,k,f(a,b))
                  XOR H(row,t,g,L(t,i,a),L(t,j,b)).

This change is deliberately noninvertible: a root-specific label alone is not a public encoding of its base key. To evaluate, a holder of w needs the input transfer and virtual rows, while the builder must never publish all base keys. Try the following concrete generation strategies.

(a) Publish input base labels, require CheckPath before deriving L. This fails before implementing anything: the adversary derives both L(t,i,0) and L(t,i,1) for any t by skipping CheckPath. If virtual rows are also public, the fixed-root input consistency objective is gone, and the earlier independently selectable labels attack applies. Reject.

(b) Instead make L a publicly invertible root tweak, e.g. L = K XOR H(t,i). Even if an input transfer temporarily releases only one L for a valid membership path, a malicious opener can commit separately to witnesses containing each possible bit, recover both K for each i by undoing the public tweak, and import them into one arbitrary t. For any garbled internal wire that can be exported, the same argument removes root separation there. This is exactly why publicly invertible tweaks do not avoid R289. Reject without implementation.

(c) Keep the noninvertible hash definition of L. Can the virtual row be generated by publicly XOR-adjusting E with an independently computed correction? Exact correctness requires

    Delta_t[g,a,b] =
       K[k,f(a,b)] XOR H(label,t,k,K[k,f(a,b)])
       XOR H(row,g,K[i,a],K[j,b])
       XOR H(row,t,g,H(label,t,i,K[i,a]),H(label,t,j,K[j,b])).

Then E_t=E XOR Delta_t. Computing this expression by the builder for one root is possible. It requires hidden wire labels for the virtual row correction. The builder does not know future roots, and publishing base labels makes (a) applicable. The correction is not determined by the publicly exposed membership paths, root or base row ciphertext via the hash equations. In a fresh-output oracle calculation, the label-domain output at a previously unqueried secret output-key/root pair is independent of previously sampled base-row bytes and public paths. This is only a preflight of this explicit correction, NOT a general lower bound on all correlated public row generation; no adaptive QROM proof claimed. An explicit table across roots is not PPT. A seeded evaluator computing these corrections without giving out the base keys has not been constructed. Naming it a constrained PRF, or a public hash tree with secret seeds, does not supply the actual evaluator. With public seeds any adversary can do all derivations; with hidden seeds the required row calculation is missing. This candidate cannot proceed to a full-public simulator.

Notice that merely appending t to each hash call of the old garbling is not a repair: even a correct set of t-specific input labels cannot decrypt base rows that use unrelated keys. The necessary translation depends on internal wire secrets, not only on input commitments. It must be jointly generated with the input transfer and the fixed payload.

## 3. Evaluator-generated garbling alternative

Try avoiding virtual row translation by having Open generate a fresh garbling after selecting t. Garble F(w,s) = s if V_x(w) else bottom with s an explicit secret input, then import one label per bit of sigma from the fixed capsule. The evaluator chooses its garbling coins and therefore knows both possible labels for each secret input position. Under that ordinary garbling distribution, if the capsule provides the selected input label before checker evaluation, the evaluator reads sigma bit-by-bit by comparing the label with its two known choices. This bypasses the entire garbling, regardless of whether a later input membership test is imposed. If the imported object does not disclose which label is selected, then it cannot be an ordinary secret-input label in this garbling; actual oblivious transfer of a hidden label without a sender or trusted evaluator is required.

A repair must instead jointly generate the garbling and secret input label distribution so that Open cannot learn the hidden mapping or manufacture conflicting labels even with its complete coins and arbitrary other chosen roots. Public rerandomization of an existing circuit that preserves hidden label mappings is not obtained by the ordinary garbling algorithm. Noninvertible root derivation in section 2 addresses the direction of label conversion but fails to supply such rows. Thus neither evaluator-generated garbling with an ordinary imported label nor public invertible rerandomization is a candidate to scale.

## 4. Handoff

The specific missing equations for a next root-bound candidate are

    C <- Build(x,VK,M,sigma; rho)           // independent of t,w
    Rows_t <- PublicRows(C,t)
    Input_i <- Transfer(C,t,i,b,P_i)
    Eval(Rows_t,Input_1,...,Input_N)=sigma  // every ORIGINAL witness

where PublicRows and Transfer have actual serialized classical-PPT implementations, including hidden label generation and row translation, not secret-key calls. Any alternative construction should explain why the public output does not allow arbitrary root selection, base-label recovery, cross-root import, or recovery from evaluator-known randomness. Merkle binding alone is insufficient for arbitrary recovery extraction: the adversary need not submit two openings or use Transfer at all. A joint simulator must include the native VK/message, related capsules, source coins and arbitrary auxiliary input; same-message accepted native forgery is part of the failure event.
