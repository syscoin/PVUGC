## 1. Exact trial format

Let R_x(w) be the unchanged original relation, on n-bit bounded injective encodings of typed certificates; malformed encodings reject. Fixed public order pi permutes the encoding bits, or is identity. Context binds the same complete source assertion, native VK/message and capsule identification as required by the original target; the calculation compares independent capsule salts at a fixed underlying relation and order. Define Cyl(p) = {w : pi(w) starts with p}. A prefix may be empty. The proposed Cover(x,pi;rho) returns a list P of at most polynomially many prefixes. A sufficient correctness condition is that for every R_x(w)=1, some p in P satisfies w in Cyl(p). Initially allow P to cover invalid strings too, to avoid assuming exact rejection/acceptance classification and to test the raw cryptographic release.

Choose a public lambda-bit tree root r and fresh capsule salt a. Set node(empty)=r; for prefix p and b in {0,1}, node(pb)=H_node(a,|p|,b,node(p)). All encodings/domain labels are unambiguous. For each p in P, set

    tag(p) = H_tag(ctx,a,|p|,p,node(p))
    mask(p) = XOF_pad(ctx,a,|p|,p,node(p),ell)
    record(p) = (tag(p), S XOR mask(p)).

S is the actual precommitted ell-bit native capability, not a freely chosen alternate payout. Build returns (ctx,pi,a,r,records), optionally shuffled; it does not publish p or rho. Cover selection is independent of S conditional on the fixed public statement/context/order, and uses only classical PPT operations if the candidate meets its resource goal. Open computes the n+1 nodes along pi(w), looks for matching tags and XORs the appropriate record with its pad. A matching authentic record gives exactly S. The actual cryptographic opening uses the prefix only; a surrounding R_x(w) check cannot make the raw record inaccessible. A native verifier can select a valid recovered signature if necessary. No hash security assumption is required for correctness of actual records. The format is specified to screen a candidate, not a claimed complete Build: the generation of a polynomial source-only cover remains the missing operation.

The concrete negative-to-positive generator trial: let Q be a finite antichain of rejection prefixes whose cylinders are the invalid set. Insert Q into a binary trie, mark its terminal rejection nodes, and emit every missing-child prefix of a nonterminal trie node; if Q is empty emit the empty prefix, if Q contains the empty prefix emit nothing. The emitted cylinders partition the complement, since the first edge outside the rejection trie exists exactly for strings not in a rejected cylinder. At most O(n|Q|+1) nodes/records. Thus this is an explicit polynomial generation algorithm *given Q*, rather than a table of all positive certificates. To obtain Q from the original verifier, a proposed recursive procedure fixes bits in order and simplifies the residual verifier by constant propagation, emitting a reject cylinder when the residual output is identically the constant zero, skipping a known constant-one branch, and otherwise branching until all n bits are assigned. At fully fixed leaves the original verifier is evaluated. This is complete if finished but can take exponential time; impose a polynomial node budget and abort otherwise. No claim that actual source verification has a small such trie. An exact polynomial Q already makes finding an original certificate easy whenever one exists: emit an accepted prefix, append zeros, invert pi. The attempted repair is to use only easily identifiable rejection cylinders (Q a subset of rejection), so that the remaining cover can include invalid strings while still covering all originals. That relaxed case is screened without assuming efficient extraction from a prefix.

## 2. Independent-build nesting: no exact cover or entropy assumption

Fix (x,w,z) with R_x(w)=1. The proof conditions on the fixed public statement, auxiliary data and order, and, if hashes are idealized, on the shared oracle. It requires that the two source-only cover generations are independently randomized with the same conditional distribution. Target Build uses its own salt/root/coins, and the attacker runs a fresh copy of Cover/Build with its own coins and a dummy S'. This is an ordinary call to a public classical algorithm, not access to the target's coins. Its own prefix list is available by instrumenting the public Build code; no adversarial representation or quantum query log is requested. An actual implementation with explicit prefix generation, including the trie above, exposes this list to its caller. This argument does not assume ability to find a hidden address from an opaque symbolic token generator.

Let P_T be the target's hidden cover and P_A the attacker's independently generated cover. For the fixed original w, let L_T, L_A be the lengths of the longest prefix of pi(w) included in their respective lists; set L=-1 on no match. If both have a match and L_A >= L_T, the attacker's prefix q of length L_A extends the target prefix p of length L_T. This follows because both are prefixes of exactly the same ordered string; all its prefixes are totally ordered by containment. The attacker need not know w, L_A, L_T, or which q is on w.

Attack: for *every* q in P_A, compute the target's tree nodes, tags and pads for every prefix of q, using only the target's public root/salt/context. Look up matching records in the public target capsule and recover their masked values. On the above event this enumeration includes the actual p, so the candidate list includes the exact S. It uses O(n|P_A|) prefix evaluations with a tag index, plus the polynomial number of matching records; even without a tag index it is polynomial. No hash collision, inversion, signature forgery, oracle programming or source evidence is used. If candidates are ambiguous, returning a uniformly selected candidate loses at most a polynomial factor for exact-S recovery; the actual native verification interface can accept S, and an independently valid alternative native signature also violates the intended unauthorized-accepted-output property. The attack does not need a signature verifier to prove nonnegligible exact recovery.

Let c=Pr[L>=0] for this fixed w and conditional experiment. By independence, both matches occur with probability c^2. By exchange symmetry, conditioned on both matching, Pr[L_A >= L_T] is at least 1/2 (ties count as success). Thus

    Pr[actual S appears in polynomial candidate list] >= c^2/2.

If correctness is averaged over a shared ideal oracle, apply the conditional statement for each oracle and Jensen's inequality: E[c^2]/2 >= (E[c])^2/2. For overwhelming completeness this gives constant list-recovery probability and inverse-polynomial exact recovery, regardless of the number or entropy of original witnesses, prefix lengths, false-positive coverage, or whether the attacker knows which prefixes qualify. This is a classical attack, hence also a QPT one. It even works if the target and attacker's selected positive covers differ completely as lists. It is stronger than a short-prefix enumeration or an explicit-positive-cover argument.

For a hard-TRUE distribution in which original certificates remain hard given public x,z and efficiently sampleable context, one cannot justify the promised recovery-implies-certificate reduction for this candidate from independent hash/native security: the above attack merely runs public setup and public prefix derivation. If the reduction actually extracts an original certificate from these operations, this yields an algorithm in the assumed hard-TRUE experiment (provided the native/auxiliary setup is independently sampleable as stipulated). This is a conditional screening argument, not a claim that a particular real Bitcoin/Syscoin distribution has been proved hard. It does not assert that the recovery attack itself extracts or rules out all possible original certificates. The hard-TRUE requirement, unlike FALSE-only hiding, is essential here. If no source certificate exists, no completeness event is available to this proof.

## 3. Repair: per-capsule random order

The nesting attack uses a shared ordering of the entire original encoding. Independent random permutations pi_T,pi_A can produce incomparable partial assignments, so a mere comparison of prefix lengths no longer proves containment. Example: for the same w=00, prefix 0 in order (bit 1,bit 2) fixes bit 1, while prefix 0 in order (bit 2,bit 1) fixes bit 2. This is a real change to the attack invariant, not more fixtures or a larger hash. However the actual trial trie generator works for every public order and is callable with that order. Since the target must tell Open its order, the attacker invokes Cover(x,pi_T;rho_A) instead of drawing pi_A. For any generator whose conditional cover distribution can be sampled in this way, Section 2 applies verbatim, conditional on pi_T. The negative-cylinder trie repair, exact or relaxed, has precisely this interface. Random public order with independent cover coins does not help.

A genuinely different repair would require an order correlated with hidden generator state such that the conditional target-cover distribution cannot be regenerated from the public order, while Build still obtains complete coverage of original witnesses without knowing them. This is not supplied by simply choosing pi=Perm(H(seed)) and using independent trie generation, since the latter can still be rerun at the exposed pi. Nor does the proof above rule out a yet-unconstructed correlated sampler with secret-dependent address namespaces that lack public prefix transport. Such a sampler must provide a serialized algorithm, demonstrate original every-witness completeness, and jointly simulate all exposed order/cover/native correlations. The user does not need a canonical witness. An unspecified opaque token generator or independently encrypted fixed source subset is not this repair.

Independent masks/shares for several public orders are not a global consistency mechanism: if each component is individually recognizable/recoverable through its own public record lookup and independently rerunnable cover, the above attack can target each separately (repeating independent builds as needed). Requiring their concatenation or hashing the component outputs does not by itself establish that they came from the same original certificate. This is the previously rejected splice premise, not a reason to implement another split construction. A nonseparable joint mechanism needs its own actual source-dependent evaluation and security reduction.
