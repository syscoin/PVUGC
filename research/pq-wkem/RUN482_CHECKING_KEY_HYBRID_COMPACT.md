## Positive narrow lemma: correlated checking key is not itself a false-instance obstruction

Let classical PPT WE.Enc(x,M) satisfy QPT indistinguishability for exact ORIGINAL-false x, with arbitrary efficiently samplable correlated classical public auxiliary input. Let classical PPT Sig.KeyGen output (sk,vk), with QPT EUF-CMA security for classical signing-oracle queries (NMA suffices if there are no signatures). Honest setup publishes x, vk, ctx and C=WE.Enc(x,sk). Context must bind relation identity, UTXO/claim, branch, anchors/window and transaction sighash. Auxiliary graph signatures must be simulatable from vk and an allowed signing oracle, and the target forged message must not have been pre-signed. The real N-of-N adaptor/erasure transcript is NOT proved simulatable here.

Hybrid H0 is (vk=PK(sk), WE.Enc(x,sk)); H1 **keeps the same vk** and replaces only ciphertext plaintext with independently generated sk': (vk=PK(sk), WE.Enc(x,sk')). A QPT WE IND adversary generates both sk and sk', keeps vk and all efficiently generated side information, asks the false-instance WE challenger to encrypt one of these two chosen messages, and runs the native-forgery attacker once. The change in probability of fresh signature acceptance is at most Adv_WE^QPT. In H1 the ciphertext and its plaintext sk' are independent of actual sk conditional on vk and oracle-simulatable auxiliaries. A QPT EUF-CMA adversary receiving vk and a classical signing oracle can itself generate sk', WE.Enc(x,sk'), and all allowed aux; a fresh accepted signature breaks EUF-CMA. Therefore:

`Pr[false-instance fresh native forgery] <= Adv_WE^QPT + Adv_EUF-CMA^QPT`.

This is a straight-line classical-challenge/QPT-postprocessing hybrid, NOT a reduction from true-instance signatures to ORIGINAL witnesses. Requires false x in the language of the **exact ORIGINAL** relation, not merely computational soundness of an inner SNARG. Multiple independent false capsules can be hybridized with q*Adv_WE loss if their joint auxiliary inputs remain simulatable; do not include a true capsule releasing the SAME sk. Coherent signing-oracle queries, unavailable quantum advice, unsimulatable setup secrets/presignatures and keyless retained-builder coins are outside this claim.

## Definitional counterexample: false hiding plus all-witness correctness need not imply true-instance knowledge

Assume an efficiently computable one-way permutation f against arbitrary QPT (explicit conditional assumption; NOT derived from LWE). Let x=(b,y,ctx) and ORIGINAL witnesses w=(s,j), j in {0,1}, with R(x,w)=[b=1 and f(s)=y]. Because f is a permutation, every b=1 instance is TRUE and has two valid witnesses, while every b=0 instance is FALSE. For an ell-bit protected message M, define WE.Enc(x,M)=(1,M) when b=1, and (0,U_ell) with uniform fresh U_ell when b=0. WE.Dec on b=1 returns M regardless of w; on b=0 returns bottom. This satisfies **perfect false-instance message hiding**, including a fixed correlated public vk=PK(M), and perfect all-valid-witness SAME-message correctness. Standard WE has no requirement that an invalid witness fail on a true instance.

Set M=sk of a native signing scheme and publish vk. For x=(1,f(s),ctx), an attacker reads sk and signs the bound challenge without knowing s. If an arbitrary-QPT extractor, given the public transcript and accepted signature, returned ORIGINAL (s',j) with nonnegligible probability, a QPT inverter given y could generate fresh independent (sk,vk), produce the capsule and signature, invoke the extractor, and output s' satisfying f(s')=y. This contradicts the stated one-way permutation assumption. The straight-line argument does not handle uncomputable advice already containing s. The separation also embeds as an explicitly tagged branch alongside an NP-complete language (if WE for the other branch is given). Thus knowledge soundness cannot be obtained by renaming WE as local mixing or merely postulating false QPT hiding.

## Cross-branch composition diagnostic

Reusing one native sk for a TRUE capsule and a FALSE capsule permits signing the false branch after the true capsule discloses sk, even with different domain-separated sighashes. Domain separation rejects *replay* of a previous signature, not *fresh signing with recovered sk*. A distinct key per claim/branch removes this particular credential-reuse path (not all other attacks); actual Bitcoin timelocks and graph restrictions require separate proof. Under QPT signature security, the false hybrid applies only if no other published capsule/function reveals the target sk.
