## Explicit functional candidate

    I_q(z)=Π_{i=1}^n (1-[z_i(z_i-1)]^(q-1)),
    A_x(z)=I_q(z)*V_x(z).
Each power is computable by repeated squaring, so the *function CIRCUIT* for A is polynomial-size in n, log q, verifier circuit size. Fermat shows I=1 precisely for z∈{0,1}^n and zero on every off-Boolean field point. Hence A_x(z)∈{0,1} for all z, and A_x(z)=1 exactly when z is an ACTUAL accepted ORIGINAL witness (given an honestly specified verifier/canonical encoding). In particular, this repair eliminates earlier off-Boolean algebraic R(z)=1 probes from obtaining a release by function evaluation alone.

## Two exact breaks in attempted public representations
1. A compact plaintext arithmetic circuit for F visibly contains the setup-selected K. Even on false x, public code syntax exposes K, so a purported FALSE security proof from the function's values is invalid. Randomizing constants by ordinary public arithmetic does not supply an independent cryptographic concealment theorem.
2. An explicit canonical reduced coefficient representation belongs to the field-function ring B_q=F_q[z_1,...,z_n]/(z_i^q-z_i). It is q^n-dimensional, exponential in witness length. Importantly, even IF the representation hides K syntactically, it gives a universal *nonwitness* extractor. Since A(z) is Boolean-valued everywhere, A^2=A in B_q. Therefore
       F*A = (K*A+(1-A)*T)*A = K*A.
   If x is true, A≠0. From public coefficients of F and known V_x, expand A in the quotient, multiply F*A, choose any coefficient j with A_j≠0, and recover K=(F*A)_j/A_j. The attack is classical polynomial in the explicit q^n coefficient-array length. It does NOT require constructing any original satisfying witness and extends coordinatewise to a frozen native signature.
   This is an exact attack on the explicit-coefficient model, NOT a polynomial attack on a hypothetical succinct hidden circuit. One cannot describe the q^n representation as classical-PPT setup or extract a standard-model QPT theorem from this finite-field test.

## Why hash commitments are not the missing public evaluator
A hash/Merkle root of an F table does not supply F(w) to an arbitrary future witness; Open needs the value and authenticated branch. Publishing all values/branches reverts to a huge public table and the coefficient/projection attack if the full function can be reconstructed. Holding branches for future issue introduces a forbidden online secret releaser. Hash-circuit garbling with both input labels publicly derivable reintroduces label-closure attacks. A compact *non-inspectable publicly evaluable encoding* of F would be precisely the new hard cryptographic compiler needed; postulating one and calling it a hash implementation would be circular.
