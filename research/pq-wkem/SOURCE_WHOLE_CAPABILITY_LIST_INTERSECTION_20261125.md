## 1. Concrete trial

Let R_x(w) be the unchanged full ORIGINAL relation: the three independently sufficient OR grounds, actual source authentication, relevance, maturity and full claim binding. Let S be the fixed safe native cancellation capability. Context ctx binds the full statement and native message/VK, capsule ID and all required protocol data. Domain-separated H, KDF are hash based. Setup samples a private t of lambda bits and may publish h=H_trap(ctx,t) to bind it; t is merely an attempted setup-only seed and is NOT a qualifying witness or substituted puzzle.

Define z_t=H_list(ctx,tag_trap,t) and z_w=H_list(ctx,tag_original,canonical(w)), with output 2k bits, via a domain-separated XOF if needed. Split either z into k consecutive pairs (a_i,b_i). The even-parity encoding e(a,b)=(a,b,a xor b) has this property: two distinct codewords agree at exactly one of their three coordinates; equal codewords agree everywhere. For any selector v in {0,1,2}^k let L(z,v) be the k-bit string obtained by selecting coordinate v_i of the encoded pair i. A complete endpoint label is the serialization (ctx,v,L(z,v)).

Trial Build computes z_t, chooses a polynomial-size set A of selectors (permitted to depend on z_t, public statement and setup randomness), and publishes, for each v in A, the selector and one whole-capability ciphertext
    E_v = S xor KDF(ctx,v,L(z_t,v),|S|).
Erase t,z_t. Open first checks R_x(w), computes z_w, and tries decrypting each E_v using its corresponding complete endpoint label. The native VK/message provides the intended recognition of an acceptable capability; exact S recovery is the target, and an accepted different native signature needs separate treatment. No native signature was generated for this trial.

For unrestricted A={0,1,2}^k, there is always some matching selector for ANY z_w,z_t. Therefore idealized exact correctness for the matching entry does not require an identical source transcript. The price is 3^k ciphertexts, already non-PPT for k growing linearly with lambda. A polynomial sparse A is the attempted repair. Note that the parity code is used here for complete capability release, not for signing rows or bandwidth optimization.

## 2. Why the natural list compiler fails before implementation

For a fixed z_t and any fixed v, if z_w is fresh uniform, each selected coordinate of each encoded pair is a uniform bit, independently across pairs. Therefore Pr[L(z_w,v)=L(z_t,v)]=2^-k. In the domain-separated random oracle/XOF idealization this applies conditional on classical Build's view, for a fixed original witness whose H_list input has not been queried during Build. It also applies to selectors chosen adaptively from z_t and that view before the unseen original-domain output is evaluated. By the union bound, probability of any exact label match is at most |A| 2^-k. KDF collisions are not a completeness mechanism.

The stronger combinatorial statement for the unconditional code property is independent of hashes: fix any z_t and restrict z_w to differ in every pair. In each block, each of the three distinct alternatives agrees in exactly one different coordinate. All 3^k agreement-selector vectors occur, each with only one successful selector. Thus any A(z_t) guaranteeing equality for ALL z_w must contain every selector, even if Build chooses A adaptively from its own input. This is NOT a claim that actual source witnesses realize every digest vector. The fresh-digest bound above instead uses a single qualifying unseen witness in the stated idealization. Neither argument requires larger fixtures.

For k=O(log lambda), complete endpoint labels have only k unknown bits once v and ctx are public. On a FALSE instance a party can enumerate their 2^k possible strings for one published selector, derive all candidate capabilities, and check the native VK/message or test exact candidate recovery in the usual challenge game. Hiding the selector rather than publishing it does not repair this small-parameter variant: enumerating the combined 6^k choices is polynomial. This does not assert uniqueness of a valid native signature. The correct candidate is in the list; an accepted alternative is already an endpoint security problem. No native forgery, transaction or real source proof was produced.

There is an even more direct **simulation defect** in the proposed digest-only compiler. Once ctx and A are public, the endpoint calculation uses only z_w, not w, nor its authenticated intermediate state. Whenever a genuine unseen original digest is uniform conditional on Build's view as above, replacing it with a locally sampled uniform z produces exactly the same distribution of trial keys, even without R_x(w). This is an equality for the classical honest-algorithm distribution in the indicated fresh-oracle experiment, not a general QPT oracle theorem or a claim about SHA as a concrete hash. Therefore improving the combinatorial overlap probability of this digest-only scheme would improve the corresponding source-free trial probability identically. The checking step cannot fix it. The FALSE instance interpretation requires specifying its actual public view; one must not transfer completeness from TRUE to FALSE just by changing x. The explicit short-label enumeration works on FALSE independently of that transfer. On hard-TRUE with fresh original digest, the source-free sampling equality directly rules out the claimed security whenever overlap completeness is high.

## 3. Attempted repair and precise next gate

One might replace the parity encoding by a relation-specific list generator G_x that outputs complete, high-entropy labels from *authenticated semantic parts* of w, not from an independent digest. This is the only plausible repair within the list-intersection shape: the proof of intersection must use actual source semantics, not arbitrary-input coding. To see exactly what is required, allow Build to generate its own list B of at most poly(lambda,|x|) labels, and publish one independently domain-separated complete S ciphertext per entry. Open generates a polynomial list G_x(w,ctx) and tries matching labels against B (entry-specific KDF salt can be public). The needed conditions are simultaneously:
* for every qualifying original w, G_x(w,ctx) intersects B for essentially every honest setup tape;
* Build computes B before w is known, without enumerating original witnesses, retaining an issuer or assuming a release primitive;
* from the complete public capsule, aux, native context and related capsules, no arbitrary QPT recovery/accepted-forgery adversary can exploit a hit or other ciphertext correlation without an actual qualifying ORIGINAL certificate or an independent justified break.

The last condition cannot be replaced by “any party producing a label must know a witness”: the output is S or a valid native signature, not a volunteered label. R303's independent-hidden-label component does not establish these correlated conditions. In particular, replacing labels with a hash of a whole authenticated path is not itself a repair. Build must demonstrate its list generation and overlap for *all three* grounds, including a previously unknown alternative history and missing/invalid burn evidence. A common publicly known source anchor is not a hidden label; an unknown future path is not something Build can simply enumerate. No auxiliary trap preimage may count as original evidence.
