## Candidate and exact constructive subproblem
Earlier R167 obtains consistency of repeated witness reads by carrying every previous live bit in a secret-state graph, leading to exponential states in its fixed read order. Instead let the FUTURE prover commit to its entire ORIGINAL witness w as a collision-resistant, domain-separated binary Merkle root rho, then supply path proofs for each local read of every source verifier. The public verifier fixes the SAME rho for the entire computation; each read (index i, value b) must have an authenticated path to rho. Under hash collision resistance, two distinct bits for the SAME index and root cannot both have accepted paths, except by an actual hash collision. This can enforce repeated-input consistency with O(lambda + log n) state and O(log n) work per read rather than enumerating all n-bit histories.

Crucial separation: this is a public consistency check, not concealed capability release. The holder chooses rho AFTER Build. Build has already frozen SIGMA and cannot precompute K xor H(rho) for unknown future valid roots. A public verifier gate attached to a fixed encrypted SIGMA remains bypassable; root commitment by itself does not make a secret correlation. The proposed candidate must generate a *source-conditioned terminal hash value independent of rho* or a polynomial Build that distributes K cryptographically for all accepted rho without letting invalid rho recover it. This is the EXACT new missing equation, not a success assumed from Merkle verification.
