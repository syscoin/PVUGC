## Named attempted gate: affine pair shares
Take F_p and t(P) mapping a fully authenticated parent/child evidence record P to a field value. Setup chooses K (a secret share or precommitted cancellation capability) and a random a, defines f(t)=K+a*t mod p. Hypothetical source records P_A,P_B yield s_A=f(t_A), s_B=f(t_B); for distinct t values a public interpolator obtains:
K = (t_B*s_A-t_A*s_B)/(t_B-t_A) mod p.
This is exact for EVERY distinct pair and naturally has a common intercept. For a fixed baseline P_A a watcher needs only the second share, but cannot derive it from arbitrary fabricated P_B. Two parent-work certificates for the same semantic child still fail the ORIGINAL fork relation independently of distinct t-values.

### Affine all-pairs lemma
If three or more distinct points (t_i,s_i) have the SAME pairwise interpolated constant K and some t_i != 0, then all points lie on a single affine line: cross multiplying each pair gives t_j(s_i-K)=t_i(s_j-K); define a=(s_i-K)/t_i and obtain s_j=K+a*t_j for all j. Thus this particular pair-linear family requires coherent shares across all future source observations; independent witness-specific pad derivations do not automatically satisfy its every-pair same-key condition. This lemma is only about the affine carrier, not an impossibility theorem for hash-only release.

### Failure and repair attempt
- Publishing f's coefficients instantly reveals K. Even publishing a publicly callable Eval(t)=f(t) without coefficients lets anyone query two arbitrary field points and interpolate K without any qualified source.
- Defining t=SHA256(parent_header||canonical_tag||context) does not repair this. A fabricated unmined header has a public hash too. A separate honest Open() could reject it but a raw evaluator remains usable.
- Encrypting/masking the raw evaluator using H(parent) yields another public transform for fake parent bytes. Requiring only a PoW numeric target on the field point lets the adversary choose target-compliant points lacking real preimages. Actual BTC best-chain/admission, AuxPoW and Syscoin ancestry are not enforced by such arithmetic.
- Hash commitments to f(t) or a Merkle root for finitely many precomputed points do not supply unknown future shares from legitimate future source records. Prepublishing shares for all 256-bit inputs needs an exponential table, not PPT Build.
- Making Eval a publicly readable program containing hidden K or a secret polynomial but checking source before returning a share merely moves the same secret into inspectable code. Assuming a secure obfuscator, TEE, online issuer, or key-holding source signer would change the model and is not an instantiated hash-only repair.
- A public ZK/STARK proof of source validity authenticates evidence, but does not make an independently callable private evaluator with a hardcoded secret unextractable. A public commitment/root is not source-to-secret opening.
The exact remaining missing equation is a classical-polynomial Build and public EvalSource(C,P) that releases a coherent f(t(P)) for EVERY authenticated, relevant original source P, but cannot be called successfully on fabricated/arbitrary P, including by an arbitrary QPT adversary with complete capsule, native VK, sibling capsules and quantum hash access.
