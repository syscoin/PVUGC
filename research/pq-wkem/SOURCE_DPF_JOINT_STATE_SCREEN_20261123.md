## Candidate selection before implementation

The missing operation remains a classical-PPT serialized Build_inc(x_W,sigma_cancel) and public Open_inc(C,w) yielding the SAME fixed safe native cancellation capability for every qualifying ORIGINAL certificate. R323's exponentially enumerated per-assignment roots stop label splicing by independent assignment domains, but cannot be materialized in PPT. This pass considered a different mathematical mechanism: replace independent assignment domains with a pair of synchronized hash-PRG seed walks whose *differences* represent accepting paths. Function secret sharing (FSS), especially a distributed point function (DPF), can compact an isolated accepting path, with all other subtrees exactly canceled by common seeds. Unlike public both-label garbling, a single evaluation is prefix-consistent by construction, and wrong branches have a zero difference; intermediate labels are not independently chosen from a pair of circuit-wire labels. The proposed release would put both walks in the public capsule, with a common fixed payload, and use the complete canonical ORIGINAL certificate as the path. A compact representation of all accepting paths would be needed, not merely a DPF for one builder-known point. This is a candidate repair, not a claim that ordinary FSS implements a source verifier.

Preflight checks the FULL joint public distribution, rather than treating each share as independently hidden. It exposes an exact failure even before considering the compactness of an arbitrary SHA/AuxPoW verification language.

## Explicit synchronization and joint-state recovery

Let the hash-based length-expanding generator produce, from each seed s, child seeds u^0,u^1 and control bits v^0,v^1. At prefix p, party i has (s_i,t_i). The public correction words at level j are a seed word c and two control bits d^0,d^1. The child transition is

    s_i' = u_i^b XOR (t_i * c)
    t_i' = v_i^b XOR (t_i * d^b).

Here multiplication by a bit means zero or the given bitstring. Suppose the hidden selected path bit is a and the two current controls differ (t_0 XOR t_1 = 1). Set

    c = u_0^(1-a) XOR u_1^(1-a)
    d^b = v_0^b XOR v_1^b XOR [b=a].

Then at the off-path child b=1-a the seeds coincide and the controls coincide. At the selected child b=a the controls differ. An already synchronized pair stays synchronized on BOTH children because their generator inputs, controls and correction words coincide. Initialization uses t_0=0,t_1=1. Induction gives one live unequal-control prefix per depth and identical states throughout all other subtrees. At the final level, an appropriate correction value e in a binary-string additive group sets the XOR of terminal share outputs to a chosen payload M on the selected path: for terminal output generator J(s), set e=M XOR J(s_0) XOR J(s_1) at the live leaf, with the share output J(s_i) XOR t_i*e. The off-path identical pairs yield zero. This is the algebraic point-function correctness mechanism; it does not assume any lattice or discrete-log primitive.

A full-public adversary holding both root states and the common correction words evaluates both child transitions, compares t_0' XOR t_1' and follows the unique branch where it equals one. Repeating recovers the selected path in O(m) generator calls up to a constant factor, for an m-bit path. At the end it evaluates the terminal correction to recover M. There is no need to invert SHA, run an exponential search, obtain a source witness from the network, use coherent queries, or splice arbitrary circuit labels. It is the standard joint-state disclosure of the two-key construction, a classical deterministic attack on the proposed use of both keys as public capsule. The ordinary security of ONE FSS key is irrelevant. If the path encodes a builder-known ORIGINAL witness, extracting it is not a hash break; it may meet a bare witness-extraction implication but it destroys the intended hard-TRUE withholding of unavailable evidence. Build in the actual problem cannot rely on knowing such a witness. If the path instead encodes a public digest/verification verdict, the disclosed path is not an ORIGINAL certificate at all and terminal recovery bypasses the source condition. Do not conflate these cases.

Publishing both keys for each independently represented accepting path does not repair joint disclosure. Nor does a single point encode all possible authentic competing BTC histories, finite burn refutations, and qualified Syscoin history/tag faults. Different admissible ORIGINAL certificates need not share a preimage, and a known-path DPF builder has no description of future certificate bytes. This is separate from the R323 exponential full-assignment construction.

## Attempted repair: blinded coalescence rather than ordinary label splicing

The potentially useful feature is prefix-consistent synchronized evaluation, not a new algebraic coefficient basis. To keep it without exposing the live prefix, the next candidate is per-side encoding B_i of the seed/control state. Require a public transition T_i on encoded states, with correction words c_j, satisfying, for each state reached on either path,

    T_i(B_i(z),b,c_j) = B_i(F_i(z,b,c_j)),

and a public terminal evaluator E_i. Off-path paired terminal outputs must cancel exactly while the selected ORIGINAL path yields the fixed M. The full-public simulation needs to hide which child pair remains live without relying on single-key secrecy. Merely relabeling states by public invertible masks is a conjugacy: the adversary inverts B_i, compares the original controls and repeats the exact path recovery. Public commitment to the live state is likewise not a secret evaluator. Hiding a control bit while leaving a public synchronized seed comparison can also disclose the path whenever the live seeds differ; ordinary DPF does not promise hiding that comparison. The control-bit attack above is exact and does not depend on seed inequality.

For B_i(z)=H(i||z), simply using a newly domain-separated hash expansion from B_i(z) does NOT implement the transition equation: the required H(i||F_i(z,b,c_j)) is a different oracle input, not the output of H applied to B_i(z). In an ideal independent random-oracle model, absent a programmed relation or input coincidence, those outputs are independent; preimage/collision security of concrete SHA does not imply such an equivariance. Giving the evaluator a secret decoder, or the builder an ideal secret transition oracle, leaves the mandated public classical-PPT Open unimplemented. Giving a separate translation row per reachable state reintroduces the source-domain materialization problem. A new compact noninvertible encoding with publicly computable equivariant transitions and correct *joint* cancellation is the missing step for this family. No impossibility theorem for all FSS, nonlinear encodings, obfuscation, or concrete hash constructions follows.

Even a successful joint-state repair would still need a source-language compiler generated from x_W alone, without known future w, that represents all accepted ORIGINAL certificates and whose arbitrary public recovery supplies an actual authenticated certificate or an independent QPT break. It cannot be a DPF over a source digest, a bare verifier output, or a chosen proof transcript. Security must include related capsule and native checking-key/message auxiliary correlations, malicious setup and erasure, FALSE and hard-TRUE cases, plus exact safe cancellation/slot binding. DPF correctness does not address any of these.

## Disposition

REJECT the ordinary two-public-key variant before coding. The joint-key attack applies to the proposed mathematical change unchanged; per anti-spinning selection there is no reason to implement larger point fixtures, more hash placements, coefficient variants, or source-pad tests. This pass is a derivation and repair preflight only; no checker was executed and no QPT experiment or practical original-source Build/Open was produced. Preserve the exact full-public path recovery and the missing equivariant transition as selection constraints, not as a user-facing advance. The research direction must supply a genuinely new mechanism with joint simulation; do not spend another run hiding one share marginally or merely reencoding the control bit.
