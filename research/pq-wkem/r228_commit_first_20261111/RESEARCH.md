# R228: Commit-first hash binding for a fixed-txid activation slot

STATUS: Conditional endpoint design only. This is NOT a source-conditioned hash witness-KEM, a Bitcoin/Syscoin consensus implementation, a native PQ endpoint or a QPT security proof. It deliberately limits the notary to activating a claim selected BEFORE the N-of-N setup; the general later-arbitrary-claim problem and challenge key release remain UNSOLVED. No PR progress comment warranted.

PROBLEM: R225 showed that different Bitcoin witness variants of one fixed nonwitness activation transaction B have the SAME txid and native cancellation outpoint U. A native cancellation signature on M(U) remains valid on each history. A mere off-chain wtxid capsule commitment does not bind the native signature to a witness-selected claim.

RESTRICTED CONSTRUCTION:
(1) Before funding/preauthorization, choose exactly ONE canonical, fully specified source claim A0 for this slot. Every safety-relevant burn ID, amount, recipient, source-root/claim-prefix policy, scope, protocol version and slot is part of A0. An honest N-of-N contributor checks the exact A0 bytes, rather than only a notary-supplied hash, then independently samples a 256-bit salt s.
(2) Define P0 = canonical_encode("ACT-BOUND-v1", slot, s, A0) and d = SHA256(P0). Freeze d in the fixed nonwitness activation transaction graph, with the relevant script input committed to this exact d.
(3) The actual activation INPUT path must enforce SHA256(P) == d using a fixed Bitcoin-style hash equality, plus the one-notary activation signature. No path bypassing this check may be accepted; simply storing d in an output script is insufficient.
(4) The off-chain source/light-client verifier MUST parse the claim exclusively from that SAME canonical SHA256-checked P in the Bitcoin-authenticated activation witness. Ignore or reject unbound side fields attempting to redefine the source claim. Its separate acceptance checks still authenticate the wtxid, actual headers/coinbase, burn/root, work and tag histories and relevance. An unmined claim does not satisfy the ORIGINAL relation.
This is a small hash equality, NOT an on-Bitcoin original NP circuit, dispute VM or new opcode. The desired native no-EC-key-path/PQ script endpoint remains hypothetical.

PRECISE BINDING LEMMA: Fix B and d. Define Admit(B,W) to include mandatory script-path checking of SHA256(P)=d AND exact off-chain parsing of this P into the only assertion A(W). If two valid admitted witnesses W0,W1 have A(W0) != A(W1), injective canonical serialization implies P0 != P1 and script validity implies SHA256(P0)=d=SHA256(P1). The adversary's TWO classical outputs thus constitute a verifiable SHA256 collision, even if the adversary is QPT. This is a straight-line reduction for semantic binding, not a WITNESS->KEY reduction. An unchecked alternate script path or unbound secondary claim field defeats the premise.

PQ BOUNDARY: Generic quantum SHA256 COLLISION search is roughly 2^85 work, NOT automatically a 128-bit claim. In the stronger fresh-salt fixed-target experiment, P0 is committed to/checked by an honest contributor BEFORE an independent salt s fixes d, and an attacker afterward must find distinct P1 matching the fixed d. Generic quantum target-search work is on the order of 2^128; the QROM precomputation/advice/timing experiment would need separate proof, and real SHA256 is not proved to match it. If a malicious notary chooses both claims opportunistically after knowing all commitments, do not claim stronger than generic collision resistance. One-honest-N-of-N ceremony and pre-funding data availability are indispensable.

WHAT THIS DOES NOT SOLVE: Two valid witness variants using the SAME committed A0 can still have distinct wtxids, same txid and portable cancellation authorization. This method prevents cross-CLAIM ambiguity, not cross-HISTORY portability; the design still requires an explicit slot-global veto policy and stringent fork relevance/admission, or a genuinely activation-specific native commitment. The fixed A0 restriction is not compatible with arbitrary future notary-selected claims. One can precommit a finite set with separate independently bound slots only if the actual graph supports it, which is not assumed here.

Critically, P0 becomes PUBLIC upon activation and satisfies the SHA equality even without an authenticated BTC/SYS/PoB/tag challenge. It is NOT a release secret; no honest evaluator condition is cryptographically enforced on the cancellation signature by this equality. The ORIGINAL false-instance/hard-TRUE Build/Open operation is completely uninstantiated:
  Build_hash(R_cancel, x_W, native_cancel_signature) -> capsule
  Open_hash(capsule, ANY qualified ORIGINAL challenge witness) -> SAME signature.
Neither source-native input transfer, joint-public QPT recovery-to-original-witness extraction nor malicious N-of-N setup completeness follows from this lemma.
