## Explicit source-chameleon primitive and straight-line reduction

Let enc be a canonical injective length-delimited byte encoding, ctx a fixed complete claim/context encoding including capsule id, and H a domain-separated collision-resistant hash with lambda-bit output. Let message m and auxiliary bytes r have bounded canonical lengths. Define the public evaluation F_x on these two disjoint input types:

    F_x(N,m,r) = H(enc("normal",ctx,m,r))
    F_x(P,m,w,t) = t   if |t|=lambda and R(x_W,w)=1
                 = H(enc("failed-program",ctx,m,w,t)) otherwise.

Reject malformed encodings outside the input type; the second hash branch may equivalently return failure (here it is included to make explicit the total function on typed inputs). No secret key, no trapdoor retained by miners. All relation checking is classical off-chain.

For any first normal opening (N,m,r) with digest t, every original qualifying certificate gives the distinct opening (P,m',w,t), for any allowed m'. Equality is exact, independent of the particular w. Conversely, any classical output pair of distinct canonical inputs with equal digest either includes a successful P input, yielding its actual w directly, or is a collision in H on distinct encoded strings. This is a deterministic case distinction on the output of any QPT adversary, not rewinding or extraction from a query log. It holds in the concrete hash model under QPT collision resistance of the base domain for the latter case, with no QROM programming. It also holds for arbitrary auxiliary input: the reduction passes through the input and returns the indicated original witness or actual collision. To infer a negligible probability of the latter from collision resistance one must use an admissible auxiliary distribution (a party already given a base collision is outside ordinary CR); this is not a multi-capsule native security theorem. A successful P branch necessarily exposes w in the classical collision pair. An adversary outputting only the digest t is NOT thereby an adversary outputting a collision or a witness.

This primitive is deliberately public and programmable by a genuine source witness. It is a hash-only way to transfer a *proof of hash equality* across different messages, not a trapdoor preimage generator for the normal branch. The distinction is essential for the next composition.

## Serialized adaptor candidate and exact failure

Let (vk,sk) be a native signing key generated before funding; M is the exact native cancellation message. Temporarily grant the native endpoint assumptions and that the signing API can sign a lambda-bit digest as its message. (If it cannot, use the ordinary native API with a canonical byte encoding; the equality argument is unchanged.) Select an unrelated normal message m0, sample r, and compute t=F_x(N,m0,r). Produce native tau=Sign(sk,t). The serialized adaptor capsule is (ctx,x_W,vk,m0,r,t,tau), with the public adaptor algorithm:

    Adapt(C,w,m1):
        return (tau,P,m1,w,t)
    VerifyAdapt(vk,m1,tau,opening):
        compute u=F_x(opening) with the opening's m equal to m1
        verify native Verify(vk,u,tau).

For every original w, Adapt produces a valid signature in this *modified* verifier on any allowed m1, without any secret evaluator. For different message m1 from m0, an arbitrary successful classical adapted-signature output either supplies a genuine qualifying P input, yields a collision with the original normal opening if u=t and the alternate input is not a successful P input, or verifies a signature on a new native message u != t. The latter is a conventional new-message forgery event in a model with only the original t signed; extend the signed-message set for sibling capsules. No claim of strong unforgeability on the same message or full-public proof is made. This case distinction shows precisely what the genuine source certificate achieves in this construction: it authorizes a change in the *off-chain message-to-digest mapping*.

Attempt the actual native Open_inc by using m1 equal to the safe cancel transaction. Bitcoin's required verification is Verify(vk,M,tau), not VerifyAdapt. There are only two choices:
- If t equals the actual native message M, tau is already the native capability in the capsule. The adversary outputs tau without a collision, source certificate or native forgery. Even making the P opening mandatory in the local adaptation program cannot affect that.
- If t differs from M, the adapted object still has signature tau on t, not on M. If it happens to verify for M, it was already a publicly available verifying byte string before Adapt. If it does not, Adapt does not change the bytes. Correctness on the frozen native message is absent, regardless of the source collision proof.

This is independent of whether a public wrapper regards m0 as benign and m1 as cancel. If some native sighash choice makes both transactions share the same native message, the first case applies (and any native endpoint reuse must be explicitly scoped). If they do not, the second applies. No new source or Bitcoin deployment fact is asserted. Replacing native verification with F_x would require the source verifier/certificate on chain or a new endpoint, both disallowed. This is not an R225 correction; it is the separate distinction between changing a programmable wrapper's message and changing the actual signed native message.

## Attempted collision-to-opening repair

Avoid publishing tau. Instead choose a uniform lambda-bit secret k, t=H(enc("normal",ctx,m0,k)), and E=sigma_cancel XOR KDF(ctx,k,len(sigma_cancel)). Serialize (ctx,x_W,vk,M,m0,t,E). The normal opening is withheld. For every actual w, the opener can compute the exact alternate opening P,m1,w,t without knowing k. Try to use the existence of that collision to recover the normal opening, then decrypt E. This would preserve the ordinary native signature endpoint if it worked.

The concrete F_x does NOT require the programmable opening to know or depend on the normal opening. In particular Adapt's programmable branch can be generated using only the public target t and w, even if the normal opening is unavailable. Thus the opening algorithm that obtains this alternate opening has no extra secret-dependent input beyond t,E. A collision is only a collision *pair* when the normal opening is also known. It is invalid to infer k from possession of a P opening alone by invoking collision resistance or special soundness. If k is published to enable the pair, E can be decrypted immediately by anyone. If it stays hidden, the exact required repair is a collision-to-normal-opening algorithm that uses w and t to recover k or the same native capability without changing R.

A more explicit functional repair is to add a public recovery descriptor D that binds the P opening to the normal opening by demanding

    Recover(D,t,P,m1,w,t) = k,

for all accepted original certificates, with arbitrary public callers and no private evaluator. Setting Recover to a hash of the P opening does not implement this equality: w can vary, while k and t are fixed; a witness-independent hash of t is public. Adding k as a field of the P opening just makes creating the opening require the very secret sought. These are rejected algebraically without another independent-pad/seed-normalization fixture. A public program that verifies R and then reads k from embedded ordinary data cannot be secured by the verifier check. Merely giving a name to a witness-extracting chameleon collision primitive with the recovery equation is also not an independent hash assumption.

One may formalize the gap without a random-oracle heuristic: suppose the normal-opening hash domain and KDF are independent of the original certificate distribution, and grant any hard-TRUE fixed original certificate w to the repair's opener. Its computation of the P opening can be reproduced by any inverter given that same w as auxiliary input. Therefore the P-opening subroutine itself supplies no advantage over an inversion algorithm which already has w,t,E. No reduction from arbitrary plaintext recovery to base-hash inversion is claimed here (the public masked plaintext and native VK/message might correlate with the key); the statement is an exact public-computation identity, not a full-public hiding theorem. To exploit actual source correlations, D must be generated jointly with the original relation and secret so that an original certificate permits this additional operation; no such D/compiler or simulator is implemented. Unlike the preceding independent secret-cell commitment exchange, here genuine witness-triggered collisions ARE publicly achievable for all w, but they provide no native message/key transfer. Increasing the number of collisions or hash length cannot repair the transfer identity.
