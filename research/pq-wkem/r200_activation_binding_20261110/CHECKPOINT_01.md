# R200 intermediate hypothesis — witness-only activation and release identity

This note is an intermediate hypothesis, not completion or a cryptographic advance.

A preauthorized N-of-N cancel signature spends a fixed parent txid outpoint. A later one-notary withdrawal can place a different assertion in SegWit witness bytes while leaving that txid fixed, but its wtxid and BIP141 witness commitment change. Thus a capsule bound only to parent txid does NOT identify the actual on-chain assertion. If Build occurs before the assertion is chosen, it needs an activation-universal ORIGINAL challenge relation over authenticated mined witness assertions, or must already bind a restricted fixed assertion/template. Merely deriving a pad from the public wtxid cannot conceal a fixed signature. A source witness must authenticate Bitcoin witness-commitment inclusion, validate the notary authorization, decode the actual assertion, then verify the ORIGINAL BTC-work/PoB/SYS-tag fault against that assertion; BIP141 inclusion does not validate the claim itself.

Planned bounded checker: serialize two synthetic SegWit assertions with identical stripped transaction bytes; compare txid/wtxid, recompute BIP141 witness root/coinbase commitment, cross-test excluded witness variant, show fixed cancel outpoint, and test a hash-pad attempt against distinct activations. No mined block, real signature, consensus validation, QPT attack, or Build/Open gate is claimed.

Exact missing result: classical PPT hash-only public Build/Open with every ORIGINAL challenge for every permitted activation recovering the same pre-signed safe cancel capability, and full-public QPT reduction. Separate fake or future-chain evidence cannot substitute for valid activation.
