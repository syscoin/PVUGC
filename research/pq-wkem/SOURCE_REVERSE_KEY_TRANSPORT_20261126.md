Exact missing operation: build a serialized hash-only public capsule before the original future challenge certificate exists, such that a full qualifying certificate opens the fixed native cancellation contribution S. The three original OR grounds and full authentication, relevance, depth/work and context rules remain R(x,w). No common original witness, online service or source coin retention is assumed.

Instead of trying to traverse a forward evaluator from publicly available per-bit labels, try reverse transport starting at a secret for ONE COMPLETE source certificate, with a globally fixed root secret. The mathematical change is to encrypt complementary key shares under each other, allowing one child key to recover its parent, rather than combine accepting fragments of independent witness evaluations. ## 1. Reverse transport candidate, including the cyclic public correlations

For a finite rooted binary tree T fixed independently of hidden keys, sample each leaf key independently uniformly in {0,1}^lambda; define each internal k_v = k_v0 XOR k_v1. The root key is uniform. It suffices that every node has at least one descendant leaf. These keys are not asserted to be mutually independent: the linear relations are intentional.

At each internal node publish two directional rows with unambiguous context, node and direction domains:

    A_v,0 = k_v1 XOR H("reverse-row",ctx,v,0,k_v0)
    A_v,1 = k_v0 XOR H("reverse-row",ctx,v,1,k_v1).

Publish D = S XOR HashStream("reverse-root",ctx,k_root).

Given one exact child key k_vb and its public row, recover its sibling by XOR and hence recover k_v. A full leaf key suffices to recover the fixed root and S. No sibling key is transmitted in the clear. Different leaves open the same S without requiring equal source-dependent leaf keys. This is a serialized transport on the chosen finite tree, not a release mechanism: no original certificate has yet been converted to its leaf key.

Why not publish raw complementary shares? If both sides of a node contain some qualifying certificate, a public dictionary of raw complementary shares for both sides contains both k_v0 and k_v1. Their XOR gives the parent with no certificate. Public shares on the ancestors then lift that key to the root. Cross-encryption is an explicit repair to that disclosure; knowing one exact child legitimately reveals both siblings, but recovering one exact child from the public rows alone is not presumed possible.

The cyclic two-row encryption does require a joint argument, not a generic independent-key encryption claim. In the following deliberately restricted experiment, T is polynomial size; context, S and auxiliary data may be correlated with each other, but are independent of all sampled transport keys and of the reserved oracle domains before publication. No leaf key, source seed or other key-dependent hint is published. Use ideal separated random-oracle domains; for each v,b, reserve one lambda-bit random-oracle output; split D into independent output-block domains if needed. Draw all row ciphertexts and D uniformly first, independently of the hidden leaf keys. Program each directional input at its actual child key to the drawn ciphertext XOR sibling key, and each root block input at k_root to its drawn ciphertext XOR the corresponding S block. All these addresses are distinct by domain/node/direction/block, irrespective of actual key collisions. Conditional on all keys and S the programmed outputs are mutually independent uniform, so this is exactly the joint real generation in this restricted experiment, including both cyclic rows. No circular-security assumption is silently imported.

Let m be the number of programmed addresses (2 per internal node plus root blocks), and q the number of coherent oracle queries. In the unprogrammed experiment the complete public view is independent of transport keys, so expected query weight at the union of programmed points is <= m/2^lambda for each baseline query, by each node key's uniform marginal. Replacing queries one by one using the unprogrammed prefix and programmed suffix, and applying Cauchy-Schwarz, bounds mean final state-vector distance by 2q sqrt(m/2^lambda). The same upper bound on distinguishing advantage (or 1 if larger) follows from the pure-state trace-distance bound, averaging over coupled classical randomness and purifying adversary operations. This remains true with nonuniform advice independent of the sampled keys. No extraction from an adversary's representation or query log is assumed in that experiment.

Important limits: a published independent root checking value derived from transport keys, exposed source-dependent leaf keys, correlated auxiliary inputs, or related capsules sharing those keys is NOT covered. S may be an independently given precommitted native contribution, but no real native signature recovery or forgery reduction is supplied. The experiment addresses whether the encrypted complementary rows immediately reveal the root through their cyclic correlation, not whether the actual source admits this interface. The tree transport deliberately gives no secrecy for root after ANY exact leaf is disclosed; that is desired only if the leaf is cryptographically obtainable from an ORIGINAL qualifying certificate. It is not safe to issue even one leaf key for invalid or fabricated evidence.

## 2. Attempted original-source instantiation

Consider full fixed-length canonical encodings of the bounded R(x,w); variable lengths need a checked injective length encoding and padding. Let one leaf correspond to each full encoding, and independently random leaf keys as above. This uses one leaf for each potential certificate, not a shared witness-specific native cancellation transaction. Build can in principle test R for each encoding and publish a dense row for each w:

    B_w = k_w XOR H("source-leaf",ctx,enc(w))  if R(x,w)=1;
    B_w = uniform lambda-bit string           otherwise.

For each exact encoding the evaluator can obtain its row, derive the candidate leaf key, traverse the reverse rows and derive a candidate S. A valid w gives exact S by construction. An invalid w does not get its true leaf key from the row by the intended construction, except accidental equality or attacks; this is a correctness statement for valid inputs, NOT a full-public security theorem for the dense scheme. In particular the independent-hidden-key proof in Section 1 cannot simply be reapplied to the published B_w rows, especially with malicious source-coin retention or oracle-dependent source authentication. A full reduction would need arbitrary unauthorized recovery to imply a qualifying original witness or independent justified break, including use of the wrong-key paths and the native checking view.

The dense construction is not classical PPT: a length L encoding domain needs 2^L leaf rows, and a full binary transport tree needs 2^L-1 internal nodes. Indexing by a hash of the whole certificate does not change the required coverage. For an arbitrary future qualifying original certificate Build cannot know which encodings to prepopulate without enumeration; using a source leaf mask only for a setup-selected valid history violates every-witness completeness. This applies even if transport were ideal. There is no claim that all encodings are admissible, that every instance has multiple witnesses, or that source validity itself requires exponential verification.

Attempt A: generate the whole tree from a short secret seed with a PRG. Build remains compact internally, but Open needs the particular public complementary ciphertext rows on its path. Revealing the seed yields the target root directly. Revealing a public algorithm for the directional rows must compute both child keys' correlation without exposing them; simply specifying the seed as a hidden constant in public code does not implement such an algorithm. A full source-conditioned row generator would require its own joint simulator, and a public evaluator returning correct k_w from an unknown setup seed when R accepts is the missing source release itself. A PRG proof for a seed hidden from the adversary does not prove public execution of code containing that seed.

Attempt B: shrink T to polynomial size by merging encodings into a class. Then for each class leaf l, Build must produce a compact public source-dependent conversion satisfying, for EVERY qualifying w routed to l,

    SourceLeaf(C,x,w) = k_l.

The exact equation must also ensure no adversary can obtain any k_l without a qualifying ORIGINAL certificate or independent break. A public class identifier cannot be this key. Choosing k_l=H(public_class) gives it to everyone; choosing independent k_l and masking by H(w) requires distinct rows for distinct w unless one implements an actual multi-witness conversion. Partitioning by the three OR branches only leaves three such missing conversions. This is the previous source-pad obstruction unchanged at the input to reverse transport, so reject before implementing a larger table or testing another hash domain. A source verifier's accept bit is not an opening.

Attempt C: make leaf keys directly H("source-leaf",ctx,w) rather than independent. The algebraic tree root becomes XOR of these keys for all selected leaf encodings. If the selected tree is polynomial and encodings public, root recovery is public. If the actual selected encodings are unknown future original histories, Build cannot compute their keys, the complementary rows or the root. If some are exposed through legitimate source evidence, the others cannot be silently assumed independent of the capsule construction. This does not solve the joint setup and arbitrary future source requirement.

These are attempted instantiations of the reverse transport repair; no alternate source relation, source work puzzle, secret online evaluation or forced canonical witness is substituted. A malformed tag wrapper must still be authenticated independently of the tag check it refutes. The prior R316 maturity correction, R225 native endpoint scope, and exact three original challenge conditions are unchanged.

## 3. Handoff

Do not repeat with larger trees, wider hash outputs, PRG compression, alternative XOR group bases, or public independent leaf-key experiments. The transport correction does not remove the missing operation: implement source-dependent leaf key generation AND a polynomial public capsule supplying the matching upward correlation for every qualifying complete original certificate, without exposing any such key on invalid input. This is not merely a matter of proving QROM security for cyclic ciphertexts. The above restricted simulator shows only a conditional transport component, and the actual source instantiation failed the classical-PPT/complete-source requirement before a full-public proof could be attempted. No qualifying advance.

No code or checker executed: the candidate's direct source instantiations retain the recorded source-pad/complete-state attacks and cost; scaling would not address them.
