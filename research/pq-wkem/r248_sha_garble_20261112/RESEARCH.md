## Candidate and exact attempted release
Try hash-XOR Yao-style garbling of a circuit for the **actual** SHA256d/Bitcoin/AuxPoW/ancestor verification, plus source admission and claim relevance, rather than verifying evidence after releasing a raw pad. \`Build\` privately samples uniform independent 128-bit labels \`L_i^0,L_i^1\` for each wire, encrypts all gate rows with SHA256-based pads, freezes the **complete claim-scoped native cancellation signature** \`sigma\` and publishes \`E=sigma XOR H("release"||L_out^1)\`. To open, a challenger must privately obtain **one globally consistent input label for every actual source-witness bit**, evaluate all garbled gates to \`L_out^1\`, and obtain the SAME frozen sigma. This defines only the garbling skeleton: a noninteractive public \`SourceInputEncode(C,w)\` for unknown future original evidence is not constructed.

### Full-public FALSE case and global consistency
The bounded counterexample is \`f(x)=x AND NOT(x)\`, identically false. If both input labels \`L_x^0\` and \`L_x^1\` are public to allow permissionless selection, a classical adversary uses \`L_x^0\` to obtain the \`NOT(x)=1\` label, combines that with \`L_x^1\` at the AND gate, and obtains \`L_out^1\` and sigma. No consistent assignment satisfies f and no original source certificate was furnished. A correct honest Open checking one consistent x does not stop direct public gate traversal. This is a negative regression of this **both-label-release** garbling family, not a theorem against Yao garbling with proper one-label private input delivery or against hash-only WE.

### Two attempted source-specific repairs
(A) Set input label to \`L_i(w)=SHA256("src"||x_W||SHA256d(parent_header(w))||i)\`, from actual SHA work. For different unknown future qualifying Bitcoin parents the digest and label vary, but \`Build\` already fixed its secret labels and rows **before** the future parent existed. No polynomial-time method to prepare all future state-dependent garbled rows is supplied. Making labels depend only on a public source bit, tag or fixed public ancestor makes both possible labels publicly computable, restoring the full-public attack. The mandatory canonical parent tag contains no builder-selected label preimages.

(B) Publish \`c=H("state"||x_W||source_SHA_state||r)\` to bind repeated input occurrences. An input commitment can be checked by the honest API, but unless its binding is enforced *inside the private-label delivery*, raw gate evaluation ignores it. Source chooses c after setup and does not know the secret builder labels; requiring a new input-delivery oracle would just rename the missing primitive. Publishing both labels for the alternative committed states again fails the false test.

There is a second **same-capability** equation: for one frozen ciphertext E, every distinct qualifying source witness w must reach \`L_out(w)\` with
\`H("release"||L_out(w)) = E XOR sigma = P\`.
If independent SHA-state-derived output labels are used, they almost never share the same pad. In an ideal independent n-bit pad model, q distinct random labels all matching a **fixed** P have probability \`2^(-nq)\`; conditioned on the first label matching, additional q-1 matches have probability \`2^(-n(q-1))\`. This is a narrow independent-label statement, not a concrete SHA reduction. The required repair is a **common hidden label** delivered from every qualified original future witness with cryptographic global-source consistency, or source-indexed ciphertexts precomputed for future witnesses. Neither is instantiated in classical PPT here.
