## Candidate serialization and attempted repair

Use domain-separated ideal random functions F (n-bit output), G (n-bit output), J (commitment), KDF (m-bit output). This is an idealized classical calculation below; it is not an implementation or proof for concrete SHA, nor a QROM simulation. Let enc be canonical length-delimited encoding. Honest Open starts at
    v0 = G(enc(x,w)).
It computes a link block sequence and then a diamond path, with every step
    v_next = F(enc(x,v,block)).
Build samples a terminal t, publishes c=J(enc(x,t)) and D=enc(S) xor KDF(enc(x,t)). It tries to publish correction data T that allows honest Open from every qualifying v0 to arrive at t without T exposing a direct way to compute t. Open verifies R_x(w), follows the public route from v0, checks c, and unmasks D at the terminal. The initial source hash, rather than the honest-code R check, is supposed to be essential to finding the terminal. Native VK/message is in the public view.

First attempt: Build constructs a finite diamond by selecting leaf states and link blocks with matching F outputs, then repeating the merge operation at successive levels. If the diamond publishes any starting state and a complete route from it to t, a party with no certificate can execute that route. Encrypting its route under H(state) does not help when state is published. Reject that variant without implementation. This is a full-public bypass, not a collision attack on original BTC/SYS source authentication.

Repair: hide ALL such starting states and paths leading to t, publish only endpoint test c and compact link guidance T. T can be arbitrary public data, but its proposed evaluator is forward hash-chain stepping, not an ideal secret evaluator. No public terminal dictionary is assumed. One possible optimization is expandable messages giving many possible link choices; each actual Open query still traverses one state/block pair. The following calculation tests whether a deliberately precomputed but hidden collision structure could make honest PPT linking succeed without a source-specific correlation.

## Exact fresh-frontier calculation

Fix the Build transcript for F,G. Let A contain every n-bit state occurring as a chaining-state input to an F query during Build, every F/G output during Build, and t. If Build made at most q_B total F/G queries, |A| <= 2 q_B + 1. A is an analysis set, NOT a set published in the capsule. Build can deliberately correlate queried states, choose t adaptively, and choose arbitrary guidance T as a function of its transcript. The calculation grants Open T and all public context, and counts queries, not bytes.

Consider a qualifying ORIGINAL w whose G input is fresh at Open, selected using original evidence independently of unrevealed F/G answers. For a distribution in which source evidence is independent of these construction domains, condition on the source and Build transcript and on freshness; this calculation applies. It does not cover a source witness deliberately selected using those unrevealed answers. If no qualifying fresh input exists in a particular source distribution, no conclusion for that distribution follows. For every-witness correctness a supported class of fresh valid certificates suffices to invalidate the proposed universal route.

G(enc(x,w)) is uniform conditional on this transcript. Its chance of hitting A is at most |A|/2^n. Until a state in A is encountered, no forward step can reuse a Build F query, since the current state is not among Build's queried input states. A new F input has an independent uniform answer conditional on the transcript so far. Reusing a previously queried Open input cannot cause a first hit, since its answer was already seen. This remains true with adaptively selected block values or branching among already computed states. For Open with at most q_O such F queries,
    Pr[any forward-path state reaches A] <= min(1, (q_O+1)(2 q_B+1)/2^n).
Arrival at t is a subset of this event. Arbitrary computation of block choices and use of a public expandable-message description do not increase the number of fresh query answers. The calculation permits precomputed CHOSEN collision routes; it does not assume the Build transcript consists of independent leaf outputs.

Scope: this is a classical random-function lazy-sampling bound for the stated forward-only evaluator and fresh input class. It assumes that the only way to advance a path is a domain-typed F step from a previously reached state, not an arbitrary overwrite of that state or an external hidden-state computation. It assumes no information about unqueried F/G values is included in Build. Any additional setup queries determining guidance must be counted in the transcript. A circuit supplying a state directly, rather than reaching it through these steps, is outside the bound and must be separately audited for direct computation by an unauthorized party. No general lower bound for hash-only WE is claimed. There is no reliance on the adversary volunteering its query log. No QPT theorem follows. Honest algorithms here must already be classical PPT, so negligible honest success is enough to reject this particular candidate.

Thus a polynomial-size chosen-collision diamond cannot repair correctness on fresh full-certificate starts merely by publishing compact forward-link guidance. If the guidance instead discloses a reachable entrance or terminal state, the earlier bypass applies. This identifies exactly where a new operation would have to be inserted, rather than treating random hash collapse as an encoding.

## Attempt to repair with short lanes

Let each forward state have b bits, enough that deliberate collisions or links can be searched in polynomial time when b=O(log lambda). To prevent the b-bit terminal from being the entire secret, try L independent lanes, each carrying a different t_i, and use KDF(enc(x,t_1,...,t_L)) for D. Publish per-lane c_i=J(enc(x,i,t_i)) so Open can check that it has merged to the right hidden terminal in each lane. This changes the honest resource tradeoff: short independently linkable states but a long combined mask.

This serialized repair is deterministically broken: enumerate the 2^b possible state values for each lane and check its public c_i. When J uniquely identifies t_i on the small domain, this recovers every t_i in O(L 2^b) evaluations, without any original certificate. For uniform independent ideal J with k-bit output, conditional on t_i the probability a different state matches its c_i is at most (2^b-1)/2^k by union bound, hence total ambiguity probability at most L(2^b-1)/2^k. Take k sufficiently large for negligible ambiguity, as honest correctness would prefer. Even a single lane without c can be enumerated with public native verification of S candidates. If b is superlogarithmic and all honest query budgets are polynomial, the preceding fresh-frontier calculation again bounds a lane's success by a negligible quantity (in the asymptotic sense when b/log lambda tends to infinity). Increasing L does not turn that failure into all-lane completeness. No security separation is established by birthday link search. No quantum speedup is required for the short-lane attack.

A joint-only commitment instead of per-lane c_i defeats the stated independent enumeration. It also removes the public per-lane target-recognition used by the proposed online linker. The next construction would need to show how the actual original certificate guides it to the one joint secret, without separately identifiable targets, and how the public guidance is simulated jointly with D, native VK/message, other capsules and source auxiliary data. Merely asserting a correlated joint search procedure is not an algorithm. This last case is NOT ruled out by the independent-lane enumeration; it is not implemented. Do not sweep state widths, add lanes, or benchmark collision search in this family unless that source-dependent joint guidance and its public simulator are supplied.
