## Concrete dependency problem and repair

The ORIGINAL public statement must bind the exact eventual claim/UTXO, branch, anchors, observation window, relation identity, and intended native verification key. If an on-chain funding output commits to the completed capsule and child pre-signatures, there is an ordinary hash dependency cycle:

\`manifest M -> funding-output script root -> txid(F) -> ORIGINAL x -> capsule C and child signatures spending txid(F) -> M\`.

This does not prove *all possible fixed-point constructions* impossible, but a protocol may not simply assume the funding txid is already fixed while its output hash contains signatures that depend on that same txid.

**SCFB algorithm.** Honest setup and validation are classical PPT. The unavailable secure \`WKEM.Enc\` is an explicitly unresolved black box, not an instantiated assumption used to prove source security.

1. Generate independent native challenge signing key \`(sk_C,vk_C)\`, safe-path signer keys and an independent *setup-only* authorization key \`vk_auth\` belonging to the already-required honest N-of-N participant. Freeze descriptor \`D=(network,R_id,claim,branch,anchors,window,native graph paths/timelocks/guards,vk_C,safe_vks,vk_auth,watcher policy)\`. The native output commits to the **descriptor and verification keys only**, not the capsule, completed child signatures or manifest. Independently verify exhaustive native path coverage and no bypass edges.
2. Form an immutable, fully specified funding skeleton \`F=BuildFunding(D,fixed inputs,outputs,fees,sequences,locktime)\`. Conditional on a witness-independent, non-malleable consensus txid, compute \`u=(txid(F),vout)\` **before any funding-input signature**. Freeze all non-witness fields; neither RBF nor malleating an input's scriptSig may substitute a different parent.
3. Compile \`x=Bind(R_original,claim,u,branch,anchors,window,vk_C,H(D),H(F))\` and \`C=WKEM.Enc(x,sk_C)\`. The eventual public \`WKEM.Open(C,W)\` must recover **the same precommitted sk_C for every valid ORIGINAL W**. Its actual cryptographic implementation and proof do not exist here. Produce complete *safe* child transactions spending exactly \`u\`; collect and validate all N-of-N path pre-signatures on fixed messages, using a full sighash commitment. **Do not pre-sign a challenge-path message.** After setup, erase/protect \`sk_C\`.
4. Form canonical off-chain \`M=(D,F,x,C,all children,all safe pre-signatures,watch policy)\`, \`h=SHA512(domain_M||M)\`, and \`cert=Sign_auth(domain_cert||network||u||h)\`. \`vk_auth\` is already committed by \`D\`; no additional online release authority is introduced. The authorization certificate is OFF CHAIN, verified by each wallet/watcher; Bitcoin does not verify it.
5. An authorized funding wallet validates \`D,F,x,C\` scope, all enumerated paths/guards, every safe pre-signature, certificate, deadline margins and full bytes, then durably stores them. It obtains a signed pre-funding receipt \`rho=Sign_watch(domain_DA||u||h||accepted)\` from at least one actually honest, independently selected watcher retaining the bytes. Only after checking the receipt and its own local copy does it release its indispensable funding-input signature on this exact \`F\`. Any missing condition causes abort **before this wallet authorizes irreversible funding**.
6. After funding, only the conditional native challenge signature under the witness-recovered \`sk_C\` authorizes the intended challenge edge. Normal payout follows the protected timeout. Bitcoin verifies ordinary native signatures and path conditions only; it never executes R, SNARG/PCP/VM steps or Bitcoin trace disputes.

The resulting directed dependency graph
\`D -> outputRoot -> F -> u -> (x,C,childTemplates,preSignatures) -> M -> cert -> watcherReceipt -> fundingInputSignature\`
is acyclic because neither C nor M is committed inside the funding output. The off-chain authenticating signature bridges \`M\` to the actual outpoint without introducing an on-chain hash cycle.

## Precisely established and conditional lemmas

**Acyclic compilation.** If the complete funding skeleton can be fixed before child signatures, the consensus txid excludes later funding witnesses and the descriptor is independent of the finished manifest, the above steps have a polynomial-time topological ordering. All capsule/source/child references include the identical \`u\`; changing \`F\` or any bound claim field invalidates the certificate/checks, absent a hash or signature break. This is a deterministic dependency and binding lemma, not a WKEM-security theorem.

**Authorized-funding readiness/abort.** Assume: (i) at least one indispensable input of the *authorized funding F* is controlled by an honest wallet that enforces the complete gate, (ii) any valid input authorization covers the whole fixed F and QPT EUF-CMA holds for that independent native signing key, (iii) the setup-only authorizer signature and SHA-512 scoped manifest digest are QPT unforgeable/binding, with all keys independently sampled from the challenge secret, (iv) the on-chain descriptor really enforces the complete path graph, exact outputs and checked timelocks, (v) \`u\` is stable and non-witness transaction fields cannot be changed after pre-signing, (vi) the designated watcher is honest when acknowledging durable possession. Then a *confirmed authorized F* implies the complete static pre-signature bundle, claimed capsule bytes and watcher-accepted manifest existed **before** the honest wallet signed F, except for a signature forgery, hash/txid binding failure or violation of the honest-gate premise. If required data are withheld the honest wallet never signs F. Proof: gate order enforces the temporal implication; an alternative complete input signature is an ordinary fresh-forgery event. An alternative manifest under a previously authenticated \`u,h\` requires a hash-binding failure or cert forgery. Classical signature simulation is straight line; no quantum rewinding/extraction. The capsule is opaque, and **this theorem does not prove it source-sound or key-hiding**.

For arbitrary nonuniform QPT adversaries the signature part requires QPT EUF-CMA with classical signing queries; signatures and keypairs are classical PPT. The manifest-hash claim requires QPT collision/second-preimage resistance of its explicit SHA-512 digest, and the real transaction ID has distinct quantum collision/preimage bounds. The simulator can generate all non-target auth keys, contexts and opaque auxiliary capsules independently; it **does not** embed a decisional-LWE challenge into a source-dependent WKEM and does not establish a full joint-public view theorem. All checking keys, sibling capsules, certification and watcher receipt are visible to the adversary. Cross-scope selective opening, malicious SOURCE choice and target-key-correlated auxiliary advice have **no** new bound here.

**Important boundaries.** Anyone can pay the same script from a different transaction: unsolicited third-party funding is outside the authorized-wallet statement and cannot be prohibited by a descriptor. The required honest funding wallet is **distinct** from the already-required one-honest N-of-N preauthorizer and the independent one-of-N watcher role. A receipt is not proof of permanent DA or timely inclusion under arbitrary BTC censorship; challenges still need a timely admissible observer and enforceable inclusion, and timeout liveness has its own propagation assumptions. The optional stronger keyless Build remains open. A maliciously constructed/cryptographically broken C could reveal sk_C despite perfect graph staging. The conditional no-EC-key-path P2MR-like/SLH-like endpoint is not deployed or proven here. No blanket 128-bit quantum security claim is made.

## Executed checker and exact failure boundary

The exact accompanying \`checker.js\` uses the Node standard crypto library with a **toy HMAC fixture** and a witness-independent JSON-hash *mock* txid; neither implements a native public-key PQ signature, Bitcoin serialization or witness encryption. It deterministically checks a staged DAG, three cyclic naive commitments, an exact manifest/outpoint binding, mutation rejection, a complete six-bit readiness truth table and an unsolicited-deposit counterexample. The published \`output.json\` is captured from the exact executed checker; the repeated execution produced identical bytes. An extended separate local Python checker performed 293 abstract assertions (twice identically) with 16 scope mutation checks and seven malformed-ceremony checks; its detailed derivation and sources are preserved in the downloadable local archive, not represented as a GitHub execution.
