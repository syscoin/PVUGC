## 1. Full-address construction attempt

Fix the full bounded original relation V(x,w) with canonical certificate serialization, branch selector and complete authenticated checks. Factor it into P(x,w) AND Q(x,w) without changing the accepted set: for example let Q check public context, syntax and claim field equality, and P check all remaining source qualification/authentication, including whichever original OR ground the selector specifies. A real split must preserve all checks; this is not a new Core or source-validity assertion. The attack below applies when an adversary can form a syntactically/contextually matching Q-only candidate without original evidence. Such candidates are the point of splitting source authentication from public syntax; if Q itself requires a full original witness, the proposed local-key step has not been solved.

Define a = enc(ctx,w,r), with injective domain separation and a fresh lambda-bit salt r ignored by P and Q. The salt is internal Open randomness and does not restrict or change the set of admissible original witnesses. This candidate's correctness is for every valid w and every salt; the bounds below are for that interface, not a lower bound for all possible Open randomness mechanisms. Choose uniform K in {0,1}^lambda and encrypt the fixed safe native cancellation capability sigma using E = sigma XOR H_final(ctx,K) (with an appropriate length-expanding independent hash domain). Context includes all claim/capsule/native binding required by the existing handoff. Build independently chooses two PRF seeds k_0,k_1. Write

    u_i(a) = LeafSeed(k_i,a)
    F_i(a) = H_i(ctx,a,u_i(a)), i in {0,1}.

LeafSeed can be an independent hash-domain GGM seed tree; allow independent random leaf seeds as an even more favorable thought experiment. H_0,H_1,H_final are independent ideal hash domains. These are explicit ROM assumptions, not a proof about SHA. The input address is included even if seed collisions occur. None of the masks is a projection of a stable garbled-wire token.

Desired opaque keys implement

    L(a) = F_0(a)       if P(x,w), else bottom;
    R(a) = K XOR F_0(a) if Q(x,w), else bottom.

If both defined at the same address, Open recovers K = L(a) XOR R(a), then sigma. Cross-address XOR does not cancel the mask. At the level of an ideal interface, distinct full-address masks are independent: for an address with just one row available, that row has uniform marginal even with K fixed. This is the intended separation from R289, NOT a joint-public key simulation or a QPT proof. Merely giving the keys for both ordinary FSS shares of a constant is not secure: for the usual shared PRF plus offset representation, the offsets and shared PRF seed are exposed. Restricting each key by an honest-code predicate does not solve it.

Concrete attempted Build: give predicate-constrained evaluations of F_0 on P and F_1 on Q using GGM prefix covers of the permitted address sets. To isolate the correlation problem, grant efficient opaque single-function constraint keys even where such covers would be exponential for the actual P,Q. This grant strengthens the candidate for the preflight; no efficient covers of the original verifier are claimed. Introduce a public correction program T with polynomial-size auxiliary hints prepared by Build:

    D(a) = K XOR F_0(a) XOR F_1(a)   on Q;
    R(a) = F_1(a) XOR D(a).

The intended implementation was DPF/FSS-style late merging: the two seed trees remain independent at interior nodes and a correction merges their terminal values only at the full address. This avoids exposing a constant offset in a common prefix or a reusable projected label. A literal terminal table indexed by a is exponential. A public polynomial per-level correction derived from the seed trees would be the useful repair if it could actually compute D without exporting either pad or K. The following preflight checks arbitrary classical PPT such corrections, including fused R (not just one proposed correction word format), under the specified independent terminal-hash representation.

## 2. Same-address recovery from any correct public late correction

Let Build make at most q_B classical ideal-hash queries. It knows K and both seeds and can publish arbitrary polynomial hints correlated with them, the complete original relation, native checking key/message, and auxiliary input independent of future random salt. Choose a Q-valid candidate w without an original witness, and sample uniform r after Build; w may be fixed independent of Build. For fixed w, each setup H_i query can address at most one salt in the injective full-address encoding. Hence the probability any setup H_0 or H_1 query had this a is at most q_B/2^lambda. Use fresh independent hash domains for the seed trees and terminal values. Condition on the seed trees, Build tape/transcript, K, a, and absence of such a query. The terminal H_0 and H_1 values F_i(a) are now independent fresh uniform lambda-bit strings, regardless of the public hints. Conditioning on the complete independent seed-tree oracle for this proof does not give it to an attacker.

Consider first the fused public classical evaluator R(a) returning K XOR F_0(a). For any evaluation not querying the actual terminal address (ctx,a,u_0(a)) in H_0, its output is independent of F_0(a). This is a deferred-decisions argument: up to that query, all replies, including those in independent domains, are identical to a run in which the target is not sampled. Thus

    Pr[R correct AND no target query | fresh] <= 2^-lambda.

The same bound holds for D(a), even if the evaluator is additionally given the entire F_1(a). Conditioning on F_1(a) and K does not determine F_0(a). Therefore, if the advertised Q-local correction succeeds except with epsilon probability, the joint event of correct evaluation and a target query has probability at least 1-epsilon-(q_B+1)/2^lambda. For D the honest caller additionally evaluates its Q-constrained F_1 key and XORs it to obtain R. If that evaluator has error, subtract its error as well. No need for a reusable root seed to appear in a query: the leaf seed can be unique to this address.

Explicit adversary: choose that Q-only w and fresh salt. Run the actual public R program (or D then F_1), instrumenting the hash calls of the public classical algorithms. Record all at most q_R H_0 replies at address a, and for each reply y compute

    K_candidate = R(a) XOR y
    sigma_candidate = E XOR H_final(ctx,K_candidate).

The query for the actual terminal value, when present on a correct run, supplies K and exact sigma. A public native verification predicate on the frozen message can select an accepted candidate; any other accepted candidate is itself an unauthorized native authorization in the stated endpoint model. Even without a selection test, a random element of the polynomial list recovers the exact precommitted capability with probability at least (1-epsilon-(q_B+1)/2^lambda)/max(1,q_R), subtracting any additional evaluation error above. This attack uses no original witness, no second address, no cross-root rescoping and no inversion of a hash. Its trace is generated by the adversary running public honest code, not supplied by an arbitrary adversary or extracted by classical rewinding of a quantum process. A classical attacker is sufficient against the required QPT class.

If Q-only candidates cannot be generated, this specific attack does not assert their existence. In particular, a correction that is correct exclusively on full P AND Q addresses escapes the argument as stated, but then its public implementation must itself enforce the original source-dependent gate, which is the missing operation. A correction evaluated by an inaccessible private program is equally not the requested Open. The fresh-salt argument is specific to the proposed address representation; it does not assume all source evidence has entropy unknown to setup.

## 3. Why the intended serialized correction and joint simulator do not yet exist

The literal Build with an explicit terminal table can enforce the correlation but has exponential size in the salt alone; it also requires an actually opaque access mechanism for the rows. Polynomial setup guesses cannot cover a fresh address (bound above). Deriving correction words from independent GGM expansions at a fresh full address requires the terminal random hash values; section 2 applies whether hints are per-level, recursive, or arbitrary polynomial public code, and whether the corrected output is emitted directly or as an XOR correction. This is not an attack based on affine witness interpolation, low degree, or stable-label recovery. The intended full-address indexing does eliminate that specific cross-address cancellation, but it does not stop this one-address export of the hidden pad from a locally accessible correction.

An ideal simulator that supplies uniformly random single-row values and no matching hidden pad query is distinguishable from the real public execution whenever it supplies a correct Q-local R without that terminal correlation. More concretely, the adversary's candidate list contains the true K on the real correct path with the above probability; a simulator that treats R and all observed H_0 replies as independently uniform relative to K gives at most q_R/2^lambda probability of this event. This comparison is to that specific independent-mask simulation, not an assertion that every conceivable simulator is impossible. K may correlate with E/native context and sibling capsules; none of those correlations repairs the real attack (it already succeeds on a single capsule), and no simulation for them is established.

Potentially a truly different correlated hash-based tree could generate the two terminal shares jointly without any independent hidden hash evaluation used as a publicly accessible correction. The argument here does not rule that out. But ordinary independent GGM trees plus DPF-style corrections for a constant, public shared offsets, or a hidden correlated-oracle interface do not instantiate it. The next exact equation is an opaque constrained-key derivation of a *jointly generated* full-address pair (L,R) with L XOR R=K only for combined valid rows, with no public local procedure computing the opposite pad or an exportable offset and with a joint simulator for the serialized keys. Do not substitute a primitive already promising these outputs. A fresh approach should supply concrete coupling of the seed evolution and constraint key material, not another parameter sweep, terminal correction table, or independent-row marginal argument. If that coupling only works under an ideal private evaluator, reject it at selection.
