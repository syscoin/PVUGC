## Repairs and exact failures

1. **Commit to builder-chosen K, ask future BTC to yield K:** An ordinary future header is not constrained to have `pad(b)=K`; imposing such a target changes original source consensus, and private premining by the builder neither guarantees Bitcoin admissibility nor prevents early malicious disclosure.
2. **Hash-only public time-lock `F=H^T(seed)`:** Build can precompute F by doing the work, but *any* observer can run the same hash chain independent of ORIGINAL evidence. Starting from unknown future b recreates the setup equation; source verification in software before raw decryption is bypassable.
3. **Condition pad on alternate Syscoin witness `w`:** `pad(b,w)=H(b||w)` varies across qualifying alternative parents/branches. A publicly computable correction that maps all valid w back to one K is precisely the missing cryptographic source-conditioned release, not an instantiated repair; hash-committing a withheld correction token does not reveal its preimage.
4. **Precompute a table for all future b:** No polynomial-size admissible-future-beacon list is available at pre-funding setup; enumerating a high-entropy future Bitcoin header space is exponential. Replacing it with common target-prefix bits/height makes the release selector public as in R247/R257.

Thus neither classical-PPT Build nor arbitrary-witness same-capability Open plus FALSE/hard-TRUE joint QPT security is instantiated. Requiring one fixed shared future BTC anchor also must not silently remove qualified original certificates from the release relation.
