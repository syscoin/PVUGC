## Candidate equations

For the candidate only, let F(s,b) be an iterated compression transition of lambda-bit states on fixed-size blocks b; F*(s,u) denotes iteration over a canonically padded suffix u. This is an abstract hash-state construction, not a claim about a consensus API, or that actual source hashes admit efficient collisions or length extension. A builder chooses a finite directed graph with entrance states a_i and labelled edges (s,b,s') satisfying F(s,b)=s'. Edges can merge, with each entrance having a known path ending at terminal z. The builder wishes to wrap a fixed capability using K=H(domain||x_W||z) and D=sigma_cancel XOR K. A canonical encoded ORIGINAL certificate w would produce a state S(w). A connector L(C,w) is to output a suffix u such that F*(S(w),u)=a_i and the graph continues to z. The intended improvement over a point-function release is that there is no single live path to distinguish: arbitrarily many entrances can lead to the same terminal.

First preflight: a public terminal z immediately reveals K. To repair that rather than merely omit z from display, give the graph opaque vertex labels, encrypted outgoing transitions and a terminal payload. For example an outgoing row for a vertex state s and block b uses H("edge"||x_W||s||b) as its mask. Store a lookup identifier H("lookup"||x_W||s) and an authenticated encrypted next-state token. Open obtains a valid entrance-state token, follows known rows to a fixed hidden terminal token t, and decrypts D using H("payload"||x_W||t). This is a meaningful public *path evaluation* equation if the entry token is genuinely unavailable until qualified source evidence exists. It does not itself implement the entry token.

## Joint test of the source entry and the graph

Case 1: the entrance token or its input state is included in the capsule, or can be computed from a public entrance state. Any such entrance can be used directly, without a source prefix or connector. In the transparent graph this is a literal suffix replay starting from a_i; in the encrypted graph it is invocation of the same public path evaluator with the exposed token. No hash inversion or source evidence is involved. The real public capsule has every graph component, not two separately hidden views. Requiring the honest Open code to first VerifyOriginal(w) is not a cryptographic restriction on this path.

Case 2: the connector is a public algorithm L(C,s) of the compression state alone, with source verification checked separately. For any public feasible s from which L succeeds, the adversary executes L and the remaining public evaluator from s. A valid source hash output with a target prefix is not a secret representation of its input. In particular, where the intended entrance condition depends only on the public digest being in a numerical target interval, the adversary can sample a number in that interval directly. The existence of a compression-state connector from that number says nothing about a qualified header, contextual target, ancestry, chainwork, burn or AuxPoW proof. This is the known target-digest shortcut, even if there are many graph entrances and no distinguished live branch. A standalone independently hard connector puzzle instead of actual source authentication does not meet the requirement.

Case 3: hide entrance tokens and require the complete original prefix (not just its state) in the row KDF. To test correctness, fix a particular qualifying certificate w that was not used in setup. Model the domain-separated entrance hash E(w)=H("entry"||x_W||canonical(w)) as an independent random oracle from the source verifier; the graph is generated without E(w) having been queried. This is an explicitly restricted classical ideal-hash calculation, not a concrete SHA or QPT theorem. If m hidden entrance tokens were fixed by Build, then Pr[E(w) belongs to the set of entrance tokens | the setup transcript] <= m/2^lambda. If Open instead tries Q distinct domain-separated salts on this certificate, the corresponding union bound is mQ/2^lambda, conditioned on no prior query to those inputs. Adaptivity to earlier unsuccessful independent outputs does not change the bound. Even allowing the builder to have used E on known certificates does not establish coverage for a different future certificate. For polynomial m and Q the candidate fails its every-witness correctness requirement, not merely bandwidth. If the entrance KDF instead truncates to a target interval small enough to make this matching practical, the public token space can be enumerated without the source certificate; the raw row-access algorithm cannot distinguish this from having actually queried E on an admissible w.

Case 4: require the source prefix in EVERY row key, e.g. H("edge"||x_W||w||s||b). Then direct state replay is blocked for independently hidden w, but the builder cannot generate even the first common row ciphertext for an unknown future w from an independent hash. For two unseen distinct certificates using the same graph edge, their masks are independent in this model. A fixed ciphertext that decrypts to one prechosen next-token value under both masks requires the masks to agree; probability 2^-lambda for a fixed pair. This is not repaired by compression-state merging: equality of F*(S(w),u) does not imply equality of the independently domain-separated full-prefix KDF. Publishing per-prefix corrections is not a polynomial construction for the original source language. Keeping the row-generation oracle private/online is outside the permitted Open model.

The exact mathematical delta from DPF is convergent-state evaluation; the unresolved equation after removing its direct joint-state leak is now:
    
    Entry(C,canonical(w)) -> hidden token tau_i
    PathEval(C,tau_i) -> t   for every qualified ORIGINAL w.

The builder must generate the jointly secure serialized Entry and the graph from x_W and the fixed native capability, without knowing future w, while raw entrance or terminal token recovery yields actual ORIGINAL evidence or an independently justified QPT break. Neither opaque row encryption nor chosen-prefix convergence instantiates Entry. The intended use of genuine source collisions/merging would also have to preserve each of the three branches, including a finite burn refutation or independently authenticated carrier fault that need not contain any pair of colliding hash states. No collision finding or herding complexity assumption has been promoted to a source authenticity proof.

## Disposition and handoff

Reject before implementing a hash diamond or any larger fixture: the closest target-digest attack survives unchanged in the public-entry variant, and the full-prefix repair lacks a public entry compiler. The restricted matching calculation is a correctness preflight for this candidate, not a general impossibility result for hash-only witness encryption. No checker, empirical security measurement, actual chain evidence or native signature was generated, and no QPT reduction is claimed. Do not repeat this attempt with larger graphs, shorter entry tokens, alternative compression functions or independent puzzles. A future candidate needs a mathematically new source-dependent entry primitive with joint simulation, not another efficient convergent graph. No ordinary PR comment or user notification; the missing advance has not been obtained.
