## Component: hash-committed dynamic witness memory

Take a fixed canonical length-N binary witness `w`, N a power of two. Define leaves `H_leaf("leaf",i,w_i)` and internal nodes `H_node("node",left,right)`, with injective domain-separated length-delimited encodings. The witness supplies its root `rho` plus an authentication path whenever a verifier queries a bit. An evaluator fixes a single root `rho` for an execution, rejecting any failed opening. Reusing any bit `i` with contradictory values at the same root yields a collision in one of the SHA Merkle hash domains: start at two different `(i,b)` leaves with the same final root, and find the first level where distinct ordered inputs hash to the same output. Thus repeated-read binding can be reduced to collision resistance without enumerating the entire `2^n` *explicit-state graph*. This is **not** a proof of secret-token release, and is not an NP-state lower bound bypass for the key-carrying graph.

Critically, if `rho` is adversary chosen AFTER setup rather than fixed honestly before, the relevant assumption is *chosen-collision resistance*, not just second-preimage resistance against a fixed root. SHA-256's generic quantum collision query complexity scales around `2^(256/3)` rather than 128 bits in an idealized quantum attack model; do **not** claim this SHA256-root gate has 128-bit PQ binding. An independent off-chain SHA-384/512 commitment might target stronger quantum collision security, but changing the hash length is not a release solution and does not alter Bitcoin SHA256d consensus. Quantum security was not measured by the test. The source relation remains a separate full protocol condition, not a Merkle proof alone.

## Four integration attempts: precise equations and outcomes

Let `sigma` be a precommitted length-k capability, `P` a domain-separated full-output hash/pad, and `rho(w)` the canonical witness root.

1. **Single source-root pad.** Setup chooses some `rho0` and emits `D=sigma XOR P(rho0)`. Open with any `w` computes `D XOR P(rho(w))`. Distinct valid witnesses normally have distinct roots. For an independent ideal hash, when `rho(w) != rho0`, equality to `sigma` has probability `2^(-k)`. The concrete toy tested four different valid-root witnesses; exactly one opened correctly. Thus no full all-witness completeness.
2. **Constraint-residue collapse.** All valid witnesses produce residual vector `g(w)=0`. Setting `D=sigma XOR P(0)` ensures same result for all witnesses, but an attacker computes `D XOR P(0)` from public data with *no source*. Embedding a software verifier around this release cannot undo prior key exposure.
3. **Common anchor collapse.** The precommitted public Syscoin/BTC ancestor `a` is common to all source transcripts, but `D=sigma XOR P(a)` is immediately public. A common known source constant is not a hidden correlation.
4. **Per-root corrections.** Publishing one `D_rho=sigma XOR P(rho)` for each accepted `rho` gives exact correctness and possible ideal-hash witness-query extraction; however Build must obtain those roots without any future witness. Enumeration of all satisfying roots takes exponential effort on generic NP instances. This is the prior witness-indexed table failure in a different form, not a repair.

**Attempted structural repair:** bind all Merkle evidence openings to one root, then derive a hidden common terminal state through a hash-sealed verifier. The *evidence consistency* is enforceable with a short computational commitment. The terminal relation `ReleaseToken(rho,w)=T` for all valid `w` still needs a hidden seed or correlated correction chosen by Build **without knowing any rho(w)**. If `T=P(0)` from public accept bits, raw bypass. If `T=P(rho(w))`, valid-witness disagreement. If all transition labels are public from their input, BFS/path evaluation can expose the accept token without an ORIGINAL witness on any reachable accept path, as R172 already shows. If labels require a secret PRF evaluation key unavailable to the witness, honest Open fails; publishing a constrained evaluator that outputs the label only for satisfying witnesses is just renaming the missing WE compiler. No H5 correlation was constructed in this pass.

## Actual executed evidence

`checker.py` uses real SHA-256 (only as a small functional hash; not authenticated BTC headers), canonical balanced Merkle paths, 4-bit ORIGINAL toy CNFs and a precommitted 32-byte capability stand-in. It ran deterministically with 205 assertions, four satisfying assignments with four distinct roots, zero satisfiers for the deliberately contradictory relation, one-of-four release by one-root pad, raw bypass from zero residue and public anchor, and a functional all-root table of four entries. `collision_regression.py` substitutes **SHA-256 truncated to 16 bits** and exhaustively searches 16-bit assignments for a pair of different witnesses with equal root and distinct valid bit openings; a pair occurred at 381 candidates. This is an adversarial control demonstrating the reliance on actual collision hardness, NOT a SHA-256 collision, QPT test, source proof or cryptographic break. Both scripts were executed, and output and source SHA-256 hashes are recorded in `MANIFEST.json`. No independent verifier/agent was invoked.

## Exact remaining nonblackbox source-release obligation

Find a polynomial-time **witness-independent** source-to-token correlation from the actual SHA256/Syscoin child/Bitcoin-parent/AuxPoW/coinbase/anchor/claim/interval **computation trace**, such that every distinct valid witness (including different legitimate parent-work certificates for the same semantic child) yields the same hidden setup-chosen terminal capability *without* any invalid-source computation, forged best-chain inclusion or observer-selected source producing an equivalent token. Bind the full cryptographic event into the release calculation, not just a post-hoc validator or a root commitment. Simultaneously provide a full-public quantum simulation and reduction of arbitrary recovery to a full ORIGINAL witness; do not let a setup/source signer retain the source labels and recover the key early. Merkle correctness alone is strictly insufficient.

A promising experiment would have to supply an explicit `Build` gate that produces a hidden *statement-conditioned* terminal token for all accepting Merkle-committed SHA traces in time polynomial in statement/security length **and** demonstrate in the same run that a FALSE/invalid trace cannot derive that token. Ordinary gate tables with public input labels, common accept-state masks, raw PoW nonces, public descendant headers, and secret-source OT-like labels that the source knows early have already failed. No such gate, PQ reduction, N-of-N ceremony or native endpoint was constructed here.
