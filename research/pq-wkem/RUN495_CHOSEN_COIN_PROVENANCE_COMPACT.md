# Run 495 — Chosen-coins defeat an Enc-image + Eval-provenance FHE release gate

Draft PVUGC#1; starting head `e454e2a443e68a33855ebd012ecbab6dfa792171`, branch `research/pq-wkem-validation-20260918`, 2026-10-14. This is a scoped counterexample to a *proposed* repair of Run 494, not an attack on deployed FHE, a completed WKEM, or an RIO theorem.

**Claim (generic separation).** QPT IND-CPA, negligible FHE correctness error averaged over honest encryption coins, a perfect public proof that `c_w=Enc(pk,w;r)`, and a perfect public proof that `c_out=Eval(F_x,c_K,c_w)` do NOT imply false-ORIGINAL-instance authorization soundness against a watcher selecting the encryption coins. Honest setup/evaluation are classical PPT; attacker classical PPT, hence also QPT; the whole public capsule including native checking key, claim, branch and auxiliary ciphertexts is available.

**Construction.** Given any base FHE E, use uniform extra coin selector `b in {0,1}^lambda` and independent ordinary coins t. Let `Enc*(m;(b,t)) = 1||m` if `b=0^lambda`, else `0||Enc(m;t)`. Let `Dec*(1||m)=m` and `Dec*(0||c)=Dec(c)`. For normal inputs, `Eval*` is prefixed base Eval. For the designated circuit `F_x(k,w)=(R(x,w),R(x,w)*k)` and exceptional witness ciphertext `1||w`, the PUBLIC `Eval*` instead returns `0||Eval(Force,c_K)` with `Force(k)=(1,k)`; complete other exceptional cases arbitrarily in public PPT. No restriction of standard honest-randomness FHE correctness is violated beyond the negligible event `b=0^lambda`: `err_new <= err_base+2^-lambda` for one fresh input. IND-CPA challenge distributions agree with prefixed base encryption except probability `2^-lambda`, so `Adv_QPT_INDCPA(new) <= Adv_QPT_INDCPA(base)+O(2^-lambda)` by a straight-line hybrid; public Eval* is simulatable, with no release/decryption oracle.

**Attack.** For an ORIGINAL-false x, choose arbitrary w and public coins `(0^lambda,t)`. Then `c_w=Enc*(w;(0^lambda,t))=1||w` is genuinely in the encryption image, so a complete explicit encryption witness proves it. The adversary faithfully executes the intended public algorithm `Eval*(F_x,c_K,c_w)`, so a perfect exact-Eval transcript also verifies. But `Dec*(c_out)=(1,K_x)`; a secret-bearing release gate trusting only these two certificates outputs K_x. This permits a fresh context-bound native signature with no ORIGINAL witness. The result is stronger than Run 494's acceptance-bit-only bypass: BOTH image membership and exact Eval provenance have been granted. It does NOT defeat a gate that directly verifies ORIGINAL acceptance or validates a pointwise semantic admissibility domain.

**Precise missing condition.** Every *certified, adversarially chosen* input must have a plaintext w on which the evaluated output actually decrypts to `(R(x,w), R(x,w)*K_x)`, except under an independently justified proof/correctness break. A certificate merely proving that input bytes arise from some encryption coins is insufficient when correctness is only average-coin. This is separate from hiding the decryptor itself, from input/source proof knowledge, and from the missing signature-to-accepted-COMPLETE-representation arrow. The exact Run 259 note, blob `c7f3b77f0273ca1cbe6f0b31c1a086b8eb3acbf2`, binds only an accepted COMPLETE representation to an ORIGINAL witness or its stated SIS break; an Enc/Eval transcript is not automatically such a representation.

**Falsification taxonomy.** (1) provenance-to-semantics seam, (3) visible rare-coin fingerprint, (5) public chosen-input Eval, (6) malicious selected coins are decisive. (4) independently generated capsules repeat the failure; (7) fresh native signing defeats mere replay binding; (8) public native checking key confirms the result; (9) attack is classical inside QPT, no separate coherent claim. Global gauge (2) is irrelevant. No new assumption or generic iO/WE-equivalent object is posited.

**Executed checks.** `node run495_compact_check.js` has 437 assertions in 64 symbolic contexts, 32 false contexts, 64 true-instance same-key releases, 32 honest false rejections, 32 false selected-coin releases and 64 exact Enc/Eval certificate acceptances. Nine finite selector widths check honest bad-coin fraction `2^-b` versus chosen-coin success 1. Local independent `run495_chosen_coins_check.py` exercises 501 assertions and 32 actual fresh classical Ed25519 signatures with altered-context replay rejection. Both were repeated with byte-identical output. Toy symbolic semantics, NOT real FHE/PQ signatures, security or quantum computation.

**Literature.** Viand–Knabenhans–Hithnawi, *Verifiable Fully Homomorphic Encryption* (arXiv:2301.07041), distinguishes encryption/input integrity from computation integrity. This run is an independent artificial-scheme separation, not a purported attack on their constructions. Full proofs were not freshly audited. CLZ and RIO remain architectural leads, not validated WKEM instantiations.

**Handoff.** Test a concrete public certificate for *pointwise* semantic input correctness under chosen coins, coupled to complete ORIGINAL-source binding and a minimal secret-bearing release. Then prove arbitrary-QPT hiding and signature-only authorization-to-ORIGINAL extraction; do not infer either from Eval-proof verification. Malicious N-of-N ceremony, related statements, actual 128-bit resources and conditional P2MR/SLH on-chain endpoint remain unproved. Production unchanged; stopping condition unmet.
