## Conditional oracle-relativization lemma
Let x be a fully bound claim, including actual UTXO/burn/assertion, BTC/SYS anchor/window, baseline, required LC depth, deadline/reset, exact safe native message and VK, capsule/session ID, public setup proofs, and correlated sibling capsules. Let H be an ideal source hash oracle. Assume honest classical polynomial-time `Build^H(x,S;r)` makes at most q_B oracle queries and publishes all of C. A *publicly serialized, fully oracle-relativizing* `Open^H(C,w)` uses H only through substitutable external calls; no intrinsically protected/nonrelativizing concrete SHA verifier is embedded.

Assume PPT `ForkForge^H(x)` constructs a finite table of t overwrites P, defining H' equal to H elsewhere, and a finite w such that:

1. `R_original^{H'}(x,w)=1` via one of the three ORIGINAL OR grounds, but `R_original^H(x,w)=0`. The latter refers to *this counterfeit w*; the actual instance may be hard TRUE because other witnesses exist.
2. x and its authenticated baseline facts remain unchanged by patches. The patches avoid every hash query made during honest setup, except with probability δ. A sufficient, explicitly assumed estimate is δ ≤ q_B*t*2^-κ if each edited point has conditional min-entropy κ against the builder's previous classical transcript. The synthetic fixture itself does not prove this probabilistic condition for a real source environment.
3. There is *oracle-universal per-qualifying-witness correctness* of `Open^{H'}(Build^{H'}(x,S;r),w)=S` with error at most ε_corr for the counterfactual oracle distribution. Ordinary averaged-over-unconditioned-RO correctness does not automatically imply this under rare conditioning.

Then a public adversary constructs H' and w, simulates all public Open hash calls with H', and recovers S with probability at least `1-δ-ε_corr-ε_forge`, while **not producing an ORIGINAL certificate under actual H**. The proof is direct: when patch keys were not previously queried, `Build^{H'}(x,S;r)=Build^H(x,S;r)=C` by induction on the honest classical setup transcript; apply the stipulated all-witness correctness. This is a *conditional model lemma*, not a complete-public QPT forgery/extraction theorem for an instantiated capsule. An adversary with coherent H access can also implement finite overrides reversibly via equality tests and XORs; this observation neither supplies QROM programmed-Oracle security for concrete SHA nor a physical reprogramming of Bitcoin hashes.

This lemma would not apply to a nonblackbox cryptographically encoded circuit that intrinsically enforces the arithmetic of concrete SHA before secret release, to a trusted external source oracle, or to a one-preimage hash-lock that lacks every-witness correctness under an intentionally reprogrammed collision. Its scope also excludes instances without a compatible counterfactual PoW history and malicious auxiliary distributions invalidating the required fresh-query entropy. The full OR relation is *not narrowed*; one possible counterfactual authenticated conflict branch suffices for the lemma's hypothesis.

## Repair screened / next equation
To evade this restricted oracle-relativization attack, source SHA evaluation must be cryptographically enforced *inside the same encoded mechanism that hides S*, not by a public validation wrapper, a hash of capsule bytes, a fake input-range ticket or a caller-supplied verification bit. Embedding SHA arithmetic in a **genuinely protected nonblackbox program** is a possible direction, not an implemented hash-only FE or source-bound key dispenser. A publicly readable SHA verifier alone does not protect secret release.

The indispensable missing capability remains practical serialized classical-PPT `Build_inc(x_W,S;r)->C`, and public `Open_inc(C,w)=S` for every authentic ORIGINAL witness, plus a complete-public, auxiliary/capsule-composable FALSE/hard-TRUE QPT unauthorized native recovery/forgery reduction to an ACTUAL qualifying ORIGINAL source certificate or an independently justified hash/native break. One-honest N-of-N preauthorization and known/native cancellation signatures remain conditional endpoints; no progress is claimed from eliminating a black-box family.
