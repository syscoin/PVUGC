## Candidate selected before implementation: guarded reachability with explicit contradictory decoys

Instead of a group product over independently selectable occurrences, low-degree raw pad function, DPF root difference, or alternate opening of a fixed proof, use a graph whose edges are ordinary publicly computable predicates of ONE complete original certificate. Release is a nonmonotone operation on the graph selected by that certificate. Use no independent wire-label secrets, no private evaluator and no alternate proof randomness. The closest R289 occurrence splice/union attack is addressed explicitly: BOTH terminal values will be reachable in the unguarded union, and invalid certificates will give a public hash-derived decoy, not the complement of the secret. Thus the usual procedure of combining all exposed local choices and obtaining a unique target does not by itself recover the key. R327 invalid-trace additive interpolation likewise has no direct pad oracle in this variant. This is a concrete construction preflight, not an asserted secure primitive.

For a polynomial-time original verifier, take its deterministic polynomial-size bounded circuit, use canonical Boolean gate trace bits z, and write its correctness constraints as f_1(z),...,f_m(z) in {0,1}, each meaning the corresponding gate/parse/authentication constraint is satisfied, including its final acceptance output. The trace is computed from the original w, not freely supplied to Open. For any computed accepting trace, all f_j=1. For any computed rejecting trace, at least one f_j=0. The conjunction covers the ENTIRE original verifier, not just a PoW digest check; this symbolic compilation is not a new implementation of the live verifier.

Build samples independent uniform k in {0,1}^lambda. For each bit i, build a graph with root r_i and two public terminal vertices T_(i,0),T_(i,1). Distinct interior vertices are used for each path:

* an accepting path with guards f_1,...,f_m, ending at T_(i,k_i);
* for every j and b, a decoy path with guards NOT f_j and h_i(z)=b, where h_i(z) is bit i of a domain-separated public hash of the full trace and capsule context, ending at T_(i,b).

Pad every path to equal length using true guards, randomize interior vertex names, randomly permute guards within each path and shuffle serialized paths. Use canonical encoding of graph, guards and context. Publish this and E=sigma_cancel XOR KDF(ctx,k,len(sigma_cancel)). No separate raw key or ciphertext for decoy paths. Open computes the canonical trace and reachable terminals on the graph obtained by retaining exactly those edges whose guards evaluate true. If each graph has a unique reachable terminal, concatenate their bit values and decrypt E; check the native signature/context if desired. This check is not a security boundary. Build and Open are polynomial in lambda and the actual bounded source-verifier size, if that verifier has been implemented. The graph itself uses no hardness assumption other than its ordinary hash/KDF computations.

Every accepting trace activates precisely the accepting path in each graph (all decoy paths have a false NOT f_j guard), so Open returns the exact same sigma_cancel independent of w. Every rejecting computed trace disables the accepting path and activates at least one decoy path, and every activated decoy for bit i points to the same h_i(z). Thus a raw honest-code Open on a rejecting trace produces E XOR KDF(ctx,h(z),len), with h(z) completely public and independent of k. Ignoring all guards makes both terminal values reachable and supplies no unique k bit. These two facts are exact, not empirical claims. They remove the naive unique-target union and invalid-complement attacks without invoking a secret label oracle. But they do not prove security against arbitrary inspection of the complete capsule.

Repeated f_j or constant source constraints can be disambiguated by canonical indexed guard descriptions; that is part of this candidate. Shuffling paths/guards and equal lengths do not help. The FALSE simulator is therefore impossible for this exact format: for any two distinct fixed messages, the output of the public recovery algorithm distinguishes their capsules with probability one.

To remove the obvious identification of the positive-constraint list, attempted a different representation for guard conjunctions: replace a guard g(z) by the conjunction

    (g(z) OR a(z)) AND (g(z) OR NOT a(z))

where a(z) is a randomly chosen publicly evaluated trace/hash predicate, with fresh private-to-this-gadget auxiliary inputs if desired. This is identically g(z), for every choice of a. Reorder, rename and mix these clauses across the full path, including the decoys. Generalize to a constant-size gadget G_g(z,u) for each original guard with its own disjoint auxiliary variables u, using ordinary Tseitin clauses for the Boolean operations; require that eliminating u yields exactly g(z), and that honest evaluation constructs u from z. These changes preserve all-witness correctness and can avoid the literal multiset-of-positive-guard attack, but do not add a secret evaluator. In the simple pair replacement, the two clauses have a public identical common subexpression g and complementary a; one resolution step recovers g. In the disjoint constant-size gadget extension, enumerate its internal auxiliary assignments (or eliminate its private variables by resolution), and recover the exact projected Boolean predicate on its explicitly declared boundary. This is polynomial when the number of private bits per gadget is O(log(lambda)) and its boundary has O(log(lambda)) Boolean bits, and the boundaries and grouping are explicit. For local truth-table source gates this is a small boundary. The paired form with a public hash expression needs only syntactic resolution, not a SHA truth-table enumeration. Recover the polarity by comparison with the original gate truth table. The original static path classifier returns. A path-local syntax mask is thus inadequate; do not run a larger gadget/guard-count/hash-placement experiment on this family.

Consider instead globally shared auxiliary variables across different constraints and paths, so there is no public partition into disjoint constant-size gadgets, and the accepted-terminal implication is a nonlocal proof property. This removes the stated local elimination argument (it is not a proof of security).
