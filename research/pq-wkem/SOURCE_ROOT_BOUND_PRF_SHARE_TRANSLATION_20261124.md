## Target compiler

Let R_x be the complete ORIGINAL three-ground verifier with all claim, relevance, maturity and source authentication checks. Fix a polynomial-size Boolean circuit for it, including public-input assertions and the accepting-output assertion, and write its computation as m >= 2 local constraints on a canonical full assignment T (input evidence plus trace). Use individual wire-occurrence equality constraints or common wire indices. Public constant assignments and output assertions are separate constraints, so each individual gate/check is satisfiable in isolation; this is important for the screen below and does not mean the entire relation is satisfiable. An authentic w gives a complete T satisfying all constraints. A fabricated T does not suffice.

Let r=(salt,MerkleRoot(x,context,salt,T)), with uniform lambda-bit salt allowed for ANY T. r is auxiliary encoding metadata, NOT a substitute for original evidence or original on-chain commitments. An opening pi_i for constraint i contains the required canonical wire values and authenticated Merkle paths under r. L_i(r,pi_i) checks those paths, positions, and the local constraint. If all L_i are satisfied under one binding r and consistent canonical positions, their union supplies a satisfying trace (unless a hash collision); this is only the verifier property, not the release property.

Build samples delta and independently uniform lambda-bit k_1,...,k_(m-1), and masks the fixed signature by B=sigma_cancel XOR XOF(domain,context,delta). Define

    P_i(r) = H_pad(i,k_i,r)          for i<m,
    P_m(r) = delta XOR P_1(r) XOR ... XOR P_(m-1)(r).

Thus every complete authentic qualifying w (with arbitrary salt) would recover delta by XORing all m shares at the SAME root. For independent ideal per-root masks the old cross-root split does not cancel: in XOR of one share from each i at roots r_i, the residual is XOR over i<m of [P_i(r_i) XOR P_i(r_m)]. If any r_i differs from r_m, a corresponding independent value remains. This is an algebraic motivation, not a security proof; arbitrary adaptive evaluation and related roots/auxiliary inputs are not covered by it.

The required actual Build output is B and a polynomial public descriptor D. A classical public local evaluator E(D,i,r,pi_i) must release the corresponding P_i(r) for every locally valid opening, without releasing the same share for an arbitrary other root at which it lacks a valid opening. In particular it may NOT leak a seed allowing evaluation at all roots. Local validity must control the share path cryptographically; a public if-check followed by recovery of a raw long-lived key is insufficient.

## Serialization attempt 1: fixed local keys and row corrections

A table indexed by a locally satisfying value tuple a could wrap k_i under H_row(i,a). This can be generated by Build, but a is independently choosable for each constraint. The evaluator or an adversary can unwrap k_i once and use it for every root. Adding a root identifier to the subsequent hash P_i(r) does not constrain that recovered key. The previous split attack applies unchanged once the raw key is available. Reject before implementation.

Wrapping k_i instead under H_open(i,r,pi_i) would need a ciphertext or translation for future r,pi_i. Even within one satisfying local tuple, arbitrary other leaves and salts change r and paths. There is no known opening at Build time. For a single XOR row correction c_a the required equality is c_a = k_i XOR H_open(i,r,pi_i) for EVERY eligible opening with that tuple; two different domain-encoded inputs already impose equality of their hash outputs. Binding the path by hashing cannot enforce this equality. A separate correction per path is forbidden exponential material. No larger fixture or new basis was attempted.

## Serialization attempt 2: direct root-keyed share evaluation without returning k_i

The better candidate never unwraps k_i as a return value: D should evaluate H_pad(i,k_i,r) directly, using a local Merkle opening to unlock the evaluation. This is the exact missing operation. A secret key written in clear in the program would be visible. A public hash-expansion seed which regenerates it is equally visible. Could a compact public table of masked evaluations avoid both? Analyze the actual random-oracle implementation, not the ideal local-share interface.

Take H_pad to be a domain-separated lambda-bit public random oracle, with canonical encodings of i,k,r; source hashes and Merkle hashes may use other independent domains in the same ideal oracle. The following is a scope-specific classical attack on direct H_pad-share evaluation, not a general hash-only impossibility. Assume classical PPT Build and E, and correctness >= 1-epsilon for each independently generated locally valid opening as required by this candidate. Assume q_B bounds Build's total oracle calls (also include public setup values generated for D, B and VK/message); q_E bounds one invocation of E. Choose k_i before querying H_pad as specified; these are independent of source coins. Build cannot program the external oracle, and no private runtime is available.

For each i<m, the adversary generates a full syntactic trace T_i satisfying constraint i alone, by assigning its local wires to any satisfying tuple and filling other wires arbitrarily. It computes canonical Merkle paths and a fresh uniform salt AFTER Build. This may be a globally invalid trace, which is permitted for this local interface. With probability at least 1-q_B/2^lambda, the salt was not used in any relevant H_pad query at Build, even if the other root bytes depend on source hash queries. Condition on setup coins and transcript and on this freshness event. Then H_pad(i,k_i,r_i) is still a fresh uniform value until queried. In particular the chance E returns that exact value without asking that target query is at most 2^-lambda, by deferred decisions on this unqueried coordinate. This statement includes any public masked correction data actually computed from the setup transcript; it does not cover programmed ideal evaluators or a different share function.

Execute the published classical E with the opening while instrumenting its actual hash calls (or inline and inspect its arithmetic and hash invocations). This is an adversary running public code itself; no honest source, attacker-supplied query log, adversary internal-state extraction or quantum measurement is assumed. Correctness implies the target query is made except with probability at most epsilon + (q_B+1)/2^lambda. Its input explicitly contains k_i. Search the observed pad-domain queries for the required i,r_i and the returned share. The true key is among them; a different queried key matching that value has negligible probability bounded by a birthday union bound over q_B+q_E pad queries, plus the fresh-output guessing term. One can also retain candidate keys and repeat at fresh independent roots to disambiguate. This is a constructive classical key-read attack on the proposed hash evaluator, not a reduction from an arbitrary external attacker.

After obtaining k_1,...,k_(m-1), generate one locally satisfying opening for the final constraint at ANY fresh root r_m (it need not equal any earlier r_i). Run E(D,m,r_m,pi_m) to obtain P_m(r_m). Compute

    delta = P_m(r_m) XOR XOR_(i<m) H_pad(i,k_i,r_m).

Unmask B and obtain the exact precommitted native capability. For polynomial m,q_B,q_E and negligible epsilon, a union bound gives overwhelming recovery probability, using only local satisfiability, even if R_x is FALSE. No guessing of the actual cancellation signature or original certificate, and no quantum speedup, is needed. Thus this direct implementation fails the full-public FALSE requirement, and fails on any hard-TRUE case where these same local traces can be generated without an ORIGINAL certificate. Native key/checking data do not rescue a recovery of the exact presigned bytes.

This attack differs from simply XORing old fixed labels: mixed roots alone no longer cancel. The problem is that actual public evaluation of the fresh keyed oracle outputs exposes the keys needed to TRANSLATE all previously recovered shares to the final root. A one-key PRF security argument requires keeping those inputs secret, which a publicly inspectable evaluation of a public oracle does not do. Ordinary hash preimage/collision hardness is not contradicted. The bound is a classical ROM argument, NOT a proof about concrete SHA programming or a claimed QROM security theorem; the classical adversary is also QPT.

## Scope and remaining compiler equation

The attack uses correctness of the proposed per-constraint evaluator for arbitrary locally valid openings. It does not exclude a compiler whose internal share outputs exist only along globally valid source computations, or one whose non-PRF share functions are jointly correlated in a way not exposing a globally reusable key. Weakening E correctness to complete globally valid traces avoids the specific attack premise but no longer gives a local compiler: the original source-conditioned gate must be built cryptographically inside E. A normal Merkle validity check after secret recovery is not that gate.
