## Trial A: re-challenge a disjunctive proof

Suppose both relations have public three-message proof verifiers V_i(a_i,e_i,z_i), with challenges in an additive finite group, and the native protocol has special soundness. Build knows S, not w. It chooses a global challenge e, simulates a source transcript (a_R,e_R,z_R), and generates an honest native transcript (a_N,e_N,z_N) with e_N=e-e_R. Publish both local transcripts. This is the algebra of disjunctive proof composition, not a claim of a sound noninteractive proof or a QPT simulator. The capsule must also have a mechanism to recover S, not just demonstrate knowledge of one branch.

Give Open the strongest convenient additional capability for this trial: from ANY w it can answer arbitrary new source challenges at the fixed a_R. The previous transparent proof experiment can convert a first-message opening into a cycle opening, but does not in general give this interface for a simulated a_R; granting it only strengthens the trial.

To re-challenge the whole transcript at e', Open can set e'_R=e'-e_N, obtain z'_R from w, and reuse the native transcript. Native special soundness does NOT apply: its local challenge remains e_N. To force a native challenge change, select e'_R != e'-e_N; then the missing computation is an accepted z'_N at (a_N,e'-e'_R), not another source proof. If Build supplies a second valid native transcript at the same a_N with distinct challenge, the public native extractor already recovers a native witness without w. If exact S rather than just an accepted signature is needed, one additionally needs an extractor that is faithful to the particular setup witness; conventional special soundness alone does not imply that. A masked second native transcript would instead require a source-dependent release mechanism for that mask.

Thus public re-challenge alone changes the challenge of the wrong branch. It is not a repair of the distinct-response mismatch. This diagnosis does not use a bound on response entropy, the earlier code radius, or a proof-system soundness failure.

## Trial B: exact shared-mask correlation

A different algebraic response form could avoid the above problem: the native response is itself masked by prover randomness recoverable with w. Test the following fully specified outer algebra over equal-length bitstrings (padding/canonical encoding fixed in x). It uses no discrete-log or lattice operation. Sample r uniformly in {0,1}^m; let u=enc(S) xor r. If there were a source proof response v with
    v = r xor enc_R(w)
then publish (u,v) plus its source proof transcript and other capsule context. Open from w computes r'=v xor enc_R(w) and returns dec(u xor r'). For an honestly generated matching v this returns S exactly. Native VK/message are public. Build would erase r and S afterward. Native re-challenge is not actually needed after r is recovered; the point is to exploit the structure of proof randomness rather than independent transcript hashes.

Here is the obstruction in the real Build distribution, BEFORE implementing it. For any fixed w the exact response equation also gives
    enc_R(w) = v xor r.
If enc_R is a witness-preserving invertible encoding, Build that knows both r and v can extract an ORIGINAL witness just by XOR and decoding. This is incompatible with the required witness-free setup on FALSE instances; on hard TRUE instances it is an efficient original witness finder. A usual simulator of source proofs may produce (a_R,e_R,v) without w but cannot simultaneously provide a chosen known r satisfying this equation for an unknown hard witness. If it could, it would already provide that witness. Picking v independently and setting r afterward requires knowing w. Choosing v and the native mask independently avoids the extraction at setup but fails the intended opening equation.

Moreover, with the same published v and the same native u, two different witness encodings give different recovered values:
    S_enc(w1) xor S_enc(w2) = enc_R(w1) xor enc_R(w2).
Thus even a witness-aware setup selecting one reference source witness cannot fulfill the every-witness same-capability condition for distinct encoded witnesses. This issue is not a spliced internal label attack; it holds for complete honest ORIGINAL witnesses.

For an alternative source response v=r xor P_x(w) with a possibly lossy map P, exact opening for all w implies P_x is constant over the original witness set (for each fixed capsule if P depends on public capsule context). Build knows the constant v xor r. If it is public or efficiently obtained from public x and context, recovery is public; if it is not, an actual witness-independent sampler of the hidden constant and a witness-enabled evaluator of it have to be supplied and jointly simulated. Merely declaring the response as a simulated proof does not supply either. This last case is not ruled out; unlike invertible enc_R, P need not expose a full source witness to Build. It is exactly the unconstructed common-value operation, not a new assumption to count as progress.

The same algebra applies if the native proof is a bitwise additive-share construction with public u and secret mask r, provided recovery is exact. No claim about all hash proofs or all nonlinear response functions follows.
