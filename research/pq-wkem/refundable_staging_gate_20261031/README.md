# RSEG: Refundable Staging Escrow Gate (offline PQ witness-KEM research)

**Status:** A conditional **protocol** construction advancing SCFB. It removes SCFB's extra honest *post-compile final-funding-input-wallet* gate by routing the initial deposit through a refundable staging UTXO whose cooperative finalization requires the **existing** honest N-of-N preauthorizer's signature. This is **not** a secure witness-KEM, an ORIGINAL-witness extraction reduction, QPT native crypto, or a Bitcoin deployment.

- First prepare a *pre-stage* scope descriptor with two paths: N-of-N cooperative transition and designated-owner refund after relative timeout. Commit to the scope template, signer verification keys and watcher policy. Pre-sign/verify the refund before the staging deposit.
- Next construct the witness-independent stage-to-final transaction `F` and its outpoint `u_F`; bind ORIGINAL relation/claim, both outpoints, branch, anchors/window, context, challenge verification key and opaque capsule to the manifest. Complete every safe pre-signature and obtain the setup certificate plus an honest watcher's durable-data receipt.
- The existing one-honest N-of-N signer signs `F` **last**, only after checking the entire manifest and stored bytes. If anyone aborts, the already funded stage has a pre-signed refund route after timeout, subject to censorship/fee/inclusion assumptions. Challenge-path signing is **not preauthorized**.

**Conditional path-cut theorem:** An unsafe stage-to-final spend without that honest signer's readiness event requires a native QPT EUF-CMA forgery, script/path/sighash/txid binding failure, forged certificate/receipt, or violation of the honest policy. The complete quantum public view and related capsules are visible, but the capsule itself remains an **uninstantiated** opaque `WKEM.Enc`; it may be malicious or leak the challenge key. The construction does not solve generic-NP SOURCE release or unauthorized hard-TRUE/FALSE recovery-to-ORIGINAL-witness extraction.

**Executed exact test:** `python checker.py` in the bundled evidence archive passed **48 assertions** and rejected **26 mutations**, twice with byte-identical `output.json`. It uses actual **classical Ed25519** signatures with intentionally public deterministic test private seeds, plus mock JSON-hash txids. It performs **no** native Bitcoin, PQ-signature, SYS/BTC evidence, LWE or quantum-security verification.
