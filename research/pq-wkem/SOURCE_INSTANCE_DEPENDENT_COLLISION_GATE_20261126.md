## 2. Explicit collision family

Fix injective canonical encodings of the statement x, context ctx and all typed fields; require canonical parsing, including checked lengths. Let H be a lambda-bit hash. Domain separation below means distinct encoded byte strings, not an assertion of statistical independence for concrete SHA. The source verifier is deterministic and bounded by the specified relation.

    F_x(0,u)     = H("collision-base",ctx,x,u)
    F_x(1,u,w)   = H("collision-base",ctx,x,u) if R(x,w)=1
                 = H("collision-reject",ctx,x,u,enc(w)) otherwise

Here u is exactly lambda bits. Noncanonical inputs are rejected and do not count as openings; the verifier never accepts a noncanonical alias of a base input. The complete source proof remains off chain.

For EVERY qualifying original w and EVERY u, the two distinct canonical inputs (0,u) and (1,u,w) collide. Conversely, consider arbitrary QPT output of two distinct canonical classical inputs with equal F_x values. If either is an accepting source-mode input, parse that input and output its original certificate w. Otherwise the encoded H inputs are distinct: two different base inputs encode different u, a base versus reject has a distinct domain, and two distinct reject inputs have distinct injective encodings. Thus output a concrete hash collision. The extraction is straight-line from the two OUTPUT strings; it is not a claim of extractability from quantum queries, adversarial representations or logs. This conditional output implication survives arbitrary correlations in the supplied context, in the literal sense that it is an identity on the two classical strings; any cryptographic probability conclusion still requires an independently justified collision assumption for the full experiment. No source coin secrecy is assumed. For a false statement there is no accepting source branch, so any such collision is a hash collision.

This construction is a public witness-conditioned collision relation with a real original-certificate extraction property for the stated collision-output task. It is NOT an encapsulation, nor does this implication say that recovery of S outputs two F_x inputs. In particular, it does not prove the required full-public recovery or native-forgery security. A published checking key or another capsule can correlate with S without ever producing a collision. The original hard-TRUE adversary is not required to volunteer any opening.

## 3. Actual Build/Open trials

Trial A: choose u uniformly, set h=F_x(0,u) and P=S XOR HashStream("collision-pad",ctx,x,u). Publish (x,ctx,h,P,u), including the usual native checking context. A legitimate holder of w constructs (1,u,w); the two openings agree in the u field and the resulting HashStream decrypts P to the SAME S for every w. Build and Open are polynomial for a polynomial verifier. However the entire native pad is publicly computable from the serialized base opening. A classical adversary ignores the source test and recovers S from P and u. This is a full-public failure even on FALSE, without a collision or any source evidence. Using only the common digest h as pad is equally public.

Trial B: remove u. Publish only (x,ctx,h,P) and the checking context. The intended Open must now construct a valid source-mode opening (1,u',w) at the same h, then use its u' field to compute the pad. Correctness of the collision identity does not supply this operation. For any qualifying w it is exactly the ordinary problem H("collision-base",ctx,x,u')=h. If u'=u, it has inverted the independently sampled setup input; otherwise the two base inputs yield a hash collision. The witness only changes a branch selector that is not present in the common H input. Knowing the whole original witness does not reveal u.

For the independent synthetic experiment (not native signature security), take u uniform, independent of the fixed genuine certificate, and take a uniformly random S of the pad length, with no u-dependent hints or S-checking side information. Then P is independently uniform even given u and the hash oracle. If a classical PPT Open could produce the intended exact common u with substantial probability, a preimage challenge for this domain and x could be used as h, with an independently uniform P and the independent genuine w, to run Open and obtain that preimage. In an ideal separated random-oracle model the exact u hit probability is bounded by (q+1)/2^lambda for q classical queries: equivalently choose h uniformly, program the point for u, and couple to an unprogrammed oracle independent of u until the first hit, counting the final guess as another candidate. An alternate preimage is a separate collision event, not exact u recovery. This demonstrates the missing honest opening in the candidate without claiming that a native VK has this synthetic independence distribution. No QPT proof of the actual capsule follows. A new source-conditioned shortcut to the independently sampled u would need construction, not an assumption of hash inversion.

Trial C: try digest-only equivocation instead, so Open needs no secret base opening. Extend F_x with another pair of canonical modes:

    G_x(2,h)   = h
    G_x(3,h,w) = h if R(x,w)=1
                 otherwise H("digest-reject",ctx,x,h,enc(w)).

For every qualifying w, anyone can convert the public digest reference into the second valid mode. This is an actual PPT witness-dependent rewrite, no unknown base input. However it is not a preimage conversion: both inputs carry the publicly visible h, neither carries the hidden u of Trial B. The proposed pad remains unavailable. In addition this extension destroys the collision-output reduction itself: given ANY base input a, compute h=F_x(a) and collide a with (2,h), without source evidence or a hash collision. Even if the base modes are excluded, evaluate any rejecting input in mode 3, then collide it with a digest-reference input for that output. Restricting the collision game to the specified pair of modes can restore the trivial witness implication, but the adversary seeking the native capability is not obliged to produce that pair. Restricting honest Open to those modes is not cryptographic access control. This explicit attempt at public equivocation trades away both the common hidden preimage and the unrestricted collision implication.

No independent hash preimage puzzle is proposed as ORIGINAL evidence. Trial B's preimage demand is precisely why it is rejected: the original future certificate must suffice without solving an unrelated setup puzzle. Trial C cannot repair that by changing what counts as an opening. Making the pad depend on the entire source opening instead of its common field would revert to the recorded variable-witness pad problem; do not spend another run sampling it. Choosing a base u from one setup-selected source witness similarly violates every-future-witness completeness.
