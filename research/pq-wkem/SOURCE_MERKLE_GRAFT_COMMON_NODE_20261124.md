## Binding of fixed routes and the public sibling-pair calculation

Assume a correctly formed capsule for the route grammar, and consider two qualifying original witnesses w,w' with different u(w),u(w') whose computed output is the same K. If their directions are fixed across all witnesses, walk the two folds backwards. At each step equal outputs on distinct encoded inputs exhibit a concrete collision in H. Otherwise the ordered inputs are identical, hence both preceding states and sibling values agree because the directions are the same. Induction reaches identical u, a contradiction. This argument allows arbitrary witness-dependent choices of siblings from P; fixing only directions already suffices. It is a deterministic implication about explicit paths, not QPT extraction from a key-recovering adversary.

Repair: allow directions and sibling indices to depend on the complete source certificate. Then equal parent digests can legitimately have different descendant paths, as in an ordinary binary Merkle tree; no collision is required. For the two successful paths above, walk backwards from K until the first differing direction at level j. Unless there is a hash collision along this walk, all levels i>j share identical ordered inputs, including the same directions and sibling values. If no direction differs, the fixed-direction argument forces u equality. At j the two ordered inputs must be equal (or provide a collision). WLOG the first path enters the left child and the second the right child. Therefore

    v_(j-1) = s'_j in P,
    v'_(j-1) = s_j in P,
    v_j = v'_j = H_j(s'_j,s_j).

This is a new authority problem in the graft grammar: the supposedly secret common interior node at the first root-down branch is obtainable by combining TWO public sibling values. Neither source witness nor its route is needed to generate the list {H_j(a,b): a,b in P}. In particular if j=d, an arbitrary caller enumerates at most |P|^2 candidate keys, checks T and unmasks E. Except for a key-check collision, T identifies K; alternatively the ordinary public native verifier tests the decrypted byte strings and any accepted one is an unauthorized native capability. No query log, adversarial representation, oracle programming, source extraction or signature forgery assumption is required for this recovery algorithm. The attacker need not know the two valid witnesses or which pair works. This is a hard-TRUE failure conditional on existence of the two correct paths, not a demonstrated FALSE break of an actual original instance.

More generally if all upper route fragments from each level j are publicly specified as a polynomial-size explicit list of possible suffixes (including the simple fixed public upper route), enumerate j, the ordered pair of pool values, and those suffixes; fold from the candidate v_j and check T or native verification. The total number of candidate folds is at most d*|P|^2*L if each list has at most L elements. Each fold uses at most d hashes. Correctness for the two witnesses and no collision on their folds guarantee K is in this list. A poly-size DAG of route fragments can represent exponentially many suffixes; this enumeration argument does not extend to that case without a separate algorithm. Nor does the argument extend to siblings absent from the public pool.

## Repair screen: conceal the common upper route or its sibling values

A genuine change to the authority is to make the shared upper route unknown, while publishing only a compact description of exponentially many possible suffixes, or to omit some sibling values from P. The first repair defeats the preceding enumeration bound, not by assuming more hash security but by removing the explicit polynomial suffix list. Binding still forces the two paths to agree on the exact upper directions and sibling *values* from their first root-down divergence up to the hidden root. Thus a public compiler would need to make the same correct upper suffix recoverable by every original certificate that reaches that branch, without revealing it from the descriptor. This is not accomplished by committing to an ordered suffix: a commitment supplies verification of a proposed suffix, not the missing algorithm that obtains it from the original evidence. Selecting a route by an ordinary public function of x_W or other known capsule bytes puts it back in the enumerated set. Selecting a route by a hash of the entire witness gives no reason for its value to agree across distinct witnesses; no further random-pad fixture was run. A compact graph with unknown valid upper suffix is a search problem, not yet a common-value release compiler.

Second repair: omit one or more sibling values and instead authenticate them against an actual committed original source tree. This can work as a *conditional* decommitment construction if the builder knows a hidden node K and EVERY actual qualifying witness necessarily provides an authenticated path computing K, while nonwitnesses cannot obtain K. But such an original-source property is not established: a future competing BTC history is not an opening of a tree of future headers committed by the depositor at Build; its terminal root is variable. The fixed public anchor alone cannot supply a hidden node. A new capsule-created commitment to such a tree would need to be generated before the unknown future evidence and bind every original path without a new issuer or an exponentially enumerated tree. The exact missing operation is this witness-blind source-to-hidden-graft compiler, with joint simulation of the public route descriptor and sibling commitments. An idealized path provider is not a construction. No inference that all authentic source nodes are public before qualification, or that no source-specific hidden-node construction is possible, is made.

The current screens distinguish two mathematical requirements: collision-free multi-path joining is possible using different directions, but public sibling-pair closure makes such joins exportable whenever the common upper route can be enumerated. Removing that closure requires a genuinely source-dependent hidden path/sibling compiler. Do not repeat this route with longer hashes, larger pools or another fixed direction assignment. It is not a standalone Merkle proof improvement, a solved WKEM, a universal impossibility result or a source-relation change.
