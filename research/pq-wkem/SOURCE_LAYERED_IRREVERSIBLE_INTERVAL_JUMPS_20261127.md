## 1. Exact compiler and target state

For any polynomial bounded deterministic Boolean V_x(w), construct a 3CNF by gate-equivalence constraints and an asserted true output, with gate variables as auxiliary witness bits. The CNF is satisfiable iff an ORIGINAL certificate exists; for each such w a satisfying assignment can be computed by honest gate evaluation, and a satisfying assignment reveals its original w. Clauses of length <=3 suffice. This is a reduction of the original relation, not a change to the admissible source evidence.

Use ordinary base-10 digits: one digit per Boolean variable and one per clause. For variable i introduce two positive integer weights, true and false, both with a 1 in its own variable digit, and each with the number of literal occurrences made true in each clause digit. For each clause add two slack weights with its clause digit equal to 1 and 2 respectively. Target digits are 1 per variable and 4 per clause. For any subset no digit carries: each variable digit <=2; each clause digit <=6 (at most three literal occurrences contributed across both choices, plus slack 3). Thus exactly one weight per variable must be chosen; a clause count c in {0,1,2,3} can reach 4 with the slack subset iff c>=1. This proves both directions and every-witness completeness without assuming a fixed canonical witness. Integers have polynomial bit length but may have exponential magnitude.

Let a_1,...,a_N be these weights, T the target, and D=2^m greater than both T and sum_i a_i. For layer j, a legal edge takes state s to s+b*a_(j+1), b in {0,1}, if within [0,D). Each layer is used exactly once. A legal path from (0,0) to (N,T) yields a satisfying CNF assignment and hence ORIGINAL w; every qualifying w yields such a path. This equivalence is combinatorial, not yet cryptographic. It also prevents repeated positive-weight jumps that would otherwise relax a 0/1 subset to unbounded subset sum.

Reference (not the candidate practical Build): independent lambda-bit state keys k_(j,s), one encrypted directed edge per (j,s,b), e= k_(j+1,s+b*a) XOR H_edge(ctx,j,s,b,k_(j,s)), and public k_(0,0). Final E=sigma_cancel XOR H_final(ctx,k_(N,T)), with independent length expansion. Context binds the complete existing capsule/claim/native endpoint scope. Honest path computes exactly the target key. This costs O(ND) edges and is rejected as practical; no new QROM security claim for even that table is made. The research question is whether a succinct hash-tree delegation can replace those edges WITHOUT changing which states are cryptographically accessible.

## 2. Concrete dyadic delegation Build/Open attempt

Use independent binary hash-seed trees per layer. For each dyadic interval I=[u,u+2^h) aligned to 2^h within [0,D), write k_(j,I) for its seed. A parent seed derives both child seeds through public domain-separated hash calls on (ctx,j,I,left/right,seed). A leaf is exactly the state key. Build chooses one random root per layer and can compute any requested node in O(m) hashes.

For edge b of layer j, cover the legal domain by disjoint maximal aligned dyadic intervals I such that J=I+b*a_(j+1) is also an aligned dyadic interval in the NEXT layer (no wrapping). For every such I publish

    e_(j,b,I) = k_(j+1,J) XOR H_jump(ctx,j,b,I,J,k_(j,I)).

This is an actual hash-encrypted seed grant, not a black-box conditional evaluator. A source interval seed decrypts the destination interval seed, and the recipient can derive the destination leaf at the desired translated offset. Build publishes k_(0,{0}) and E as above. For honest Open, the actual source leaf belongs to one cover interval for its selected edge. If the interval is a singleton, the leaf key decrypts the edge; otherwise Open needs its ancestor seed. An attempted completion adds upward grants

    g_(j,I_child) = k_(j,I_parent) XOR H_up(ctx,j,I_child,k_(j,I_child)),

for those child-to-parent steps needed to reach an edge cover root. These are public stored records, not an assumed secret upward operation. Honest Open uses the grants to climb, decrypts the jump, descends to the intended next leaf, and repeats. If all necessary grants/edges are present, correctness holds for every original witness and same exact sigma. This is distinct from independent full-address FSS: the encrypted item is a preexisting next-layer subtree seed, and no public routine computes a hidden opposite pad.

Two issues determine whether this is a valid implementation, not merely a representation of a directed graph.

### 2a. The forward-only root grant itself widens the state language

Possession of k_(j,I) grants ALL leaf keys for s in I, irrespective of the precise leaf from which the interval seed was acquired. No splicing of two witnesses, inversion, oracle programming, or combining two independently valid traces is necessary. A complete serialized capsule with an upward grant that enables a root containing even one spurious state s' permits the attacker to start the remaining path there.

Define R_j = {sum_(i<=j) b_i*a_i} and B_j = {T-sum_(i>j) b_i*a_i within [0,D)}. Exact prefix legality is s in R_j. A false instance satisfies R_j intersect B_j = empty for every j. A sufficient condition for a direct recovery attack is that a seed accessible without a qualifying witness covers I with I intersect B_j nonempty, and the remaining b_i path is computable and has its needed grants. The attacker derives that leaf, follows the actual remaining edge programs and obtains k_(N,T). In particular T belongs to B_j for EVERY j via all remaining zero edges. Therefore an accessible whole-layer root, or any seed covering T followed by available zero transitions, permits exact recovery on FALSE x with no source evidence. The attack simply derives the target leaf in the terminal layer if it reaches its root. All-zero paths are publicly known.

For a concrete version, make zero-branch grants use the maximal cover I=[0,D), which is aligned for shift zero. To make Open work even for an original witness whose first subset decision is zero, the attempted universal upward grants let the public initial leaf climb to the root. The zero jump transfers an entire next-layer root. Further zero jumps transfer whole roots up to the terminal layer; derive k_(N,T) and recover E. This same public algorithm works on ANY false compiled original statement whose capsule includes those grants, no need to find a satisfying assignment or rely on the existence of a valid witness. An honest-code check of the actual sum/claimed witness at the end does not protect the native capability. A simulator assigning inaccessible target keys independently of that public view fails, because the real view computes the exact key. This is an explicit classical attack against the QPT security requirement, not a query-log extractor for arbitrary adversaries.

Selective grants only for genuine reachable states might prevent that particular climb; however granting the interval root via ANY reachable child still delegates all its leaves. Adding a public Merkle proof or state index to the leaf does not repair the possession of the root if those leaf credentials are themselves derived from it. If the proof needs a distinct source-dependent unexportable credential, producing that credential is a new required release operation, not accomplished by this construction.

### 2b. Exact-domain aligned translation need not be succinct

For an ordinary dyadic interval of width 2^h, both u and u+b*a must be divisible by 2^h. For b=1, this implies 2^h divides a. Thus an odd a forces every I in the exact translation cover to be a singleton. For the complete domain 0<=s<D-a this means D-a edge ciphertexts. The compiler includes odd weights (e.g., a unit clause-slack weight at the least significant clause digit when clause digits are low-order). Choose D as a power of two above twice the sum if necessary: this does not change any legal path from zero, and makes the explicit complete-domain cover for that weight exponential in m in large instances. This is a cost of the specified cover construction, NOT a proof that all cryptographic representations need exponential size.

A natural repair is to shift the coordinate origin of the next tree by a so translated intervals are aligned. But both zero and one choices must land in the SAME destination state-key system, independent of the chosen path. If each b uses its own shifted tree, the two keys for a shared numerical destination s are generally different independent hash-tree outputs. Build must provide an actual conversion between these leaf keys or a final merge. A conversion by grants of a shared ancestor reintroduces section 2a; converting every leaf individually is the original explicit table. A path-specific coordinate origin o_j=sum of chosen weights makes each edge simple in local coordinates, but then the sum state is in the origin, not the local coordinate; the final target origin needs a cryptographic common leaf token, not a public test followed by decrypting a key available for every origin. No serialized conversion with joint simulation is supplied by merely shifting the origins.

## 3. Specific repair criterion; no claim of impossibility

Instead of maximal dyadic covers, consider delegation only to intervals certified as wholly inside R_j, or more weakly intervals not adding any suffix-completable false state. The former is a valid *semantic* repair of widening (if all accessible roots satisfy it), but it needs a witnessless polynomial-time way to construct the needed grants for the ORIGINAL compiler without enumerating reachable sums. The latter needs to rule out intersection with B_j on false x, again before a witness is available. A public partition into exact reachable intervals with polynomial-size publicly recognizable membership would itself decide target reachability for this general subset-sum compiler. This conditional complexity observation is not a general hardness theorem against encrypted covers: in a different scheme membership might require a hidden seed obtainable only through a valid path. That would be useful if it had a concrete correlated Build and joint simulator.

For the current design the precise missing operation is **exact-state-to-next-state key translation with one-use layers and common destination keys, without exporting a seed covering unauthorized states**. Neither a public upward grant nor a separate shifted tree provides it. The closest prior label-switch attack is avoided only at the level of the directed singleton graph; the proposed polynomial compression introduces an independent subtree-access attack. Reject this particular dyadic/root-grant representation rather than sweep widths, order weights, or test a larger interval fixture. Future work on this path would need a genuine forward-only, hash-based, compact state transition whose *entire public representation* preserves exact path authorization even under arbitrary state/key processing. Merely naming a constrained program, a succinct automaton with secret outputs, an obfuscated jump oracle, or a hash fast-forward primitive does not construct that operation.
