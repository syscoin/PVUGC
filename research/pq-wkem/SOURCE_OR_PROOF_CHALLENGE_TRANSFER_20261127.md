## 1. Serialized candidate and intended extraction

Let R0(x,w) be the complete ORIGINAL relation with all three independent grounds, not a simplified predicate. Let r be uniform lambda bits and y=H_key(ctx,r). R1(y,r) asserts this equality. Use ordinary public-coin three-message proof protocols Pi0 and Pi1 with challenge space {0,1}^k, efficient honest-verifier simulators S_i(statement,challenge), correctness, and special soundness on two accepting transcripts with identical first message and distinct challenge. These are abstract proof interfaces, not claimed concrete QPT constructions. For example, a conventional commitment-based NP proof via Hamiltonicity has a binary challenge and a classical two-transcript extractor; parallel repetition provides vector challenges, with distinct vectors differing in at least one coordinate. The following challenge equations apply even granting ideal honest-verifier simulation and perfect special soundness. No group, lattice, private evaluator, or online actor is needed for these equations.

Build:
1. Sample r, compute y and E=sigma_cancel XOR KDF(ctx,r,length).
2. Sample c0 uniformly, run S0(x,c0) to obtain (a0,c0,z0), including on a false source instance (grant the chosen-challenge simulator can do so).
3. Generate honest Pi1 first message a1 with fresh secret prover coins. Compute total c=H_chal(ctx,x,y,a0,a1) in {0,1}^k (independent domain). Set c1=c XOR c0; compute honest response z1 using r.
4. Serialize C=(ctx,x,y,E,a0,c0,z0,a1,c1,z1) plus public proof parameters and native binding. Verify local transcripts and challenge equality before erasing r and prover coins.

This is a real straight-line polynomial serialization given the proof algorithms. It works without knowing a qualifying source certificate. It is not a complete release algorithm.

Intended Open: with arbitrary valid w, use w to switch the source branch to an honest proof and obtain a second accepting Pi1 transcript (a1,c1',z1') with c1'!=c1. Apply special soundness to extract r' with H_key(ctx,r')=y, then unmask E. Strictly, this recovers the exact frozen capability only when r'=r (a different preimage is not enough). One could choose a binding public preimage relation with computational uniqueness over sampled r, but that is an additional property; the candidate fails before that issue. No QROM security or native recovery result follows from the proof interface alone.

## 2. Challenge-transfer computation and failure

The key branch's commitment a1 must remain exactly fixed. The source branch may make a fresh a0' and answer any honest challenge using w. The new total challenge is c'=H_chal(ctx,x,y,a0',a1). For each prospective c0', the required key branch challenge is c1'=c' XOR c0'. There are precisely two cases.

* Set c0'=c' XOR c1. This gives a valid fresh source response and permits reuse of (a1,c1,z1), with no extraction. Honest source knowledge produces this transcript efficiently, but its key-branch challenge is unchanged.
* Set c0' to any different value. Then c1' differs from c1 and a NEW key response z1' is needed. Honest proof of R0 says nothing about the prover coins or witness of Pi1. Special soundness explains what two such responses imply, not how to obtain the second.

This remains true with a fixed external total challenge rather than a hash. Choosing c0 before a0 in a simulated source transcript can remove the need for w entirely in that external-challenge variant. The Fiat-Shamir hash only changes which c0 is required; it creates no key-branch response.

Granting a source-assisted fork of the SAME a0 is not sufficient either. At fixed total c, changing c0 forces c1 to change. Extraction of two distinct source challenges gives a source witness (already held by Open), not the release preimage. To use OR special soundness one must force the extractor into branch 1, not merely present two distinct total challenges. An AND proof with common challenge would force branch-1 extraction but honest proof construction for the second transcript then requires the very release witness which is missing.

## 3. Attempted repair by precomputed second response

Build can compute an additional response for the same a1 at c1*!=c1 using its retained coins and r, before erasure. This is a genuine way of avoiding the missing second-response computation during Open. But publishing it unmasked gives EVERY observer the same branch-1 extractor. This is classical straight-line recovery, on FALSE as well as hard-TRUE, without source forgery. It does not require breaking Fiat-Shamir or accessing an adversary's internal state.

If Build instead encrypts z1* under a hash of a new honest source response z0*, it must know the actual unmasking value before any future original witness exists. A public simulatable response supplies no source dependence. A response requiring original w may vary over arbitrary w and prover randomness; the builder lacks the required response and an every-witness common-value mechanism. Giving a distinct response with public hash-checking information but not its plaintext just places the unresolved WKEM in the second-response ciphertext. This is the precise missing operation of the repaired construction: a public capsule generated with only (x,ctx,z1*) which allows any original w to recover z1*, while arbitrary unauthorized recovery implies original evidence or an independent justified break. No progress is made by assuming this interface.

An independent Pi1 simulator also cannot fix a1 merely by changing its challenge. To quantify this, condition on the public honest a1 and let p(a1,c1*) be the probability that independently running S1(y,c1*) outputs a valid transcript with first message a1. If p is nonnegligible over the honest capsule distribution, an arbitrary public algorithm without w samples that simulator and checks equality, extracting a release-relation witness using the published transcript when successful. In the exact-preimage case this opens C. With only negligible overlap, independent polynomial resampling has negligible success by the union bound. No independence of a malicious adversary or extraction from its query history is asserted. This rejects independent public resimulation as a repair without parameter sweeps.

## 4. Joint witness-indistinguishability preflight

There is a useful test of the proposed *different* proof transfer operation before implementation. In the key-only diagnostic experiment, generate r uniformly and y=H_key(ctx,r), independent of an original true (x,w) and public ctx. Consider a complete serialized OR proof P generated either from witness (branch 1,r) or (branch 0,w). Assume QPT witness indistinguishability for this distribution with auxiliary w, including all public proof parameters. Suppose a claimed proof-only Open(y,x,ctx,P,w) returns r' satisfying H_key(ctx,r')=y with probability epsilon in branch 1. An efficient public hash check is a distinguisher; by WI its success in branch 0 differs only negligibly. Given an independent random preimage challenge y and independently generated (x,w,ctx), a reduction generates the branch-0 proof itself (it needs no r) and runs Open, inverting that preimage challenge with the same probability up to the WI loss. No rewinding, oracle programming, or adversarial internal representation is used.

Thus a proof-transfer mechanism with this proof-only recovery property cannot simply retain ordinary auxiliary-WI on this experiment, assuming the independent preimage task is QPT hard. This is not a general WE impossibility result. It is explicitly not a proof about an arbitrary native-mask-dependent attacker: E may correlate with r and sigma_cancel and cannot be simulated from y alone without another justified hybrid. Nor does the diagnostic require that the original source statement itself be generated independently in every production experiment. It tests a candidate claiming universal proof-only extraction. For the target mechanism a source witness must enable a specific correlated response that conventional WI proof generation does not supply. The exact challenge-split calculation above shows where such a response would have to enter.

A new direction, if pursuing proof carriers, must specify an asymmetric proof sampler where the *same* original w that permits the conditional response also enables witnessless simulation of all public bytes in the security reduction without inadvertently permitting branch-1 completion. Merely weakening WI or invoking designated-verifier proof semantics is not such a sampler. Reject independent OR challenge reallocation, independent simulator replay, and ordinary WI proof inversion before implementation. Do not expand this experiment into more parallel rounds or replace the hash domain. The unresolved step is a NEW source-conditioned response correlation, not proof verification or special soundness itself.
