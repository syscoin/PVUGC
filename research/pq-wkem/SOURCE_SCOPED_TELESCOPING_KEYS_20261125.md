## Explicit local-scope construction

Let x bind all original claim, chain, source, window and native endpoint fields. R_x(w) is the full unchanged bounded three-ground ORIGINAL verifier. Use a deterministic bounded-fanin Boolean circuit for it. Introduce its complete deterministic evaluation trace t; set z=(enc(w),t), including canonical input/length/padding checks, fixed constants, each gate constraint, and acceptance. Write the conjunction of the local constraints as C_1(z) AND ... AND C_l(z). Each C_i depends on at most a constant number c of bits (decompose canonical parsing and all arithmetic/hash verification into the circuit; do not replace them by a smaller relation). A valid z gives an actual ORIGINAL witness by projection, and each actual qualifying w gives a valid z by deterministic evaluation. No assumed new Core verifier implementation.

A useful point for this trial is that a *single* GGM function can have two distinct local scopes without needing a generic circuit-constrained PRF. For interior vertex i in 1,...,l-1 choose an independent root seed k_i and order the complete z domain with the union of variables of C_i and C_(i+1) first, then all remaining bits in a fixed order. The union has size at most 2c. Define F_i(z) by traversing this ordered seed tree, splitting a lambda-bit seed via a domain-separated hash-based PRG at each step, with a terminal hash expansion to m bits. Include x, capsule ID and the vertex identifier in the domain. For either adjacent clause, enumerate the at most 2^(2c) assignments to the front block that satisfy the desired clause, and publish just the corresponding subtree seeds with their prefix indices. To evaluate F_i on a full index in that scope, choose its front block and descend the corresponding subtree with the rest of z. No source witness is needed to generate these local keys. The two scopes of a vertex refer to exactly the same leaf function because the permutation of input coordinates is fixed per vertex, not selected separately by the caller. This is an explicit polynomial-size scoped key serialization for local gates, assuming only classical hash-based tree expansion for functionality. A GGM security claim in the actual joint QPT distribution would need separate proof; the attacks below require none.

Proposed target: sample a uniform m-bit K, D=enc(S) xor K. Use two endpoint functions F_0 and F_l with F_l(z)=F_0(z) xor K for every qualifying z (first try the stronger all-z equation). The edge i supplies the local difference
    E_i(z)=F_(i-1)(z) xor F_i(z)
only when C_i(z)=1, using scoped keys for its two adjacent vertices. Honest Open evaluates the full z, obtains all l edges, and telescopes:
    xor_{i=1}^l E_i(z) = F_0(z) xor F_l(z) = K.
The endpoint relation is necessary for this exact strategy, not something already established by the ordinary PRG. Interior scopes have real serialization above; the endpoint generation must still be built. This differs from independently hashed complete-proof outputs because the interior values cancel exactly, rather than relying on a hash collision. It also does not require the native signature or secret to be an original witness.

## Endpoint correlation trial and repair screen

Try a shared endpoint root with a fixed permutation putting the union of C_1 and C_l variables first, and define F_l by offsetting the base F_0 by K. This gives the exact all-z correlation and polynomial local scopes for the base function. However, a standard tree key for F_l plus an explicit terminal XOR offset publishes K itself. Omitting the offset produces the wrong endpoint function. This is not a secure Build. To screen the meaningful repair rather than repeat root-offset variants, grant the strongest desired functionality at the two ends: a scope key for F_0 when C_1 holds and a scope key returning *only* the already-offset F_l when C_l holds, without disclosing its base key or the offset. Even these hypothetical endpoint keys do not suffice for the proposed conjunction. They are granted solely to exhibit the following attack, not assumed as available primitives.

At a full index z satisfying C_1(z)=C_l(z)=1, evaluate both end keys and compute
    S'=D xor F_0(z) xor F_l(z).
With all-z endpoint correlation S'=enc(S), even if every intervening edge is unavailable. The attack uses the identical full index, so it does not mix labels across different histories or require interpolation of hidden coefficients. It ignores the entire middle of the computation. It needs no internal query log, hash break, source coins, or knowledge of a representation of the adversary.

Finding an index satisfying just the endpoint predicates costs at most 2^(2c) local evaluations: enumerate their joint variables, choose any satisfying assignment, and fill all other bits arbitrarily. On any satisfiable full conjunction there is at least one such endpoint assignment. If the completed index also satisfies the full conjunction it is a source-finding algorithm, so on an ensemble where original evidence is hard to find this cannot happen with nonnegligible probability for this PPT method. On FALSE instances one can ensure the two boundary clauses are jointly satisfiable by placing independent fixed sentinel-bit checks at the ends of the trace constraint list; the full relation is unchanged by adding the required sentinel bits. Such a false capsule with the proposed all-z offset leaks the exact signature deterministically. This is an attack on the compiler even if the hypothetical endpoint key itself hides K locally and all interior GGM keys are perfectly scoped.

The attack also covers a public evaluator which exposes unordered pairs of endpoint *values* instead of individually named values: at z obtain the two pairs at the first and last edges, try the at most four choices of one member of each pair, and use the native VK/message to test D xor u xor v. The correct endpoint pair is among them. More than one verifying signature is not a rescue: any accepted native cancellation is already a violation, separately from exact-signature recovery. No same-message uniqueness assumption.

If F_l(z)=F_0(z) xor K were required ONLY on fully valid z, the above attack would not automatically return K on endpoint-compatible invalid z. That alternative is not ruled out here. But the standard common-root+offset implementation explicitly has the all-z relation; a *conditionally correlated* endpoint family is the original-source-dependent operation that remains to be constructed. No proof of the actual conditional endpoint generation arises from local scope keys. Do not claim it exists.

## Difference-only edge repair

Try to retain the strong all-z endpoint offset but remove the shortcut by exposing ONLY a single scoped difference E_i, not F_(i-1) and F_i separately. In an ideal interface, XOR of all differences at the same valid index still gives K; the foregoing endpoint enumeration is not automatically available from two differences. This is a materially different disclosure pattern, worth screening. A public two-root GGM key for each difference (even in an unordered pair representation) does not implement this restriction: each subtree seed is public and can be expanded separately. Applying a software XOR before returning values does not hide them from an arbitrary caller. The actual local-key serialization above is thus incompatible with the needed difference-only interface. Similarly, exposing a standalone fixed share masked by a local-clause key is the familiar cross-index attack: each local clause can be satisfied independently, so one can recover each fixed share at a different full index and combine them. Reject that variant unchanged; no bigger fixture.

For this repair to work, a classical PPT generator must derive a compact scoped key for the XOR of TWO independently keyed nonlinear leaf functions, without revealing any separately evaluable constituent root/subtree key, and include a correlated endpoint offset in those difference-only keys without publishing it. It must also demonstrate that querying available differences on many different full indices cannot recover K from their joint public key representation, not merely that their honest XOR computation requires all clauses. Ordinary GGM constrained-key security does not promise this interface, and independent leaf pseudorandomness does not simulate correlated keys containing the native mask. Hashing the pair of seeds into one ordinary seed does not implement XOR of the two original leaf functions; there is no such identity in ordinary nonlinear hash expansion. Replacing it with a public low-degree reconstruction, or independent per-occurrence label garbling, would return to already recorded regressions. No such replacement was implemented.

An abstract difference-only black box with all-z hidden endpoint correlation is not a solution, nor is a generic primitive whose security definition simply demands this source-gated common K. The repair must exhibit the serialized algorithm and simulator. Alternatively put the full source condition inside at least one endpoint's actual scope so the cheap boundary intersection no longer supplies both keys. An explicit prefix cover of the whole accepting set would reveal an accepted full index by choosing any listed prefix and padding it; constructing such a cover without a witness is incompatible with hard-TRUE source-finding in the claimed scope. This does not rule out a nonenumerable evidence-derived scope generator. The local-variables-first GGM construction cannot supply it by itself.

## Handoff and proof boundaries

The useful screen is the distinction between polynomial local scope-key construction and conjunction enforcement. Local key agreement at the same complete index can avoid the known occurrence-splice syntax and still permit a same-index endpoint shortcut. A successor using telescoping must change the *disclosed objects* or supply conditionally correlated endpoint functions, not just re-order predicates, increase tree seed widths, publish unordered pairs, or change hash domains. The missing equation remains a genuine source-controlled nonlinear correlation with actual Build/Open and full joint simulation. The attacks are classical and hence valid QPT attacks; no QROM programming theorem, no claim about concrete SHA security, no proof of generic hash-only WE impossibility.
