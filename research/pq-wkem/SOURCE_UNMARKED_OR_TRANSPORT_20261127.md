## 2. Unmarked OR construction

For colored graphs U,V let T(U,V) be a connected rooted colored graph with a root attached to all vertices of two distinctly colored factor copies of U and V. Root and factor colors are disjoint. Consequently T(U,V) is isomorphic to T(U',V') exactly if U is isomorphic to U' AND V is isomorphic to V'; maps restrict to factor isomorphisms. Use disjoint union with the SAME root color for both top-level components.

Suppose (A,B) were a graph pair for R_x, with an efficient map from each original certificate to an isomorphism A->B and an efficient decoder of any such isomorphism to an original certificate. Suppose (C,D) were a graph pair for the hash relation H("dummy",ctx,t)=y with corresponding encoder and decoder. Both pairs must be generated without witnesses, not assumed from an ordinary circuit-to-cycle reduction.

Define

    X = T(A,C) disjoint-union T(B,D)
    Y = T(A,D) disjoint-union T(B,C).

There are exactly two root pairings. Under pairing 0, T(A,C) maps to T(A,D), and T(B,D) maps to T(B,C); an isomorphism restricts to C->D. Conversely, given g:C->D, use identities on A,B and g,g^-1 on the second factors. Under pairing 1, T(A,C) maps to T(B,C), and T(B,D) maps to T(A,D); an isomorphism restricts to A->B. Conversely, given f:A->B use f,f^-1 on the first factors and identities on C,D. Thus X~Y iff A~B OR C~D. This is an exact finite construction; it preserves arbitrary-map extraction rather than asking an attacker to identify the branch voluntarily. Every original witness would give a polynomial transport in pairing 1 if the source pair encoder existed. Build, knowing t, can transport in pairing 0 if the dummy pair encoder exists.

Unlike the marked-cycle shell, X and Y depend on y but not on a witness to y. In a preimage challenge, a simulator with only x,y could generate these public graphs identically (conditional on the pair generators being actual witness-free algorithms). It need not program a random relabeling of a hidden marked cycle. This resolves that PARTICULAR transcript-sampling requirement at the level of the conditional unmarked pair, not the full public capsule.

Try the previous canonical-isomorphism key K=enc(lexmin Iso(X,Y)), with E=S XOR ExpandH("unmarked-or-pad",ctx,K,|S|). If K were computable from either transport using jointly simulatable public data, arbitrary recovery in the separated QROM pad domain could use the measured-query reduction from the previous note: in the baseline take E uniform; program pad addresses for K to E XOR S; an event gap delta with q queries implies measuring a random baseline query yields a target address with probability at least delta^2/(4q^2). Decoding K yields an entire isomorphism, and restriction by the root pairing gives a real certificate or a dummy preimage. This is conditional on correct complete-key encoding, actual joint setup simulation without t, and the separate native baseline game. It is not an assertion about concrete SHA or auxiliary states correlated with target oracle values.

## 3. Why the previous stabilizer-chain repair does not compose

For finite explicitly represented graphs, the canonical-coset algorithm from the previous note can use a complete public stabilizer chain of Aut(X). This time the two components of X can be exchanged by an automorphism iff BOTH A~B AND C~D: restriction of a root-exchanging map gives BOTH factor isomorphisms, and conversely they construct the exchange. Since C~D holds for the honestly planted y, this equivalence is precisely the original statement's truth value.

Take the first base vertex in the proposed complete stabilizer chain to be the root of T(A,C). Its orbit contains the root of T(B,D) iff the original statement is true. If present, its public transversal representative is an explicit automorphism, and its factor restrictions immediately supply an original witness and a dummy preimage (under the pair-decoder premises). Even without reading the pad, the complete chain reveals that data. If the original statement is hard-TRUE, Build would need to generate this chain without knowing an original certificate; an actual efficient Build that did so would itself solve that source-search task. On FALSE the root-exchange representative is absent. A simulator given only y cannot simply supply the complete chain from the known-with-witness compiler; it needs the same missing search information. The complete chain thus destroys the witness-free transcript property just gained in section 2. This is an exact composition failure, not an assumed GI hardness result.

Try publishing only the subgroup preserving both top roots. It no longer reveals a cross-root representative. But right composition with this subgroup preserves root pairing, so the lexicographic normalization of pairing 0 and pairing 1 lies in disjoint cosets. The canonical maps cannot coincide, even if both are valid global isomorphisms. For an independent ideal pad domain, hashing distinct encodings gives independent pads, equal with probability 2^-ell for ell output bits. Publishing a second ciphertext for pairing 1 requires Build to compute its key, which the source encoder needs an original witness to do. Publishing a fixed explicit root-exchange automorphism as a converter leaks both factor maps directly as above. Publishing only a hash of that automorphism does not implement composition by it. These repairs are rejected without testing larger graphs.

This distinguishes two missing requirements: witness-free generation of an OR transport transcript, and witness-independent secret normalization of its transports. The former alone is insufficient; the normalization data must be jointly simulated without already solving either branch.

## 4. Concrete succinct dummy encoder and source-matching attempt

Try removing the separate unknown graph compiler for the dummy branch. In an ideal hash model, take uniform t in {0,1}^lambda and H in a separated domain with 3lambda output bits. The probability another input in this restricted domain hits y=H(t) is at most (2^lambda-1)2^-3lambda by the union bound. Conditioned on unique preimage, let C have all lambda-bit vertices, no edges, and color 1 iff H("dummy",ctx,z)=y. Let D have the same vertex space and no edges, with color 1 iff z=0^lambda. The descriptions are polynomial-size color predicates computed from y alone. Build knowing t can construct the permutation swapping t and 0 (identity if equal), encoded by a short reversible conditional circuit. Every isomorphism with efficient inverse evaluation returns t by evaluating its inverse on the marked D vertex. This is a literal witness-free succinct pair for the hash branch in the stated model, not an assumption of hard GI. It does not provide the original source pair. Its explicit vertex count is exponential, so the previous full-permutation key and complete explicit chain are not PPT. Canonicalizing arbitrary circuit descriptions is not supplied by the explicit-graph algorithm. The unique-preimage calculation is only an ideal-domain statement and the real SHA/native correlation argument is not supplied.

For the ORIGINAL side, a direct succinct perfect-matching compiler avoids the unknown source-to-GI reduction and handles an arbitrary number of valid witnesses. Fix a padded injectively encoded n-bit witness space W for R_x. The left and right vertex sets are each {star} union W (use distinct sides; identify names for permutation notation). Define the bipartite edges:

    (z,z) for every z in W;
    (star,z) and (z,star) exactly if R_x(z)=1;
    no (star,star) edge; no other edges.

Adjacency is an actual polynomial-size predicate using the complete source verifier, not a stored witness table. For any qualifying w, the map P_w swapping star and w and fixing all other names is a perfect matching, represented and evaluated by a polynomial conditional circuit, inverse equal to itself. Conversely, every perfect matching pairs left star with a qualifying w, so one forward evaluation of any accepted matching extracts original evidence. Moreover all perfect matchings of this particular graph are exactly these swaps: if star maps to w, right w is occupied, hence left w must map to star; all other left z must then use their diagonal. This avoids a uniqueness-of-original-witness assumption and the local occurrence-label splice at the level of the mathematical matching constraint. Include a tagged dummy branch in W if desired, so Build can produce a matching from t, Open from any original w, and the description is simulatable from x,y alone. This is not a release algorithm: the matching itself depends on the witness.

Try using this matching compiler in the isomorphism transport directly, i.e. require the possible isomorphisms between two fixed graphs to induce exactly the above allowed matchings on a preserved distinguished set of vertices. There is an exact obstruction to that particular conversion. For any fixed pair of graphs X,Y and isomorphisms f,g,h:X->Y, the composite f g^-1 h is also an isomorphism X->Y. If all maps preserve the designated source/target vertex sets, the induced restrictions must have this same closure. For two distinct valid witnesses a,b, the allowed matching permutations P_a=(star a), P_b=(star b) satisfy

    P_a P_b^-1 P_a = (a b),

which fixes star, hence is NOT an allowed matching. This follows by conjugation of a transposition. Even adding auxiliary vertices while insisting on invariant designated sets and exact induced matchings cannot remove the closure condition. In the combined OR relation there are already two distinct tagged witnesses when at least one original certificate and the planted dummy both exist. This rejects a direct matching-to-isomorphism gadget using exact projected maps, not all reductions involving matchings or graph actions. A decoder from arbitrary maps that is not an induced restriction could avoid this particular obstruction, but would require an explicit construction.

The alternative of canonicalizing the matching itself to the lexicographically first permitted P_z simply requires finding a canonical satisfying z. Build knows the dummy and Open knows some original witness, not necessarily the canonical one. Ordering the dummy first lets Build compute it but forces Open to recover the independent hidden hash preimage; ordering original witnesses first on TRUE gives Build the source-search problem. Using a public invariant such as permutation parity (all these swaps are odd) makes the pad computable without a matching. Hashing the full short swap representation distinguishes different witnesses, not a common key. No arbitrary source-to-common-value converter results from the matching compiler.
