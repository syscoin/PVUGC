# Run 680 — public late-witness join cannot itself release an IND-CPA plaintext

Research-only, 2026-10-21. Target `syscoin/PVUGC#1`, draft branch `research/pq-wkem-validation-20260918`, starting SHA `d2ac760d78252daaca420f82cb7b4d5b01487db2`. Exact dependency: CLZ assessment blob `c19d9d9cd515140e3ce62eac960cd548c0add622`, Run 259 blob `c7f3b77f0273ca1cbe6f0b31c1a086b8eb3acbf2`.

**Falsified candidate, not the actual Canetti–Luo–Zhang construction.** Honest classical setup publishes ordinary IND-CPA encryption `C=Enc_pk(K)`. A late watcher provides an ORIGINAL witness `w`, in clear or public encrypted form. Classical public `Join(pk,C,x,w)` may perform arbitrarily nonlinear homomorphic evaluation, and public `Open` purportedly outputs the *same* K for all valid w. No key-dependent FE token, obfuscated decryptor, or retained authority is included.

**Theorem (known-true-instance IND reduction).** Fix efficiently generated `(x,w*)` with `R(x,w*)=1`, and distinct equal-length secrets `K0,K1`, all independent of the PKE challenge bit. Assume every other input to `Join/Open` is independently sampled or efficiently simulable from the PKE public key and `(x,w*)`. If `Open(Join(Enc(Kb),w*))=Kb` with probability at least `1-epsilon` for both b, then a classical PPT IND-CPA adversary chooses `(K0,K1)`, obtains `Enc(Kb)`, evaluates `Join/Open`, and identifies b with success at least `1-epsilon`. Hence arbitrary-QPT IND-CPA encryption cannot supply this public-release interface with negligible epsilon. No QROM, rewinding, quantum access or source extraction is used. This is closure of encryption indistinguishability under efficient public processing, specialized to late witness admission; not a new hardness assumption.

**Critical limitations.** The theorem does not apply to key-dependent auxiliary outputs such as `pk_native(Kb)`, secret-key-derived FE functional keys or obfuscated inverse-related programs; the IND-CPA adversary cannot simulate those. It does not rule out hard true instances without an efficiently known witness. The actual CLZ work has richer, key-dependent protected functions: this is not a CLZ cryptanalysis. It also does not rule out ordinary homomorphic *encrypted* evaluation, which can compute `Enc(K)` but cannot publicly reveal K by this stripped route.

**Executed finite check.** Standard-library 4-bit one-time-pad fixture tests four ORIGINAL witnesses `3,7,11,15` and a nonlinear public join of independently encrypted K and w. All 16 key-conditioned full output distributions coincide; optimum guessed K is `1/16`. Adding the toy correlated public tag `K mod 4` changes the bound to `1/4`, explicitly illustrating the missing native-public-key correlation. Two independently padded capsules remain independent of K. Python compilation and two byte-identical executions passed 420 assertions. This is NOT PKE/FHE/FE/WKEM or a PQ security test.

**Attack scope.** Public seams/gates, global public mixing, local fingerprints, fresh multi-views, and chosen public w are all simulable in the IND game; correlations with K, reused setup secrets, malicious N-of-N setup, replay, full QPT auxiliary-output security and native forgery remain UNPROVED. A classical distinguisher is already QPT-allowed; no quantum attack against a surviving design is claimed.

**Handoff.** Simple public homomorphic witness insertion, even if constructed, does not supply exceptional witness-dependent plaintext release. The protected release frontier must contain additional concrete key-correlated cryptographic structure *and* prove arbitrary unauthorized signing/key recovery -> accepted complete SOURCE representation or independent QPT break. Run 259 only extracts ORIGINAL w from such an accepted representation; native signatures are not representations. No practical WKEM, resource parameters or future-P2MR/SLH Bitcoin graph is established. Production unchanged; PR remains draft/unmerged.
