## Selection and missing operation

Need a serialized offline classical-PPT Build(x,S) and Open(C,w) returning one fixed native safe cancellation capability S for every full qualifying original w. The immediately preceding public non-malleable encoding cannot protect its state from public decoding and re-encoding. Its secret MAC refresh is not implemented. Instead of adding a hidden decoder, try a publicly verifiable hash-chain authenticator on the ENTIRE chronological execution state with a fixed terminal signature as the common secret. The mathematical change is a forward-only chain operation on authenticated state digests, not public decoding, local scalar transport, another label basis or affine coefficients. Intermediate state may be fully public; it is the signature on the complete state that is supposed to prevent state splicing. No extra source authority or signing oracle is allowed. Screen whether forward hash updates can actually implement the signing operation before attempting a garbled transition wrapper.

Let R_x be the unchanged complete bounded original verifier with all three sufficient grounds and all binding, relevance, authentication, maturity, window and replay checks. Compile it to a deterministic chronological execution with state z_j and a public transition T_j(z_j,a) taking the next source chunk a, including rejecting invalid rows. Let terminal ACCEPT be a canonical distinguished message, distinct from all prefix state messages. All accepted original executions must terminate in this message. The setup can compute its bytes without any witness. Define m_j=Encode(ctx,capsule_id,j,z_j) with an injective encoding; the fixed m_*=Encode(ctx,capsule_id,terminal,ACCEPT). A digest domain distinct from chain evaluation and terminal KDF maps these messages to a Winternitz digit vector including its usual checksum. This is an internal authenticator only, not the native Bitcoin signature.

## Concrete forward-chain trial

For base B>=2, let d_i(m) in [0,B-1], i=1..L be the message and checksum digits. Sample independent uniform secret chain starts k_i. To isolate the proposed update operation use chains F_i iterated on lambda-bit strings, with separate domain per chain but identical step function within each chain (not a claim that this is the exact standardized WOTS+ hash addressing). Define sig(m)_i=F_i^{d_i(m)}(k_i), pk_i=F_i^{B-1}(k_i). Public Verify hashes each component B-1-d_i more times and compares pk_i. Fixed S is masked by D=enc(S) xor H_expand(ctx,Encode(sig(m_*))). Build publishes pk, signed initial state (z_0,sig(m_0)), the public verifier/state transition descriptions, and D. Erase the starts. To update a legitimately signed state to the next exact z', if every new digit is at least its old digit, simply hash component i d_i(m')-d_i(m) times. Otherwise forward evaluation does not implement the update. Open on a complete w attempts the chronological transitions and finally derives the fixed terminal signature and pad. This is serialized and polynomial, but incorrect: arbitrary valid source execution does not guarantee monotone digest digits. Indeed the ordinary checksum is designed so that a distinct message-digit vector cannot be componentwise greater while its checksum digits also all are greater or equal. If a nontrivial message digest changes only by increases, its integer checksum strictly decreases, so at least one checksum digit decreases. Thus ordinary WOTS forward-only evaluation does not even move between two distinct authenticated digests by correctness of the proposed chain method.

Dropping checksum and imposing a monotone encoding of state does not fix the release: any componentwise reachable target can already be computed directly from the public initial signature, without the intermediate source checks. An honest-code requirement to follow T_j cannot restrict arbitrary hash evaluation. A backwards correction table indexed by two digit values can supply an earlier chain element, but once that element is obtained it can be hashed to any subsequent value independent of the source. Adding a source-authenticated cryptographic gate to that table would need an independently implemented original-source-dependent release, not a public if-check.

## Screen repair A: allow valid-only refresh, retain same global WOTS key

Grant, solely to screen this repair, a complete public refresh that emits the exact WOTS signature after every well-formed prefix. It need not emit signatures for invalid transitions. This is not a constructed evaluator. Unlike the earlier local-state mixing attack, all signed prefix messages here commit to whole states; no attack assumes that an invalid state signature can be synthesized by concatenating two ordinary state encodings. The same-key WOTS reuse attack nevertheless applies to the authenticators themselves.

Suppose q distinct accessible prefix messages m_1,...,m_q can be generated in polynomial time without an original qualifying certificate; the attacker simply runs the public refresh from the published initial state, copying its input state as needed. Consider the independent random-function idealization of the digest domain, and fix the distinct message strings (including m_*) independently of that domain's outputs; the chain starts and other source hash domains are independent of it. This is a sufficient screening condition, not a theorem about actual SHA or about which prefix states the full real verifier admits. For each coordinate i let a_i=min_t d_i(m_t), and choose any genuine observed signature attaining it. If a_i<=d_i(m_*), compute the exact target component F_i^{d_i(m_*)-a_i}(sig(m_t)_i). If this holds simultaneously for all i, the entire exact target signature, not just a different verifying signature, is recovered. The terminal KDF and D then recover exactly S. No private state, forged source history, adversarial query log or signature extraction from an adversary is used.

The q+1 digest samples are exchangeable; each digit including a checksum digit is a deterministic function of one sample. For any coordinate, the event that the terminal digit is strictly smaller than all q prefix digits has probability <=1/(q+1): at most one sample can be a strict unique minimum, and the terminal index is exchangeable. No independence across digits is required. Union bound gives success >=1-L/(q+1). E.g. q>=100L gives >99% success for the specified ensemble, a polynomial query count. This is an ordinary classical multi-use failure even if every prefix authenticator came from an honestly checked source transition. Independent hash KDFs, exact terminal signatures and full digest binding do not help. The actual one-time security of WOTS is not contradicted. If the real protocol exposes only a single prefix transcript under that key, this particular many-prefix calculation does not apply; public offline copyable evaluation cannot assume such a restriction. If refresh demands a complete qualifying witness before revealing ANY intermediate signature, it has moved the release problem into that first refresh. We did not assume a specific false original bridge fixture or establish the availability of q actual source-prefix states for every x.

## Screen repair B: stage keys with publicly forward-updatable starts

The meaningful attempted repair is to separate the signature key at every stage while enabling a hash-only change of key without an online signer. For a common chain function F_i, choose k_(j,i)=F_i^j(k_(0,i)). Publish each stage pk_(j,i)=F_i^{B-1}(k_(j,i)). The required signed state update at stage j->j+1 is exact:
    sig_(j+1)(m')_i=F_i^{j+1+d_i(m')}(k_(0,i)).
Given a previous signature component at total exponent j+d_i(m), the correction is simply 1+d_i(m')-d_i(m) forward iterations when nonnegative. This uses genuinely different stage public keys and is a concrete public key refresh, rather than an ideal hidden signer. It still fails completeness for drops larger than one. More importantly, if terminal stage J is at least B-1 stages beyond the public initial signature, then every target component exponent J+d_i(m_*) is at least d_i(m_0). Direct forward hashing from the initial signature computes the exact terminal signature for any statement x, including false statements, bypassing every source check. This is independent of digest randomness. Making larger offsets to accommodate every possible drop only strengthens this bypass. The same argument applies to arbitrary monotone public offsets with terminal offset at least B-1. These are exact equations for this candidate, not a claim about arbitrary hash-based signature schemes. Domain separating every stage and every chain step or independently generating the stage starts prevents that arithmetic shortcut, but does not give the required key refresh: the opener has only F_(j,i)^d(k_(j,i)), not the secret k_(j+1,i). Public evaluation of the stage-dependent functions cannot create the correct independent chain preimage by the stated algorithm. A secret PRF of the full state to derive stage keys also does not implement this computation publicly; revealing the master key defeats it.

An independently generated final-stage key can be kept offline and used to mask S as above. To complete the repair, Build must serialize transition tokens that map authentic whole-state input signatures to exact new independent-stage signatures only on original-consistent states. A public table over all possible complete states is exponential in general. Publicly authenticating a new state-specific WOTS key with a prior key requires a signature by that prior key; exposing the prior signing seed permits arbitrary authentication, whereas a cryptographically restricted signer is exactly the missing operation. A Merkle root of an exponential state-key table is not a PPT construction of that table or of its future opening paths. The attack on reuse does not imply a failure of independent-stage signatures under their standard definitions. No hidden evaluator or correction oracle is being counted as implemented.
