## 1. Explicit candidate, not an assumed source oracle

Fix the full ORIGINAL canonical verifier R_x(w), including the three independently sufficient grounds, source admission, relevance, window and maturity. Let S be the exact preauthorized native signature, with M,VK and the complete claim context bound. Setup samples an independent lambda-bit t, publishes h=H_trap(t), and uses the internal relation Q(w,t') = R_x(w) OR [H_trap(t')=h]. This is only a setup device, not a new valid ORIGINAL challenge. Let w0 be a public dummy of canonical padded length. For input vector u=(w,t') use an ordinary three-party XOR sharing independently at each bit: choose a_i,b_i uniform bits; c_i=u_i XOR a_i XOR b_i. A cut J is an explicit list of selected party/bit coordinates of this array, with canonical ordering. More general transcript cuts could include wire values, but the concrete first implementation below uses input cuts, and separately evaluates the top OR interface.

Build_inc(x,S):
  1. Execute Q on u0=(w0,t); choose m polynomial cuts J_j, and sample a fresh XOR input sharing for each cut.
  2. For each j let v_j be the selected raw cut vector, z_j=H_tok(context,j,J_j,v_j).
  3. Serialize h, all cut descriptions, d_j=H_check(context,j,z_j), and B_j=S XOR XOF(context,j,z_j,|S|), along with the public relation, context and native data. All hash domains are separated.
  4. Erase t and the sharings. No input share or v_j is published.

Open_inc(C,w):
  1. On a qualifying ORIGINAL certificate choose u=(w,0); execute the ORIGINAL branch and sample fresh independent sharings (one per cut).
  2. Compute v'_j,z'_j with the same public cuts. For any matching d_j, return B_j XOR XOF(context,j,z'_j,|S|); native verification is available.
  3. If no matching entry, return failure.

The optional honest relation check does not itself protect B_j. The candidate's only actual cryptographic release path is matching a token. Its algebraic correctness for any exact raw cut hit is immediate, and any matching entry yields the SAME S, not a fresh signature. Setup/open cost is polynomial in m and the bounded verifier/input sizes; repeated samples may be folded into the list length. No exponentially large witness or transcript table. But this does not guarantee a hit for every actual original witness.

## 2. Exact simulation and failure of the concrete input-cut compiler

For any cut J, define F(J) as the bit positions for which J contains all three shares. For any fixed u, the distribution D_J(u) of the projected input sharing is uniform on the set of cut vectors satisfying, precisely for i in F(J),

    a_i XOR b_i XOR c_i = u_i.

Proof: at one bit, any choice of zero, one or two coordinates of a uniform XOR sharing has uniform distribution (each chosen pair fixes exactly one choice of the original two random bits). Choosing all three gives a uniform pair and the required parity. Random choices at distinct bit positions are independent. Thus D_J depends only on u restricted to F(J); no other input dependence is present.

Fix any actual qualifying w, setup t, all setup cut descriptions and the actual v_j values. For each cut, either u=(w,0) and u0=(w0,t) disagree at a position in F(J_j), in which case the raw cut hit probability p_j=Pr[v'_j=v_j] is zero, or they agree at every such position. In the latter case, the publicly known **fake** vector u*=(w0,0) has exactly the same restricted bits as u. Indeed on a source position agreement means w_i=(w0)_i; on a trapdoor position it means t_i=0. The explicit unauthorized sampler of projected XOR sharings of u* therefore has EXACTLY the same distribution D_J(u*)=D_J(u) on every hit-compatible cut. It need not satisfy Q, find t, learn any original certificate, alter setup data or break a hash.

Let p be the probability an honest opener obtains at least one exact raw hit, over setup and opening coins for this fixed w. By the union bound E[sum_j p_j] >= p. A classical PPT adversary given the actual public capsule chooses j uniformly, samples the projection of u*, computes z*_j, and returns B_j XOR XOF(context,j,z*_j,|S|). Conditional on setup, the hit probability is at least sum_j p_j/m, because incompatible cuts contribute zero to that sum, and on compatible cuts the unauthorized distribution equals the authorized one. Thus unconditional exact-S recovery is at least p/m. No representation or query log is needed from the adversary. No independent-source entropy assumption, no query simulation, no asymptotic fixture. This already defeats a hard-TRUE security claim for this compiler if it has nonnegligible correctness and such a hard instance. It also exhibits the same public sampling route whenever the fake distribution hits on a FALSE instance; the hard-TRUE break alone is sufficient, without asserting a FALSE probability not derived here.

The proof is about exact raw hits. Different raw cut vectors yielding the same z_j or a false match of d_j would need an independent hash collision or coincidence. Relying on such events for useful honest completeness is not a justified repair. The attack does not need a collision: equality of raw vectors yields byte-for-byte equality of the key derivation. The bound is unchanged if the setup chooses the public cuts after seeing its own shares, because the argument conditions on that setup and uses fresh opener shares. Nor can a public selection rule on the honest list protect the capsule: the adversary can sample a single entry without applying that rule. Repeating the openings polynomially increases the number of trials for both parties. In a QPT game this classical attack is already admissible. No QROM theorem is required to establish this failure.

For deterministic raw input projections (no sharing), the same argument is even simpler: all coordinates of any exact matching projection already agree with u*; the unauthorized candidate computes that projection directly. If the projection includes the full input then the two branches generally cannot match. These are cut-specific rejections, not a general impossibility of witness encryption.

## 3. Attempt to include branch acceptance in the token instead

Move the cut from the input to the complete top OR gate interface, using independently freshly XOR-shared branch outputs a=R_x(w), b=[H_trap(t')=h] and output c=a OR b. This is a different concrete projection family; its interface is generated by evaluating both branches and sharing the three resulting bits. For the normal setup dummy with a=0, the setup interface parities are (0,1,1). For an ORIGINAL witness with t'=0 not a trapdoor preimage they are (1,0,1). A projected interface containing all three shares of either differing branch bit has disjoint raw supports; all other compatible projections depend on at most the shared output parity c=1. In this latter case the unauthorized party directly samples sharings of (0,0,1) (or (0,1,1)), without executing an accepting ORIGINAL relation. By the same uniform-projection proof it matches the authorized distribution for every compatible cut. Including a local OR consistency check before returning S cannot constrain a party that simply computes the matching mask; local validity of (0,1,1) itself is also public and does not establish the internal trapdoor/source branch. This is not a claim that arbitrary internal wire-view projections of a real MPC protocol have independent distributions. Those correlations would require a new explicit construction and joint proof, and are not supplied by the independent-share interface.
