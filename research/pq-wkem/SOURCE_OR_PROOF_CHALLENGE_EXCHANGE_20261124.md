## Independent-salt candidate fails even honest completeness

Its salt is uniform and independent of the graphs, source witness, all other salts and all noncommitment hash domains. Even give the honest opener K, the actual p_K, all other salts and all secret-graph adjacency bits as side information for this test of the *exchange operation* (not a key-recovery security game). The only information about the remaining salt in the full honest capsule is its commitment output A_K,t. In particular z_S0, z_S1 and E contain no dependent value. Domain-separate each cell for the following classical ideal-random-function test.

With no additional salt-dependent public data, any putative z_K0 must open this cell, irrespective of its choice of p_K'. Condition on A_K,t. Use lazy sampling with one uniformly planted lambda-bit salt under the actual bit. Before finding the planted input, unsuccessful probes of that bit exclude at most the number of probes from the salt space. Queries on the other bit do not identify the planted input. Each nonplanted fresh input has independent probability 2^(-lambda) of returning A_K,t. Count the returned candidate opening as one additional probe if not previously evaluated. For q classical queries, the probability of a valid opening is bounded by
    min(1, (q+1)/(2^lambda-q) + (q+1)/2^lambda)
for q<2^lambda, by a union bound for finding the planted salt and for nonplanted target matches. This conservative bound includes the possibility of opening to a different adjacency bit, without requiring that the returned permutation equal the setup permutation. A deterministic source witness and any number of source challenge responses independent of the secret-cell salt do not change the argument. This is a classical correctness screen for the specified independent-salt compiler, not a quantum query theorem or a proof about concrete SHA. No adversarial representation or rewinding is required. The idealized graph hash is not the commitment oracle; conditioning on concrete G_K and K is legitimate for the separate commitment domains.

Thus even the strongest honest source opener in this test cannot perform the proposed challenge exchange with overwhelming probability. More proof repetitions, larger graphs, new challenge encodings or another local label arrangement do not fix this candidate. ## Coupled-opening repair attempt

Change the secret salts before generating A_K. The intended structural repair is to derive them from the *complete* source challenge response, rather than exposing an accepting label or letting each source occurrence authorize a secret cell. This would defeat the preceding independent-salt calculation if the genuine public source opening carried a dependent value. In particular, for all hidden cells t, try
    s_K,t = H_salt(ctx,t,enc(z_S1)).
The whole cyclic ordering, vertex labels, lengths and salts are included in enc. Different qualifying source histories can map to different cycles; no assumption of one canonical original witness is permissible. Build only knows z_S0, not z_S1. If it selects a representative source response (even granting it a witness), then for any different encoded source response the derived lambda-bit salt for a fixed cell matches with probability 2^(-lambda) in the separate ideal salt domain. A different salt which nevertheless opens the same fixed commitment is a target match in the commitment domain. Such failure is a correctness defect, not the independent-salt attack. This repair has no general every-witness compiler.

Try instead s_K,t=H_salt(ctx,t,enc(z_S0)), since the full challenge-0 source response is witness independent and known at Build. Then anyone computes all secret salts without w. For each secret cell, evaluate the two possible adjacency bits against A_K,t and recover the bit (unless both match, which is a commitment collision). Recover the entire p_K G_K. The proposed complementary challenge-0 response still needs p_K, an isomorphism to G_K. To complete this explicit repair, choose p_K by a public deterministic procedure from z_S0 as well (including the simple shared permutation when graph sizes are matched). Then anyone forms z_K0, uses the published z_K1 and recovers K by the reverse witness map without any original evidence. If p_K remains hidden, this instead leaves an unimplemented isomorphism-finding step; graph isomorphism hardness is not an independently justified hash foundation. Revealing the salt from a source opening that every caller can evaluate cannot by itself establish the original relation. Correlating salts with source permutation or other already public challenge-0 data gives the same public computation.

A stronger repair could define a common secret-branch opening using a nonlocal function of the source cycle, potentially allowing different valid p_K' through automorphisms. However each individual cell has a fixed commitment. Two valid different openings of that cell would be a hash collision (unless the byte encodings coincide). Consequently variable p_K' alone cannot remove the need to derive the same hidden opening salts across all source witnesses, except by giving up commitment binding. Generating a public witness-blind circuit for those salts without exposing them is the exact unsolved exchange compiler; assuming it can be done via a trapdoor commitment or witness-based equivocation already assumes a substantial missing primitive. Do not simply model Exchange as a private oracle. This is not a general impossibility theorem for special-soundness-based release constructions, only the concrete transcript and repair above.
