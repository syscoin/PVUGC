## Selection

The missing original-source operation is a public, offline transformation of a setup transcript, containing a frozen cancellation capability S, into a transcript from which exactly S is recoverable using any qualifying original witness w. Try a global special-soundness extractor, not a private-coefficient evaluator, locally reusable garbled input labels, or a forward hash-chain state authenticator. The mathematical change is to bind a complete proof first message before issuing any responses and require two different challenges for the SAME first message. A mixed collection of individually valid local labels is not a valid second opening of an ordinary binding commitment. This is the reason to screen the transcript-switch construction instead of sweeping the already rejected state-refresh family. The test is whether the required switch can be implemented, not whether special soundness is true in isolation.

Keep R_x as the full original three-ground predicate, with all source and endpoint binding, authentication, maturity, relevance and network conditions. A source proof circuit is merely a deterministic encoding of that predicate. A second relation Q_y has witness S, the exact fixed safe native capability; y includes the relevant native checking key/message and a binding digest of S, so a different verifying signature alone is not an exact S. In the following abstraction, extractors must return a relation witness, not just a transcript accepting bit. No assumption of post-quantum security is granted to an unspecified proof protocol.

## Trial A: split-challenge proof transcript as the capsule

Take two public-coin proof protocols with a common additive challenge group E. A transcript for branch i is (a_i,e_i,z_i), with public predicate V_i. For the standard OR composition, the overall challenge e is e_R+e_Q, and the same first messages (a_R,a_Q) are used for both branches. Suppose branch Q has t-special soundness: t accepted responses to distinct challenges at a fixed a_Q allow a deterministic extractor Ext_Q to recover a Q witness. Grant this property solely for the construction screen, not as a QPT argument.

Setup knows S, can generate a_Q and one genuine response (e_Q0,z_Q0), and can use the simulator of branch R to generate an accepting (a_R,e_R0,z_R0) without any original w. It publishes this OR transcript, a chosen overall challenge e0=e_R0+e_Q0, context, and optionally other public auxiliary tables. Erase setup secrets. A public opener possessing w would like to create another accepted OR transcript, same first messages and same e0, with e_R1 != e_R0. This forces e_Q1=e0-e_R1 != e_Q0. If Q is 2-special-sound, the two Q responses now extract S up to the binding of its digest; if it is t-special-sound, repeat with t distinct splits. A switch at fixed e0, rather than public selection of a new overall challenge, avoids merely changing the verifier's challenge. In a hash-derived overall challenge version e0 would have to be pinned to the first messages and context; we have not supplied an algorithm for making the initial simulated transcript satisfy that additional condition.

The precise missing update is

    Switch(C,w,e_R1) -> (z_R1,z_Q1)
    V_R(x,a_R,e_R1,z_R1)=1,
    V_Q(y,a_Q,e0-e_R1,z_Q1)=1.

Original knowledge alone is not an algorithm for either response at a previously simulated/committed first message. More importantly, even granting z_R1 on demand does not supply z_Q1. In a standard OR proof with knowledge of the R witness one simulates Q at a chosen challenge BEFORE its first message is fixed; simulation is not a way to answer a fresh challenge at an already fixed a_Q. An accepting simulated Q transcript with fresh a'_Q cannot enter Ext_Q. This is the exact chronological failure of the proposed repair and is independent of local-label splicing.

To make the R obstruction concrete with hash-only commitments, use the ordinary graph 3-coloring proof as an illustrative NP encoding. A first message commits to each vertex's permuted color with independent salts; a challenge selects an edge and the response opens both endpoint colors. A simulator for a fixed edge can commit to distinct endpoint colors and arbitrary remaining colors. Those remaining commitments need not describe a proper coloring. Binding prevents replacing them with a witness coloring at another challenge. Even if the simulated first message happened to encode a proper coloring, a different witness does not generally know the setup's opening salts. Multi-edge extraction from openings of a single binding first message is possible only if the required openings are supplied, not just from existence of a valid graph coloring. This example is a protocol-level countercheck, not an assertion that the original bridge relation is 3-coloring or that all hash-only proof systems have identical commitment syntax. The graph proof example illustrates many-challenge extraction, not 2-special soundness for arbitrary edge pairs.

## Trial B: source-conditional equivocation as an actual repair to the R half

An explicit hash-only witness-dependent commitment can permit any original holder to change the R openings without setup salts. Define Commit(m;r)=H(domain,ctx,m,r), and OpenCheck(x,c,m,pi) to accept either a conventional opening r or an entire w with R_x(w)=1. Tags distinguish the two branches. The conventional commitment is computationally hiding only under suitable salt/hash assumptions; on false x the modified binding reduces to conventional binding. On true x a holder of ANY original witness can open the same c to ANY m without a setup trapdoor. This is a complete public algorithm for conditional equivocation, not for common-value release. For the R proof example it can open every committed color according to any witness coloring, and thus generate responses at the fixed R first message. The modified R verifier must actually enforce the full original predicate on every conditional opening. It is not sufficient to claim that the caller checked R. This modification is not claimed to preserve zero knowledge or ordinary proof soundness properties on true x.

Test the resulting complete R-side switch against the extraction goal. The Q first message still uses ordinary binding commitments; the cancellation witness is not known by the opener. The preceding equations require Q responses at distinct challenges and Trial B provides none. If we also replace Q commitments by source-conditional commitments, the same R witness now lets an opener choose arbitrary alleged Q openings, independently of their setup values. This destroys precisely the binding premise of Ext_Q. In the graph encoding, choose any alleged color for any challenged vertex and authenticate it using w; different edge responses can use incompatible colors for the same vertex. More fundamentally, even globally consistent colors chosen by the holder of w encode a witness to Q only if the underlying constraint system really has that coloring. Conditional equivocation does not calculate a coloring for Q. Thus it neither guarantees extraction of ANY Q witness nor the precommitted S. This does not attack the original unmodified special-soundness theorem; the theorem's hypotheses were removed by the repair.

A generic extractor that reads only the alleged opened messages and ordinary public setup bytes also has a useful explicit regression: if its deterministic opening values are chosen by the opener from public data, it can run on those same public values without the proof tags. Checking proof tags before applying the extractor does not make its computation secret. If it reads the original witness or hash of the conditional proof bytes, then this shortcut does not automatically apply, but the construction must implement a new correlation between those varying bytes and the same frozen S. No such correlation is supplied by commitment equivocation. In particular, publishing t ordinary accepting Q responses so that the witness can select which ones to combine immediately gives a public extractor its t responses; hiding them behind a new gate is precisely the unimplemented operation. Do not infer that a different, independently justified proof-dependent extractor is ruled out.

## Exact handoff

The conditional-opening primitive above is implemented at the algorithm level and resolves changing the source-side first-message openings (by including the original witness itself); it does not transport hidden information from the Q branch. A possible next attempt must have a genuine source-dependent response update for Q that preserves ordinary binding/special-soundness or independently proves its replacement. If it relies on a witness-conditioned simulation trapdoor, specify the serialized algorithm that computes it from original evidence and the public capsule, not a trapdoor granted by the model. The two-transcript equation must be checked jointly with the simulator: any public combination yielding enough ordinary Q responses already reveals S even on false x if such a capsule can be generated there; any arbitrary recovery/accepted native forgery in hard-TRUE requires actual original certificate extraction or an independent QPT hash/native break, with aux input, malicious source coins, sibling capsules and native context correlations. The explicit conditional opening is not a security proof for those cases. No rewinding or QROM programming asserted, and no generic impossibility theorem inferred.
