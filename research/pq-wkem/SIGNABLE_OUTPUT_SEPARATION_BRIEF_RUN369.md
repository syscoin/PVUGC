# Run 369 — Full signing-key hiding does not imply fixed-branch authorization hiding

Starting live PR head `8a7b59163fb7a5c1b3e4e39f8be4b6a72a632432` (`syscoin/PVUGC#1`, open/draft/unmerged); latest substantive ordinary comment `5945825660`. Exact dependencies read: Run 368 `bd25ba419279de8a18783127c76419c9de547f62`; Run 259 `c7f3b77f0273ca1cbe6f0b31c1a086b8eb3acbf2`. This is a **bounded source-to-native-signature falsifier**, not a WKEM construction.

**Candidate.** Use independent Lamport one-time signing secret leaves `s[i,0],s[i,1]` and public checking key `vk[i,b]=H(s[i,b])`, with a fixed fully bound Bitcoin challenge message `m`. Publish two individually uniform local auxiliary views `A[i]=r[i]` and `B[i]=r[i] XOR s[i,m[i]]`. Give the defender an *ideal, unimplemented* source-gated key-release oracle: `R((flag,y),(p,t))=1` iff `flag=1`, `H(p)=y` and `t in {0,1}`; only a valid ORIGINAL witness obtains the **same entire signing key K**. Witness-dependent `t` can differ. For `flag=0` the gate releases nothing and there is no ORIGINAL witness. This ideal gate is granted only to attack the auxiliary output, never offered as a WE/iO/RIO construction.

**Unconditional classical attack.** From the full public capsule compute `sigma[i]=A[i] XOR B[i]=s[i,m[i]]`. The public native-like verifier accepts `sigma` for exactly the preauthorized target message with probability one, **even on false statements and before any witness-based release**. Each of `A` and `B` separately is uniform independent of the secret leaves, even conditioned on `vk`; only their *joint distribution* leaks the signature. No raw-frontier inverse (Run 368), public path cycle (Run 364), multi-capsule reuse (Run 365), Simon oracle (Run 366), or Grover search (Run 367) is needed.

**Exact-key nonimplication.** Suppose `H` is QPT one-way on independent uniform secret leaves. On the false source flag the ideal release oracle is constantly `bottom`. A QPT attacker outputting the **complete exact native signing key K** from `(vk,m,A,B)` with probability `epsilon` gives a straight-line inverter for `H`: embed its challenge as one *unselected* Lamport public-key leaf, sample every other secret, simulate all auxiliary pins using only selected leaves, and output the recovered challenged preimage. No QROM programming or quantum rewinding is used. Thus false-instance full-K hiding can hold while usable challenge authorization is already public. This is **not** native EUF-CMA forgery: setup created a target signature and the capsule leaked it. QPT OWF hardness is an explicit independent assumption, not inferred from SHA-256 or the finite checker.

**Precise bridge implication.** Run 259 only proves `accepted complete representation -> ORIGINAL witness / stated SIS break`. The public `sigma` does not create such a representation; for `flag=0` none exists. Source-binding must cover **unauthorized pre-release target-signature availability**, not just recovering the whole SK. Legitimate *post-release* relay remains allowed (Run 361). Distinct-message/UTXO/branch sighash binding can stop replay but not the attack on `m` itself. This Lamport toy is **not** SLH-DSA or a Bitcoin deployment; NIST FIPS 205 is the actual SLH-DSA specification (2024-08-13, https://csrc.nist.gov/pubs/fips/205/final).

**Attack-surface audit.** Local seam XOR cancellation and complete-public-view/auxiliary-checking-key correlation: broken. Single-view marginals: perfectly uniform. Honest independent setup masks: insufficient; subsequent secret erasure does not unpublish a signature. Adaptive evaluator queries, global frame synchronization, cross-UTXO replay, and coherent quantum search: unnecessary for this failure. Malicious setup, multi-capsule composition, actual conditional P2MR/SLH transaction semantics and any secure source-gated mixer: **unproved**. The classical attack is also a QPT attack, but no quantum-only algorithm is claimed.

**Reproduction.** `signature_pin_release_compact_run369_check.py` is exact deterministic finite checking (individual uniform marginals, joint signature recovery, two dummy ORIGINAL witnesses, false source gate, public signing verification and different-message rejection). Two executions and `py_compile` passed. Finite tests do **not** establish QPT OWF strength or a complete release compiler.

**Core handoff:** Prove a message/branch-specific *authorization-extraction* game for the **entire public capsule and pre-signed graph**. Both `unauthorized usable signature -> accepted representation / independent QPT break` and `accepted representation -> ORIGINAL` are needed; the second remains scoped to Run 259. Full-public false-instance QPT hiding, true-instance early recovery extraction, honest-erasure N-of-N composition, arbitrary QPT auxiliary inputs, and practical 128-bit parameters remain **UNPROVED**.
