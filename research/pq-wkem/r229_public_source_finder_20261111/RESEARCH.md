## Exact conditional source-enumerability lemma

Fix the actual withdrawal x, the three-branch ORIGINAL source challenge relation R_original(x,j,w), and output time t. Let S_x(t) be a *fully public, polynomial-size, finite, authenticated, complete and indexed source snapshot* containing all relevant BTC headers, contextual consensus data, parent coinbases, Syscoin pure-child headers including qualifying side branches, actual ancestor paths, burn authorization/state and any needed off-chain DA attachments. Its public availability is an explicit premise, NOT established by a Merkle root.

If all qualified ORIGINAL witnesses at time t are reconstructible from this snapshot using polynomial-time operations, a classical PPT extractor independent of any adversary's internal state exists:

    Find(x,S):
      for each candidate generated from indexed BTC/SYS tips, state keys and
          complete authenticated source records:
          if R_original(x,j,w) == 1: return (j,w)
      return none

The candidate enumeration is not an exhaustive enumeration of arbitrary bitstrings. For B indexed BTC headers each tip has one predecessor path to the anchor. Up to O(B^2) header visits enumerate possible competing histories and compare *validated target-derived cumulative work*; a normal extension does not qualify. For a full authenticated burn-state registry, the fixed burn ID has one bounded query and its complete proof (or a bounded full-history scan when required). For S indexed Syscoin child headers, at most O(S^2) tip pairs suffice to propose histories, and each has one predecessor chain; project at the exact withdrawal-relevant height, enforce the fork-depth/window and validate actual AuxPoW and tag/source rules. Parent-work variants of the same pure child do not become distinct forks. The branch candidate only becomes an ORIGINAL witness after the complete original source verifier accepts it. The source validator is not implemented by the toy code.

**Conditional proof:** Snapshot coverage ensures an eligible true witness occurs among these polynomially enumerated candidates. Sound checking ensures every returned certificate satisfies R_original itself. Thus, on TRUE public-snapshot instances, even an arbitrary QPT adversary that outputs the protected native cancellation signature without revealing a representation can be followed by a deterministic, straight-line Find(x,S) that outputs an ORIGINAL witness. It does not rewind the adversary, measure quantum queries or assume an iO/WE oracle. On FALSE instances this lemma establishes NO secrecy, no native unforgeability and no source-KEM construction.

**CRITICAL SCOPE:** The premise is not proved for the CURRENT broad ORIGINAL challenge. A privately mined but valid competing BTC work history or a privately held qualified Syscoin side branch can be used by an off-chain decryptor yet be unavailable to an independent public scanner. BTC AuxPoW parent coinbase commitments do not reveal missing Syscoin child-header preimages. An authenticated state root does not reveal an absent-burn proof or missing transaction data. To make the lemma apply in production one would need an explicitly specified publicly reconstructible source admission/DA condition that covers every eligible challenger witness before opening. A root-only receipt does not do that. Requiring publication may change the challenge relation, add latency/censorship assumptions and must NOT be silently imposed.

## Executed countercheck and captured provenance

A SHA256 Merkle root of four entries commits to a private conflicting source record. Three disclosed entries verify under the SAME root but cannot reconstruct the fourth. The owner of the undisclosed fourth has a valid membership path. An independent public scanner finds no conflict until the fourth record is disclosed. This is an exact counterexample to root-commitment-implies-availability; it is NOT a Bitcoin/Syscoin source validity counterexample.

## Remaining hash-only ORIGINAL gate

Even when a future source witness can be publicly discovered, the pre-funding setup does not know which future authenticated history will exist. Discovery is NOT cryptographic conditional release. Still missing are polynomial classical Build_hash(R_original,x,sigma) and public Open_hash(C,w) yielding the SAME frozen claim-scoped native cancellation capability for *every* qualifying actual witness, with full-public FALSE-instance QPT secrecy and arbitrary unauthorized final-key recovery/native forgery -> ORIGINAL witness or independently justified PQ hash/native break, including malicious setup, advice, sibling capsules and source-secret retention. No independent puzzle, online signer, public fabricated labels, private oracle or Bitcoin NP verifier is introduced. Thus this public-data theorem is a conditional side result, not a reduction of the required current-source hard-TRUE game. Continue construction work; do not optimize this checker.
