## 1. Construct the source-enabled opening interface

Fix x, including the original three independently sufficient OR grounds with authentic, relevant and mature evidence. Write R_x(w) for its deterministic bounded complete relation. Fix the exact native message M and verification key V, and let S be the exact frozen native signature. The native relation N_(V,M)(s) is native verification. This relation may have more than one witness; a knowledge extractor for it does not necessarily recover S. The candidate must recover S, and we test even the weaker accepted-signature goal.

Consider the explicit commitment interface for a color b in {0,1,2} at coordinate i:

    Commit(b;r) = H_com(ctx,i,r,b),  r uniform lambda bits
    Verify(c,b,(0,r)) = [H_com(ctx,i,r,b) == c]
    Verify(c,b,(1,w)) = R_x(w)

The second type is domain- and claim-bound by R_x and the common context; the committed color is typed and bounded. This is intentionally only an acceptance-level commitment, with binding conditional on the absence of access to qualifying original evidence and ordinary hash collision resistance. For an adversary outputting two different accepted openings, either at least one contains an actual original witness or two distinct typed hash inputs collide. This is a direct classical-output reduction, also valid for a QPT adversary producing such outputs. It is not a proof that the commitment is hiding for arbitrary correlated auxiliary information. Unlike independently planted two-opening PRG seeds, EVERY qualifying original witness enables the alternate opening without knowing a setup seed. Unlike an unrestricted label table, it requires no public supply of hidden semantic labels. The question is whether alternate opening acceptance can actually turn into native secret extraction.

For selection grant a polynomial witness-preserving graph reduction G_(V,M) to 3-colorability, with maps Enc(S) -> proper coloring chi and Dec(chi) -> accepted native signature. No actual native graph or exact-S extractor is asserted. Build commits independently to the colors of chi under fresh salts for all n vertices, draws a uniformly random edge e=(u,v), and discloses genuine type-0 openings for its two endpoints. This is one native proof transcript. The public capsule contains the graph, commitments, e, the two openings, context, V,M and x; no ciphertext or native secret evaluator is granted. Use of independent challenges is intentional here: we need honest secret-bearing correlation at all before optimizing a proof system. Additional independent repetitions with fresh salts are allowed polynomially.

Proposed Open: with a qualifying source witness w, obtain alternate accepted openings for the remaining vertices of the *same* native commitment vector. Combine the transcript and the new openings to extract a proper coloring, then Dec. This would avoid both the preceding fresh-instance decoder-transport problem and an OR proof extractor that is allowed to return the source witness instead of the native witness.

## 2. Extraction is lost exactly at the binding switch

For an unopened vertex i, the explicit alternate opening (1,w) verifies for every color b. This holds even if the genuine committed color was different. Thus the ordinary extraction argument from a collection of edge responses cannot assert that the color assigned to i in different responses is consistent. Even a response collection covering ALL edges can be made using a single actual source witness with locally distinct endpoint colors chosen independently per edge. The genuine disclosed edge is preserved. Each additional edge can use two type-1 openings with unequal colors; neither invokes the original commitment's hash preimage. All responses pass, but no one global coloring need be encoded by the responses. For example, on a triangle with the genuinely opened edge (u,v) colored (0,1), choose responses (u,z)=(0,1) and (v,z)=(1,0); the two openings of z disagree. The responses can instead agree on some coloring, but choosing a proper coloring of the whole native graph at Open would already be solving the native relation. This is not a claim that a triangle is a hard native graph.

The standard binding step for a special-soundness extractor from full edge coverage is precisely: an accepted opening at a vertex fixes its color for all edge responses. With the new opening type its reduction returns w, which Open already has. It does not recover the type-0 salt, true color or S. Even granting a complete native graph compiler, ordinary special soundness does not survive composition with the witness-equivocable commitment. This is a different direction from replaying short challenges to fake original evidence: here the opener is authorized and the failure is **correct native extraction**.

## 3. Test whether a different extractor could rescue this concrete capsule

Consider the following explicitly conditional source/native sampling experiment. A reduction receives a native public verification key and the frozen message without its signing secret or a signature for that message. The original statement and an actual qualifying w (and public auxiliary data) are efficiently sampleable from public inputs, independently of the fresh proof salts and without S. Allow context to bind V,M. Assume native no-signature forgery hardness in this experiment. This is a screening experiment, not a claim that every real bridge instance can be sampled this way. In particular if auxiliary input carries native signatures or salt preimages, a separate experiment is needed.

Model H_com as an independently domain-separated classical random oracle. All honest setup and proposed evaluation algorithms are classical PPT; classical security failure or contradiction of correctness is enough for selection, and no QROM programming theorem is claimed. Given V,M,x,w without S, simulate the proposed capsule: sample a uniform edge, uniform ordered distinct endpoint colors, arbitrary independent colors at unopened vertices and independent fresh salts. Compute genuine commitments, reveal the sampled endpoint openings. In the real experiment Build first independently applies a uniformly random permutation of the three colors to Enc(S); thus on a fixed edge the opened color pair has exactly the simulator distribution. At unopened coordinates the salt input remains hidden. Commitments at those coordinates can be coupled to independent uniform oracle outputs until the evaluator queries a hidden salt or a prior salt input is reused. For T total commitment coordinates across polynomially many independent transcripts and q total other classical queries in both executions (including prior generation), a conservative bound is O(T*(q+T)/2^lambda). Domain separation by transcript/coordinate only improves it. This is a coupling of experiments, not a programmable hash API for the honest algorithm. The simulator computes all its own hashes normally and does not need any oracle reprogramming. Revealed endpoint salts have the same distribution in both experiments. The type-1 openings and anything computed from them using R_x are public computations of w and the simulated transcript; they add no hidden native-dependent information.

Consequently any classical PPT Open extracting even an accepted native signature with probability 1-eps from the real proposed capsule and w yields an ordinary native no-signature forger with probability >= 1-eps-O(T*(q+T)/2^lambda) in this specific experiment. The forger constructs the simulated capsule and runs Open, then checks the actual V,M. It receives and does not need to produce w from an unauthorized execution: this reduction concerns honest correctness of the proposed capsule. It does not assume same-message EUF for already disclosed signatures, does not extract a transcript from an arbitrary adversary, and does not prove hardness for the full real bridge joint distribution. The test also rejects adding an arbitrary public transcript-processing extractor to this exact format, not just the naive coloring merger. Publishing a simulator trapdoor not generated in this experiment or correlating proof salts with future source evidence would change the distribution and needs its own construction.

## 4. Repair selection

A genuine type-0 opening would preserve the native proof's extraction argument. Replacing the type-1 opening by a procedure that obtains a genuine salt r with H_com(ctx,i,r,b)=c and the actual hidden color for each needed native vertex is the exact missing operation for this direction. Under the independent proof-salt experiment, guessing an unopened lambda-bit salt has the same query bound as above; ordinary hash verification and source-witness possession alone supply no such salt. A proof accepting type 1 is not a salt-producing algorithm. Do not implement additional graph sizes, more edge repetitions, alternate alphabets or changes of proof hash under the same distribution.

A viable continuation in this direction would need a source-dependent *genuine native opening* correlation in Build, non-simulatable even given authorized w without access to S, while joint public material remains simulatable/extractable for unauthorized attacks. The fresh proof salts can no longer be independent of that correlation. This is a specification of a missing equation, not a new primitive assumed to solve it. Merely encoding w in an alternate commitment opening, or weakening native special soundness to extraction of either source or native witness, does not implement this correlation. There is no general impossibility claim against witness-assisted native-proof extraction, special soundness, non-black-box hash constructions or source-specific WE.
