## Explicit scoped key generation attempt

Take a binary GGM seed tree over a domain of fixed-width encodings. Its PRG splits a lambda-bit seed into two lambda-bit children. For each full certificate w and gate g, give the selected-label family its own logical leaf by encoding

    I(w,g,b) = (b xor t_g(w)) || w || enc(g).

This index is computable in classical PPT from the actual full source certificate; it is a bijection in the b coordinate for fixed w,g. The two root-child seeds are s_0,s_1. Build can disclose s_0 and erase s_1; the public evaluator obtains L(w,g,t_g(w)) by ordinary descendant expansion under s_0. It does not obtain the unselected label at this same w,g by retargeting a published prefix seed. In contrast to a single garbling, the keys used at (w,g) and (w',g) are distinct leaf inputs when w != w'. This gives a syntactic namespace solution for the selected-label generator alone; it is not a simulation or a claim that the actual selected trace is secret. That trace is entirely public given w.

Test a tempting way to avoid holding a secret generator: disclose a public universal retargeting routine which returns a standard punctured GGM key for any chosen (w,g), punctured at I(w,g,1-t_g(w)). Such a key, if it covers *all* other leaf inputs, immediately leaks the purported hidden value at any (w,g): request the key for a different puncture (w',g'), then evaluate at the first leaf. This is a different attack on the key generator itself, not a splice of two source labels into one gate. Public retargeting plus ordinary point-puncture security is insufficient. The fixed first-bit split above avoids this attack because s_0 covers only selected labels and cannot be retargeted into the other half-tree. A repair using scoped keys for disjoint w domains likewise avoids this particular cross-key attack; it does not by itself provide any output correlation.

For each ordinary gate use the selected labels from the public subtree and generate only its actual-row ciphertext as the output label XOR the usual hash of its input labels and its context. This requires neither S nor s_1. The evaluator can compute that row and its decryption. Other rows need not be generated or provided. Each specialized garbling is therefore functionally correct on its actual nonterminal trace with polynomial evaluation and seed-only storage. This is deliberately tested as a component of the end-to-end compiler, not a new one-time garbling security claim: the public generator is using the verifier trace itself, and nothing secret is being computed at ordinary gates. In particular any unauthorized w can obtain its own actual labels.

## Attempt to attach the native capability without exposing an alternate row

At the terminal gate change the label convention: allocate an absolute accept label A(w) under a hidden seed namespace rather than a selectedness label under s_0. Keep the reject output public and separately typed. Let P(w)=H("row-pad",x,w,selected terminal predecessor labels) be an m-bit pad. P(w) is available for any w through the explicit seed generator and full trace. Let D(w) be a public decoder-mask generator. The intended single selected accept row is

    C(w) = P(w) xor A(w),
    D(w) xor A(w) = S     if R_x(w)=1.

Thus Open on a qualifying input returns D(w) xor C(w) xor P(w). Only one row is ever generated for a given w. A reject row may be arbitrary but must not yield an accepted cancellation. This avoids assuming the predecessor note's two-row callable interface. The necessary valid-row equation is

    C(w) xor D(w) xor P(w) = S  for every ORIGINAL qualifying w.

Attempt to generate C and D from ordinary public GGM roots (or independent public-seed hash expansion), leaving P computed from selected labels and a distinct hash domain. Here Build can choose the public roots and ciphertext auxiliary data adaptively using finitely many hash queries, but it does not have future w. In the simplest concrete independent-domain variant, C(w) and D(w) are computed without querying the P-domain at evaluation. Condition on the setup transcript, roots, source, selected labels at a qualifying w and C(w),D(w). If the final P-domain input is fresh and the selection of w, the labels and C,D does not use that unqueried P-domain answer, P(w) is uniform. The probability of the valid-row equation is exactly 2^-m, even conditioned on S. This is a restricted classical random-function correctness calculation, not an adaptive quantum security bound. A construction with correlated row generators that query P is outside it; the calculation does not assume that every future source distribution gives a fresh input.

Try the straightforward correlated repair, which makes the pad cancel *by design*. Let B(w)=H("decoder",x,d,w) from a disclosed seed d, set D(w)=B(w), and have the public row generator incorporate P(w). The required residual row function is now

    U(w) = C(w) xor P(w) xor B(w);
    U(w)=S on every valid w.

The desired hash-only correlation has not been provided by the scoped generator. A direct public common-mask repair sets U(w)=S on all indices and breaks recovery on an invalid w, but that is not the only possible function U. In particular one could aim for a public *single-row* generator whose actual residual is S only on accepted w, and arbitrary otherwise. No alternate-row oracle is implied by that specification. Generating U on this condition without S retained is exactly the missing source-controlled operation, not an implementation.

Try placing a hidden seed in the accept subtree and publishing a correction for it: choose a public seed d defining B(w), and define the hidden accept-label family A(w)=S xor B(w) for all indices, rather than assuming ordinary independent PRF leaves will have that offset. This gives the exact every-witness decoder equation, but it creates an essential constraint on the *evaluation* key. If Build discloses a prefix seed or scoped subtree key that returns any A(w) for a known w, the attacker combines it with B(w) to obtain S even if R_x(w)=0. A key covering a publicly identified entirely accepting prefix gives the attacker a witness by padding the prefix; producing such a key in setup would already supply the qualifying source evidence. A finite explicitly listed prefix cover of all valid leaves therefore cannot serve as the witness-free generator on hard-TRUE instances merely by using ordinary tree derivation. This does not rule out a more powerful public evaluator in which a scope can be derived only through actual original evidence, or an accept-label family correlated on valid indices but not others. Neither is built here. Publishing public root pairs with an XOR offset S at a root discloses S there; applying an ordinary nonlinear hash expansion to the two roots does not in general preserve the offset at leaves. No variant based on linear expansion or another coefficient basis is pursued.

This observation is not the simulator of the final capsule. The missing joint object is the serialized terminal-row correction with its decoder and native VK/message.
