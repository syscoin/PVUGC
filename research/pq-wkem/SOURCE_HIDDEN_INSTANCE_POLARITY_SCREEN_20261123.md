## Exact proposed release path

Take a lambda-bit independent uniform K, let E=sigma_cancel XOR KDF(ctx,K,len(sigma_cancel)). For each j, Build chooses independent random tapes and emits a pair (A_j0,A_j1) and public transport data T_j. The required construction properties are:

* For every original w with R(x_W,w)=1, the deterministic public transformation T_j(x_W,A_j0,A_j1,w) returns candidate witnesses u_0,u_1 such that V(A_jb,u_b)=1 precisely when b=K_j. The other instance is false (stronger than rejection of this particular transport). This must hold for arbitrary qualifying original witnesses, not one planted by Build. The original source verifier may be compiled into a classical Boolean circuit, with full original witness decoding from each genuine transformed instance.
* If R is false both are false. Their complete serialized distribution including transport data must hide which construction branch was genuine, not merely have identical truth values on false x. For hard-TRUE it must hide the polarity against arbitrary QPT with original statement, source information, related capsules and native auxiliary context; an adversary is not required to run T or volunteer its trace.
* Open uses the actual w to evaluate T and the public transformed-instance verifiers, recovers K from the unique accepted member of each pair, and unmasks E. No hidden evaluator, future known-witness assumption or signer is in this interface.

This is a genuinely different operational target from finding a low-degree masked pad: no secret enters the transport computation, and the secret is encoded by the selection of public transformed instances. A source-specific realization would be sufficient without generic-NP WE. However, assuming the bit-hiding instance generator as a primitive would already assume essentially the desired source release. It is not an independent hash assumption.

The necessary simulation equation is concrete. If an actual pair generator supported a straight-line QPT indistinguishability reduction for either polarity, including all transport bytes and independent sibling generation, a hybrid could replace each K_j-dependent pair by a fixed-polarity pair while keeping E and the actual native public key/message/context unchanged. In that final hybrid K is independent of all pairs; the public capsule could be simulated without sigma_cancel if the independent KDF pad is pseudorandom in that joint view. A subsequent native target-message forgery reduction would need no signing oracle on the frozen target message, and would count any accepted same-message signature, not just exact recovery. Selective openings and malicious source/setup correlation would require their own joint simulation. This is a proof plan conditional on an unconstructed generator, NOT a theorem for this candidate or a reduction to ordinary hash security.

## Concrete compiler attempt

Let F be the original deterministic source-verifier circuit, with output y. Consider two copies of its gate constraint system, with randomly relabeled internal wires and fresh independent per-wire polarity masks r_v. For each gate v=f_v(a_1,...,a_k), replace its relation by

    z_v = f_v(z_a1 XOR r_a1,...,z_ak XOR r_ak) XOR r_v.

Here z_v=v XOR r_v. The transformed input encodings are provided for the original input bits; statement bits have their proper fixed encodings. To generate the genuine transformed instance, require z_y=1 XOR r_y. For the false member, explicitly require the same genuine verifier acceptance and its opposite terminal condition. That latter condition is syntactically visible if both are on one wire. To make the two formats look alike, an attempted repair first uses only one terminal condition z_y=0 XOR r_y in the other member, and relies on the public transport from w to reject there. In that repaired form the other member may have witnesses for invalid original inputs, so it does NOT satisfy the stronger false-instance property. It still gives every-original-witness functional correctness if transport runs the actual circuit and tests terminal condition. To avoid weakening the security target, one would have to restore actual R acceptance inside both systems.

There is a direct attack even on the weaker functional version. When the compiler supplies correspondence to the original gate variables and encodings of source input bits, the attacker can recover every internal polarity without an original witness. Process gates in topological order. For any k-bit tuple a (not necessarily jointly reachable in the original circuit), compute

    r_v = f'_v(a_1 XOR r_a1,...,a_k XOR r_ak) XOR f_v(a_1,...,a_k).

The truth tables are public and the fan-in is bounded. This equality holds exactly for a correct conjugated gate, including a constant gate, independent of a. It propagates masks to y, and exposes the terminal condition's semantic polarity. No valid source input or genuine chain proof is used. If input translation directly discloses the per-wire masks, the attack is even simpler. This does not assert that every possible circuit obfuscation can be decoded, or that the actual source relation is easy. It identifies the public-conjugation bypass for this compiler before security testing.

A different repair is to hide the original gate correspondence entirely and only publish a transformed circuit which Open evaluates on the original input through a public input map. In the simple polarity form with public raw output z_y=R(x_W,w) XOR r_y, a known invalid certificate (e.g. malformed/empty evidence in a properly typed original input domain) lets a public evaluator compute r_y directly; if original input validation is moved before this raw evaluation, ordinary public code can still be invoked after the check. If the transformed circuit has known visible fixed statement inputs, they can also seed the topological attack whenever its wiring correspondence is recoverable. No claim of general efficient circuit isomorphism is needed.

To remove that known-invalid-input attack, consider instead the genuinely different pair of public predicates

    P_b(w)=R(x_W,w) AND [b=K_j].

Both reject invalid w, and the accepting one has all original witnesses; a rejecting one is actually false. This is the right semantic shape for this construction strategy. Publishing the constant selector (or an ordinary circuit with a recognizable final AND and constant) trivially leaks the bit. An ordinary randomized wire conjugation does not conceal the constant from the mask-propagation attack, and moving the selector outside into a proof-of-correctness check does not hide the raw circuit. A genuinely nonlocal, source-aware randomized circuit compiler would have to make the entire public descriptions of these two cases indistinguishable on hard-TRUE statements, not simply show that their functions agree on invalid inputs. On FALSE their functions are identical, but their descriptions may be distinguishable. Function equality is not a hash-only simulator.

## Alternative construction attempt: hidden consequences instead of explicit selectors

The intended next change is to sample a predicate g with a known semantic bit on EVERY satisfying original trace, without emitting an explicit selector or a reversible wire mask. One concrete way to generate known consequences without a future witness is a randomized proof derivation from the original verifier constraints (e.g. resolution of public clauses). Build could select a derived clause L, then publish a predicate evaluating L for bit one or its negation for bit zero. Correctness follows from the derivation, but the clause versus negated-clause formats immediately reveal the polarity. Rewriting both into the same generic circuit format, hiding the derivation or committing to its proof does not establish indistinguishability of the actual circuit bytes. A predicate explicitly assembled from known satisfied constraint values also permits evaluation on the formal all-satisfied values if those interfaces are visible, without a globally consistent trace. This is why merely replacing the earlier additive mask by a nonlinear Boolean combiner is not an admissible next experiment. No independent hash-based generator of jointly hiding implied-predicate descriptions, or reduction from deciding their polarity to extracting ORIGINAL evidence, has been found. Do not treat difficulty of propositional inference or graph matching as a justified hash assumption.
