## Distinct attempted repair and algorithm
The prior SHA-braiding and low-degree global-correction candidates put a hidden constant behind publicly manipulable source-derived values; their public intermediate outputs permitted extraction, and secret-source braids varied over valid witnesses. Here test a different *hash-only* primitive: a compact GGM punctured pseudorandom-function key allowing evaluation at any input other than the fixed baseline ancestor. Its key is a polynomial-size serialized public object, unlike the earlier ideal-private evaluators. The concrete question: could a public key with one forbidden ancestor implement an original fork-conflict veto without enumerating future Bitcoin parent headers?

Use a 256-bit seed s, domain-separated SHA256 expansion G_b(s)=SHA256('ggm-child-b'||len(s)||s). For n-bit attribute a, let F_s(a)=SHA256('ggm-final'||len(s_a)||s_a) where s_a follows n left/right expansions. Given the baseline ancestor attribute a0, Build can publish the n sibling subtree seeds along a0's path, a standard punctured-key representation Puncture(s,a0). Public Eval(Puncture(s,a0),a) computes F_s(a) for every a != a0, with n hash seeds and O(n) hashes; evaluation at a0 is undefined. This is actual serialized hash-only key access; no FE, lattice, discrete-log or source-signing authority is presumed. This section claims only correctness of punctured evaluation; no PRF theorem or QROM proof is asserted for concrete SHA.

Attempt 1 (fixed claim-scoped mask): choose any fixed a* != a0 at Build, publish D=S XOR F_s(a*), and instruct a challenger with a qualified different ancestor to obtain the pad via public Eval. The complete-public attacker instead computes F_s(a*) immediately. Exact recovery: S=D XOR Eval(Puncture(s,a0),a*) with no original source certificate. An off-chain if CheckContextualAuxPow(w) before that expression is bypassable; the bytes contain both D and the eval key. The leakage holds on FALSE claim instances as well, hence there is no FALSE joint-public simulator hiding S for this attempt. The attack is classical and carries to QPT adversaries.

Attempt 2 (future-source indexed mask): choose D_w=S XOR F_s(a(w)) where a(w) is the semantic conflicting ancestor authenticated by a future original w. The builder does not know a(w) before the fork, so cannot publish one D_w for every qualifying original witness. A single D cannot equal S XOR F_s(a(w)) for all different a(w), except by adding another correction mapping all acceptable source indices to a common secret. Publishing that correction for arbitrary indexes reveals it before evidence; restricting it to authenticated evidence is the unimplemented original FE/WE gate. This is a statement about this exact indexed-mask family, not an impossibility for all hash-only source-specific cryptography.

Attempt 3 (syntactic difference as attribute): let a(w)=ancestorHash(w) and accept a(w)!=a0 as sufficient. An adversary simply chooses an invented 256-bit a!=a0, evaluates the punctured key and bypasses all actual original authenticity/relevance, AuxPoW parent coinbase binding, strict modern chain ID, canonical tag, claim-prefix/maturity depth and deadline conditions. Even if its parent SHA is a plausible low target, raw private PoW is not a qualified Bitcoin/Syscoin source certificate. A syntactic GGM prefix/puncture authorization domain is too broad. Hashing a supplied but unauthenticated header does not repair it. The original fully verified relation must control cryptographic key access, not an external if-check.

## Two obligations exposed together
The punctured-PRF approach gives public key provisioning at polynomial cost, but neither:
(A) a gate cryptographically disallowing all invalid/irrelevant original source certificates, nor
(B) convergence of all different qualifying original certificates to the same precommitted capability.

For genuine ORIGINAL w the desired contract remains C=Build_inc(x_W,S), Open_inc(C,w)=S iff R_original(x_W,w), where the OR is qualified greater exact BTC work, authenticated particular-burn invalidity/nonmembership/refutation, or qualified source-history conflict/tag fault. It retains exact claim/outpoint/burn/amount/recipient/source anchors/window/LC depth/reset/native message/VK/capsule IDs and strict post-PQ contextual child/parent rules. Proving only A would give witness-specific F_s(a(w)), not the common key; proving only B on syntactic a lets invented attributes unlock S. A secure result must instantiate both inside one publicly serialized evaluator and simulate its full public bytes jointly, including one-honest setup participants, siblings and malicious source coins.
