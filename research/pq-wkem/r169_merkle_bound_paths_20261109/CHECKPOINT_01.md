Candidate MBVP: first encode the complete ORIGINAL witness as a binding Merkle root r=Merkle(w), then every read of bit i is accompanied by an authentication path to the *same* r. A verifier keyed to r can check consistency across arbitrarily repeated bit reads, while maintaining only O(log n) witness-path verification state. Inductive proof: if two distinct (i,b,pi), (i,b',pi') with b != b' both verify under the same root r, their leaf-to-root computations collide in H at the first divergent node, except for domain-separation/encoding bugs. This is a source-consistency *component*, not protected release. Including the full claim/UTXO, source child, parent-work proof, headers/chain ancestry, interval tags in the committed witness and defining R_original over them ties semantic eligibility to complete source evidence, but a Merkle root alone does not prevent public fake-work hashing or enforce best-chain inclusion.

Before committing a positive security claim, implement and check root-sharing consistency under adversarial proof splice, source relabeling, two-parent-one-child distinction and off-Boolean inputs. In parallel test the terminal convergent capability question: after a publicly evaluable authenticated trace, distinct valid witnesses produce distinct terminal hash digests; a fixed pad D=K XOR H_pad(digest) cannot be formed by Build for every unobserved digest. A public validity bit -> frozen K requires protecting K in a secret-bearing evaluator, which is still the actual ORIGINAL-dependent compiler.

Do not label proof-of-consistency as an end-to-end WKEM. No GitHub publish receipt yet; this is a local intermediate checkpoint before experiments.
